# books_library: домашняя библиотека книг

Веб-библиотека для каталога книг `/mnt/copy/Books`: каталог индексируется в SQLite (FTS5), интерфейс
открывается в браузере. Служебные режимы меняют файлы книг: исправляют кодировку (fb2, txt), конвертируют
fb2 в EPUB через Calibre и DOC/DOCX/RTF/ODT/MHT в EPUB или FB2, находят дубликаты, упаковывают книги в zip.
Движок на стандартной библиотеке Python 3, без зависимостей, venv и обёртки; внешние программы
(Calibre, poppler, djvulibre, pandoc) вызываются по необходимости. Общие правила mytasks — [AI.md](../ai-md/AI.md),
правила проекта — [mytasks.md](../ai-md/mytasks.md), справка по теме — [topics/books.md](../ai-md/topics/books.md).

## Состав

| Файл | Назначение |
|---|---|
| `books_library.py` | движок: сканирование, база, веб-сервер, OPDS, служебные режимы, карантин, журналы |
| `books_library.json.example` | пример настроек (рабочий `books_library.json` не попадает в Git) |
| `tests/test_books_library.py` | тесты pytest на синтетических данных во временных каталогах |
| `../systemd/user/books-library.service` | постоянный веб-сервер |
| `../systemd/user/books-library-rework.service`, `books-library-rework.timer` | юнит переделки библиотеки: ночная обработка и индексация |
| `reports/` | журналы и отчёты служебных режимов (в Git не попадают) |

Запуск — прямой вызов движка (файл исполняемый, интерпретатор — `python3`):

```bash
python3 books_library/books_library.py <режим> [ключи]
```

## Режимы

| Режим | Что делает | Меняет файлы |
|---|---|---|
| `serve` | веб-интерфейс на `127.0.0.1:8090` в переднем плане (по умолчанию) | нет |
| `scan` | индексация каталога: новые и изменённые по размеру и mtime, исчезнувшие удаляются из базы; однокнижные zip перечитываются; при пустой `author_variants` загружает решения из файлов (`export-decisions`) | нет (только база) |
| `scan --reparse` | то же, но метаданные перечитываются у всех книг (схема v6: `book_meta`, подразделы и сборники из метаданных) | нет (только база) |
| `fix-encoding` | кодировка fb2 (объявление и «полу-cp866») и txt (в UTF-8 без BOM, LF); то же внутри однокнижных zip | да, с журналом и карантином |
| `unpack-fb2zip` | `.fb2` из `*.fb2.zip` рядом с архивом; с `--multi` — и из многокнижных `.zip` (два и более `.fb2`) в папку `<архив без .zip>/` (рядом или `--out`), имена по метаданным fb2 («Фамилия - Название.fb2», без метаданных — `librusec-N.fb2`), сверка md5 с `md5_sum.txt` рядом | да (добавляет файлы); архив остаётся; с `--multi --delete-source` — в карантин `replaced/` после полной распаковки |
| `convert` | DOC/DOCX/RTF/ODT/MHT/MHTML → EPUB (по умолчанию, по главам `--split-level=2`) или FB2; `--only html` — HTML библиотеки Мошкова → «Фамилия - Название.epub» рядом; `--only fb2` — fb2 и однокнижный zip с fb2 → EPUB (собственный конвертер, при сбое — Calibre) | да; исходник — в карантин `replaced/` (`--only fb2`) или только с `--delete-source` (любой формат, не удаляется) |
| `reconvert-fb2` | пересборка epub, которые ночью сделал Calibre из fb2 (OPF `calibre:timestamp` 16–18 ноября 2026), собственным конвертером EPUB 3; `--sample N --out DIR` — выборка для проверки | да (замена epub в библиотеке с переносом старого в `replaced-calibre/`); `--dry-run` и `--sample` — нет |
| `unpack-collections` | книги из раздела «Сборники» — в папки авторов (только командная строка) | да (перенос файлов), база |
| `sort-underscore` | книги из всех служебных папок «_» — в папки авторов (автор: метаданные, папка, имя файла, текст; только командная строка) | да (перенос файлов), база |
| `merge-authors` | склейка папок «Фамилия Имя» и «Фамилия Имя Отчество» (только командная строка) | да (перенос и переименование папок), база |
| `misplaced` | отчёт: книги в папках авторов, лежащие не в папке своего автора (только командная строка) | нет (JSON в `reports/`) |
| `export-decisions` | выгрузка решений: `author_variants` (different/merged) — в `books_library/decisions/` (репозиторий); отметки, полки, правки метаданных и решённые дубли — в `decisions_dir` вне репозитория (0600) (только командная строка) | нет (только файлы решений, база только читается) |
| `import-decisions` | загрузка решений в базу по ключу книги, повтор безопасен (только командная строка) | да (база), под блокировкой scan |
| `check-folders` | отчёт: папки верхнего уровня без «_» и «.» — соответствие «Фамилия Имя [Отчество]» (категории `ok`, `not-person`, `coauthors`, `single`, `initials`; только командная строка) | нет (JSON в `reports/`), без блокировки scan |
| `fix-misplaced` | перенос книг из чужих папок в папку их автора: папка целиком — только при 100 % голосов, иначе книги по одной (общие запреты `move_guard`) | да (перенос и переименование папок, удаление пустых), база |
| `merge-folder` | ручная склейка папки `--from A` в `--to B` (A — и внутри `_…`, B — папка автора, существующая служебная `_…` или внутри `_разобрать`) или переименование A в B, если A и B верхнего уровня и B нет | да (перенос и переименование папок), база |
| `strip-suffix` | «имя_N.ext» → «имя.ext», если имя свободно и нет других «имя_M.ext» в папке | да (переименование файлов), база |
| `enrich-epub` | epub в папках авторов: недостающие метаданные из fb2 (`book_variants`, карантин) дописываются в OPF; нет оглавления, сносок или рабочих ссылок при доступном fb2 — пересборка из fb2; без fb2 — правка ссылок на сноски | да (правка и пересборка epub, карантин `replaced`/`edited`), база |
| `name-variants` | «имя_N.ext» при одноимённом файле с другим текстом → «имя (уточнение).ext»: пер., язык, источник, год, иначе «вариант N» | да (переименование файлов), база (только чтение) |
| `windows-names` | имена папок и файлов, недопустимые в Windows (Syncthing), — в допустимые; конфликты регистра не переименовываются (строка `conflict`) | да (переименование файлов и папок), база |
| `move-books --list ФАЙЛ` | перенос отдельных книг по списку `откуда<TAB>куда` (только командная строка) | да (перенос файлов), база |
| `purge-quarantine --reason R` | **необратимо, только по решению пользователя:** окончательное удаление папок карантина `<quarantine_dir>/R` (только командная строка) | да (удаление из карантина), JSON-отчёт до удаления |
| `dedup` | поиск дубликатов по автору и названию и по имени файла в папке; дубль уходит в карантин, результаты — в базу | да (карантин), база |
| `dedup-folders` | дубликаты внутри каждой папки автора: ≥ 97 % шинглов — дубль в карантин; 85–97 % — «похожая» (группа для решения вручную), если имя другое; одноимённая книга (без регистра и «_N») с ≥ 85 % — дубль (same-name, решение 20.11.2026) | да (карантин, переименование оставленного), база |
| `author-variants` | папки одного автора с разным написанием («Ivanov Ivan» и «Иванов Иван») (командная строка и ночной таймер): пустая удаляется, общие книги склеиваются в папку с полным ФИО, только при `same_person`; остальные — во вкладку «Авторы» | да (перенос, удаление пустых папок), база |
| `unzip-books` | однокнижный `name.ext.zip` → `name.ext` рядом; многофайловые zip не трогаются | да: книга распаковывается рядом, архив уходит в карантин `unzipped/` (не удаляется) |
| `--migrate-db` | только миграции схемы базы | база |

Ключи:

| Ключ | Действие |
|---|---|
| `-n`, `--dry-run` | ничего не менять; план строками `[dry-run] будет: …` и итог |
| `-p`, `--path DIR` | каталог для `fix-encoding`, `unpack-fb2zip`, `convert`, `strip-suffix`, `name-variants`, `dedup`, `unzip-books`: абсолютный путь или относительно `books_dir`; по умолчанию — каталог книг. Корень файловой системы и домашний каталог целиком отвергаются; `dedup` принимает только путь внутри каталога книг |
| `--only` | `fix-encoding`: `all`, `fb2`, `txt`; `convert`: `all`, `fb2`, `doc`, `docx`, `rtf`, `odt`, `mht`, `mhtml`, `html` (`html` — только явно, в `all` не входит) |
| `--workers N` | `convert --only fb2`, `dedup`: число потоков, 1..64 (по умолчанию `workers` из конфига); `unzip-books`: по умолчанию `unzip_workers` |
| `--max-mb N` | `unpack-fb2zip`: предел размера одной распаковываемой книги, МБ (по умолчанию 200, допустимо 1..4096) |
| `--multi` | `unpack-fb2zip`: обрабатывать и многокнижные `.zip`; записи с путями и `..` отбрасываются, zip-бомбы (степень сжатия выше 200) пропускаются |
| `--out DIR` | `unpack-fb2zip --multi`: абсолютный каталог, куда класть папку `<архив>/` вместо папки рядом с архивом; не внутри каталога книг и карантина; создаётся с правами 0700 |
| `--ignore-md5` | `unpack-fb2zip --multi`: распаковать архив, даже если md5 не совпал с `md5_sum.txt` (предупреждение в журнале; CRC записей всё равно проверяется) |
| `--delete-source` | `convert`; `unpack-fb2zip --multi`: исходник (архив) в карантин `replaced/` после полной распаковки (без флага архив остаётся) |
| `--to epub\|fb2` | `convert`: формат результата (по умолчанию EPUB — правило библиотеки); `merge-folder --to B`: папка автора верхнего уровня, существующая служебная папка `_…` (`--to "_1tmp"`: всегда склейка, новая `_…` не создаётся) или путь внутри `_разобрать` |
| `--from NAME` | `merge-folder`: папка верхнего уровня или путь внутри `_…` (`_Сборники/Серия/Автор`), которую склеить или переименовать; ключ можно повторять |
| `--non-books-to-quarantine` | `merge-folder`: только с `--to` внутри `_разобрать`; файлы не книг уходят в карантин `not-book/` вместо переноса |
| `--overwrite` | `convert`: перезаписывать существующий результат |
| `--skip-newer` | `convert` с `--overwrite`: не трогать результат, который новее исходника |
| `--allow-no-author` | `convert --only html`: конвертировать HTML без автора в `<title>`; название — весь `<title>` (или первый `<h2>`, если `<title>` пуст), имя «Название.epub», автор в epub не пишется |
| `--exclude SUBSTR` | `convert`: пропускать имена, содержащие подстроку (можно повторять) |
| `--author NAME` | `convert`: автор для всех документов (иначе — из метаданных DOCX или From у MHT, затем из имени папки) |
| `--title-mode auto\|filename\|keep` | `convert`: откуда название (`auto` — метаданные, затем имя файла) |
| `--no-toc`, `--toc-depth N` | `convert`: без оглавления / глубина оглавления (1..6, по умолчанию 3) |
| `--delete-source` | `convert`: перенести исходник в карантин `replaced/` после проверки результата (с JSON-отчётом) |
| `--config PATH` | другой файл настроек вместо `books_library/books_library.json` |

Коды возврата: `0` — успех; `1` — ошибка выполнения (ввод-вывод, база); `2` — ошибка конфигурации или
отсутствует нужная программа (например, pandoc для `convert`, Calibre для `convert --only fb2`); `3` — уже выполняется
другая операция. Блокировка `books_library/.books_library.lock` общая для `scan`, `fix-encoding`, `unpack-fb2zip`,
`convert`, `dedup`, `unzip-books`, `purge-quarantine` (боевой запуск) и кнопки «Пересканировать» в интерфейсе: одновременно работает только одна операция.

**Изменяющие режимы — сначала с `-n`**, кроме режимов, которые окончательно ничего не удаляют (всё уходит в карантин и
журнал `reports/`): они запускаются сразу боевыми (решение 18.11.2026; ключ `--dry-run` в каждом режиме есть). Порядок для
остальных: `-n` → просмотр плана (количество, список, спорные случаи) → боевой запуск по прямому подтверждению. Ночной
таймер выполняет боевой запуск автоматически (см. «Ночная обработка»).

Отчёты режимов — в `books_library/reports/` (см. «Отчёты и журналы»).

## Примеры

```bash
python3 books_library/books_library.py scan -n                          # план индексации; база не создаётся
python3 books_library/books_library.py scan                             # индексация
python3 books_library/books_library.py fix-encoding -n --only all       # план исправления кодировки
python3 books_library/books_library.py fix-encoding --only all          # исправление (после -n)
python3 books_library/books_library.py unpack-fb2zip -n -p /книги       # план распаковки
python3 books_library/books_library.py unpack-fb2zip -p /книги          # распаковка (после -n)
python3 books_library/books_library.py unpack-fb2zip -n --multi -p /книги                          # план: многокнижные zip
python3 books_library/books_library.py unpack-fb2zip --multi --out /var/lib/lib-rus -p /книги --delete-source  # боевой (после -n)
python3 books_library/books_library.py convert -n -p /книги --only doc  # план конвертации DOC
python3 books_library/books_library.py convert -p /книги --only doc     # конвертация (после -n)
python3 books_library/books_library.py convert -n --only fb2            # план: fb2 → EPUB через Calibre
python3 books_library/books_library.py convert --only fb2 --workers 4   # конвертация (после -n)
python3 books_library/books_library.py dedup -n                         # план поиска дубликатов
python3 books_library/books_library.py dedup --workers 4                # дубликаты в карантин (после -n)
python3 books_library/books_library.py unzip-books -n                   # план распаковки однокнижных zip
python3 books_library/books_library.py unzip-books                      # распаковка (после -n), затем scan
python3 books_library/books_library.py serve                            # веб-интерфейс
```

## Однокнижные zip

Архив ровно с одной книгой — прозрачный: в интерфейсе, поиске, статистике, OPDS и API он показывается как книга
формата внутреннего файла, а путь — как `name.ext` (zip не упоминается).

- Имя `name.fb2.zip` (и вообще `name.<ext>.zip`) с одной книгой внутри — книга формата `<ext>`. Прежний формат
  `fb2.zip` больше не отдельный формат: такие файлы индексируются как fb2.
- «Скачать» (`/file/<id>`) отдаёт распакованную книгу потоком. Исходный zip — только `GET /api/books/<id>/file`
  (ссылка `links.raw` в JSON книги).
- Читалка распаковывает книгу в `books_library/cache/` (`unwrap_book`); предел — `reader_max_mb` на запись и
  `cache_mb` на кэш.
- Защита от zip-бомб: заявленный размер записи, степень сжатия (больше `ZIP_MAX_RATIO` = 200 для записей больше
  1 МБ) и фактически прочитанные байты сверяются с пределом.
- Многофайловые zip не считаются книгами и не трогаются; вложенный zip тоже.

## Имена файлов

В каталоге книг имён с «_N» быть не должно. Занятое имя не получает «_N»: режим берёт уточнение в скобках — «пер. Фамилия»,
язык, источник (сборник), год, иначе «(вариант N)» (функция `free_variant_name`, правила как у `name-variants`). Если имя
не подобралось, это ошибка в журнале, а файл остаётся на месте. Ночные `strip-suffix` и `name-variants` убирают остатки
«_N» от прежних прогонов. В карантине «имя_N» допустимо (см. ниже).

## Карантин

Всё, что служебный режим удаляет или заменяет, переносится в карантин, а не удаляется. Каталог — `quarantine_dir`
(по умолчанию `/mnt/copy/Books-removed`; не может быть внутри `books_dir`, поэтому не индексируется). Путь:
`<quarantine_dir>/<причина>/<путь в каталоге книг>`. Имя, которое уже занято, получает суффикс `_1`, `_2`… — только в карантине; в каталоге книг имён с «_N» не бывает (занятое имя — уточнение в скобках, см. «Имена файлов»).

| Причина | Когда файл туда попадает |
|---|---|
| `replaced` | прежняя версия, замененная режимом: исходник fb2 или zip после `convert --only fb2`, однокнижный zip до перепаковки кодировки, копия прежнего файла при исправлении «полу-cp866»; epub с тем же именем уже есть — исходник сразу сюда |
| `duplicate` | книга-дубль: ≥ 97 % её 5-словных шинглов есть в оставляемой книге и в ней ≥ 200 слов (`dedup`, `dedup-folders`) |
| `edited` | прежняя версия epub, fb2 или однокнижного zip перед правкой метаданных в вебе и API (путь `edited/<путь в каталоге книг>`) |
| `rejected-convert` | зарезервировано: fb2, который не сконвертировали ни собственный конвертер, ни Calibre, сюда больше не переносится — остаётся в библиотеке (`convert --only fb2`, см. ниже); строка журнала и счётчик есть |
| `rejected-zip` | битый zip, не прошла проверка упаковки (одна запись, размер, CRC, `testzip`), имя `name.ext.zip` занято |
| `rejected-encoding` | кодировка txt не распознана или данные бинарные; файл не меняется |
| `rejected-name` | имя длиннее 255 байт UTF-8 или недопустимо для NTFS (Syncthing, Windows); для `unzip-books` ещё имя с `..` или разделителем пути |
| `replaced-calibre` | epub, собранный Calibre из fb2, до замены собственным конвертером `reconvert-fb2` (путь книги не меняется); `replaced-calibre/<путь в каталоге книг>` |
| `unzipped` | однокнижный zip после распаковки `unzip-books` (книга уже лежит рядом; то же для двойника), путь `unzipped/<путь архива>`; карантин чистит пользователь |
| `not-book` | файл не книга (не из набора форматов scan; html/htm тоже сюда): оглавление, картинка, служебный `.adb`/`.err`, css; `merge-folder --non-books-to-quarantine` при переносе остатка сборника в `_разобрать`, путь `not-book/<путь в каталоге книг>` |

Перенос в карантин в `--dry-run` только записывается в журнал. Отметки и полки книги переносятся на новый путь
(relink), если путь изменился (упаковка, замена, переименование).

## Режимы обработки

### fix-encoding

- **fb2**: объявление кодировки исправляется на UTF-8, если в файле UTF-8 при иной заявленной кодировке; «полу-cp866»
  (заглавные кириллицы cp866 0x80–0x9F, прочитанные как cp1251, «‘тейнбек „жон» → «Стейнбек Джон») исправляется в тексте
  и описании. Перед заменой прежняя версия копируется в `replaced/`.
- **txt**: UTF-8 с BOM — без BOM; UTF-16 с BOM — в UTF-8; cp1251, KOI8-R и cp866 — по доле строчных букв среди
  кириллических (≥ 0,8); cp1252 — в UTF-8. CRLF и CR заменяются на LF во всех txt, которые переписываются.
  Нераспознанная кодировка или бинарные данные (`\x00`) → `rejected-encoding/`.
- **однокнижные zip** с fb2 или txt — то же самое внутри архива: перепаковка, прежний zip — копия в `replaced/`.

Повторный запуск ничего не находит. Лимит размера — `reader_max_mb`; большие файлы пропускаются с записью в журнал.

### convert --only fb2

fb2 и однокнижный zip с fb2 → `name.epub` рядом (то же имя) через Calibre (`ebook-convert`), с `--workers` потоков.
Результат проверяется `verify_book` (ZIP/CRC, `mimetype`, `container.xml`, текст). Исходник после успеха переносится
в `replaced/`. Если рядом уже есть epub с тем же нормализованным именем (регистр, ё/е, знаки не важны), конвертации нет:
исходник сразу в `replaced/`. Сначала работает собственный конвертер `fb2_to_epub3` (см. ниже); если он не смог
разобрать fb2 или результат не прошёл проверки, файл собирает Calibre. Сбой обоих или проверки — fb2 остаётся в
библиотеке как fb2 (решение пользователя 18.11.2026): файл не трогается и не переносится в карантин. В журнал пишется
строка `rejected-convert` с причиной (счётчик `rejected-convert`; поле `engine` — `fb2epub3` или `calibre`), а у книги
в `book_meta` — ключ `convert_error` = `причина|размер|mtime_ns`. Пока размер и mtime файла совпадают с записанными,
прогон пропускает его (счётчик `skipped-rejected`); изменился файл — конвертация пробуется снова. Без `ebook-convert`
режим работает, пока собственный конвертер справляется; иначе отказ фиксируется так же.

### Собственный конвертер fb2 → EPUB 3

Правило «сноски в EPUB для всех читалок»: нажатие на сноску не отвлекает от основного текста — сноска показывается на месте (всплывающее окно: `noteref` + `aside epub:type="footnote"` в том же файле; внизу страницы в crengine/KOReader/CoolReader — `-cr-hint: footnote-inpage`), без перехода в другой файл. Запасной вариант — блок сносок в конце главы (`section.footnotes`) с обратной ссылкой на место вызова. Это проверяет `book_completeness` (поле `links_ok`) и исправляет `enrich-epub`.

Пишет EPUB 3.3 из fb2 средствами стандартной библиотеки (только XML-разбор без внешних сущностей; DOCTYPE с
`ENTITY` в начале отвергается). Упаковка: `mimetype` первым без сжатия; `nav.xhtml` (оглавление по разделам и
ориентиры), `toc.ncx` для старых читалок; метаданные: авторы с ролью и сортировкой, переводчики, серия (`belongs-to-collection`
и `calibre:series`), жанры, аннотация, ISBN, дата; обложка с `cover-image` первой в порядке чтения.
Бумажное издание из `publish-info`: `book-name`, если отличается от названия, — сборник `belongs-to-collection` с
`collection-type` `set` (`id="edition1"`); издательская серия — не `belongs-to-collection`, а
`<meta name="books_library:publisher-series">` и `books_library:publisher-series-index` (номер), чтобы не спутаться с
авторской серией. `Epub.details` при скане читает их в `book_meta` и `book_collections` (`publisher-series`).
Серии: все `sequence` описания переносятся — первая как `belongs-to-collection` (`collection-type` `series`) и `calibre:series`,
вторая и далее — `belongs-to-collection` (`id="c2"`, `c3`, …) с `collection-type` `series` и `group-position`.
При скане (схема v6) первая серия EPUB или fb2 — `books.series`/`series_no`, остальные — `book_meta` `series_extra`
«имя #номер». Серия по папке: имя файла `N. Название`, папка `Серия (110,124)` (в разделах — подпапка сборника,
для книг из сборников — `orig_path`) → `book_meta` `series_folder` и `books.series`, только если серия из описания пуста.
Служебные значения (`SERIES_STOP`: рассказы, повести, сборник, сборники, стихи, роман, без серии, антология…) серией
не считаются: `books.series` пуст, значение — в `book_meta` `series_raw`. Пересчёт у существующих книг — `scan --reparse`.
Картинки из `<binary>` определяются по сигнатуре (JPEG, PNG, GIF, WebP); SVG не принимается, битые пропускаются.

**Сноски.** Ссылка на сноску (`type="note"` или ссылка на раздел тел `notes`/`comments`) становится
`<a epub:type="noteref">`. Сама сноска — `<aside epub:type="footnote">` с обратной ссылкой «↩» — кладётся в конец
того файла главы, где первая ссылка на неё, поэтому читалки с всплывающими окнами (Apple Books, KOReader, Kobo,
PocketBook, ReadEra, Moon+) показывают её всплывающим окном, а остальные — текстом в конце главы. Повторные ссылки
из других глав ведут на `chNNN.xhtml#n1`. Сноски без ссылок и прочие разделы тел `notes`/`comments` — в последний
файл `notes.xhtml` («Примечания»), ничего не теряется.

**Главы.** Каждый раздел верхнего уровня — свой файл `text/chNNN.xhtml`; раздел крупнее ~300 КБ делится по
вложенным разделам. Текст не меняется, только экранируется.

### convert --only html

HTML библиотеки Мошкова (зеркало lib.ru, файлы `.html`/`.htm`) → EPUB рядом с исходником, имя результата —
`Фамилия - Название.epub` (фамилия — последнее слово автора из `<title>`, название — остаток `<title>`; длина имени
не больше 120 символов; занятое имя — уточнение в скобках «(вариант N)», без `_N`). Только по `--only html`: в `all` и в ночном таймере
HTML не участвует.

- Автор и название: `<title>` «Имя Фамилия. Название» делится по первому «. »; автор — 1–4 слова без цифр.
- Текст в `<pre>` превращается в абзацы: строка с отступом не меньше 3 пробелов или пустая строка начинает абзац,
  остальные строки приклеиваются через пробел. Сохраняются `<a name>`, `<h2>`/`<h3>`, `<hr>`, `<b>`, `<i>`, локальные
  `<img>`; внешние ссылки и картинки убираются.
- Картинки: локальный файл внутри каталога страницы копируется во временный каталог конвертации и подключается к
  pandoc; ссылки вне каталога страницы и на внешние адреса не используются.
- Пропуски (счётчики в выводе): `skipped_index` — `index*.htm(l)` (оглавления папок); `skipped_small` — меньше 5000 байт;
  `skipped_no_pre` — нет `<pre>`; `skipped_no_author` — в `<title>` не выделяется автор (и название).
- `--allow-no-author`: HTML без автора тоже конвертируется. Название — весь `<title>` (при пустом `<title>` — первый `<h2>`),
  имя результата «Название.epub» (то же ограничение 120 символов; занятое имя — уточнение в скобках «(вариант N)», без `_N`), автор в epub
  не пишется (в том числе не берётся из имени папки; `--author` задаёт его явно). Без флага такие файлы пропускаются.
  Счётчик `converted_no_author` — сколько результатов сделано без автора; в dry-run — «из них без автора» в итоге плана.
- Исходник HTML с `--delete-source` после проверки результата переносится в `replaced/<путь в каталоге книг>`, не удаляется;
  JSON-отчёт `convert-<время>.json` пишется до переноса.

Порядок для библиотеки Мошкова: `convert --only html --path <каталог> -n`, затем без `-n`; после — `scan` и
`sort-underscore`, которые разложат книги по папкам авторов.

### reconvert-fb2

Пересобирает epub, которые ночной `convert --only fb2` сделал через Calibre (в OPF `dc:contributor opf:role="bkp"`
начинается с `calibre`, `calibre:timestamp` — от 16 до 18 ноября 2026 по локальной дате). Список берётся из таблицы
`books` (`fmt = 'epub'`), читается только OPF каждого файла.

Исходный fb2 ищется в карантине `replaced/`: индекс по названию (`title-info`) и фамилии первого автора (читаются первые
64 КБ каждого файла). Ровно один кандидат — он. Несколько — тот, чей стем имени совпадает с epub без суффикса `_N`.
Иначе запись `unmatched` и файл пропускается.

- `--dry-run` — только сопоставление и счётчики (`matched`, `unmatched`, `ambiguous`).
- `--sample N --out DIR` — собрать N книг в `DIR` (вне каталога книг, библиотека не меняется); сначала книги со
  сносками (`type="note"`). Опция `--epubcheck` проверяет результат утилитой `epubcheck`, если она установлена.
- Боевой запуск: сборка в `text_cache_dir/reconvert/`, проверки `verify_book` и `epub_text_loss`, слов не меньше
  98 % от calibre-epub. Затем под общей блокировкой старый файл переносится в карантин `replaced-calibre/`, новый
  копируется рядом и подставляется `os.replace`. Провал — старый файл остаётся, запись `kept-calibre` с причиной.
  Отметки и полки не переносятся: путь книги не меняется.

- Вторая попытка разбора с починкой: fb2, который не читается, чинится (управляющие символы убираются, голый «&» экранируется, HTML-сущности вроде `&nbsp;` раскрываются) и разбирается снова. DOCTYPE с `ENTITY` по-прежнему отклоняется.
- Основное тело: если нет тела без `name`, основным принимается первое тело с `name` (например, с названием книги), если оно не `notes`/`comments` и аналоги.
- `<p>` внутри ячеек таблиц выводятся строками через `<br/>`, а не склеиваются.
- Внешние ссылки без хоста (`http:///`) или с пробелами выводятся обычным текстом.
- Счёт слов сравнивается с calibre-epub без `<head>`: заголовки и CSS в счёт не идут.
- Повторный прогон безопасен: уже заменённые книги пропускаются как `not-calibre`, неудачные остаются calibre-epub с записью `kept-calibre` в журнале.

Опции: `--workers`, `--limit N` (не больше N сопоставленных книг), `-p` (подкаталог внутри каталога книг).

### dedup

- **Группы-кандидаты**: одинаковые автор и название из метаданных (по всей библиотеке) и одинаковое имя файла в одной папке.
- **Оставляемая книга**: по значимости формата — epub → fb2 → txt → pdf → djvu → прочие; среди epub нативный (от издателя или автора) раньше сконвертированного из fb2 (Calibre, `fb2_to_epub3`, pandoc); затем по объёму текста и размеру.
- **Дубль** (`duplicate/`) — только если ≥ 97 % шинглов младшего есть у оставляемой и у младшего ≥ 200 слов.
- **Похожие**: если младшая книга содержит уникальный текст, она остаётся; группа получает статус `similar` и ждёт
  ручного решения. Решённые группы при повторном запуске не перезаписываются.
- **Текст**: fb2, epub и txt читаются сами; pdf — `pdftotext` (poppler, обязательная зависимость); djvu — `djvutxt`;
  прочие форматы — `ebook-convert`.
- Группы больше 16 книг пропускаются (запись в журнал).
- Итог — в таблицах `dup_groups` и `dup_members` (миграция v2). Решения по группам — во вкладке «Дубликаты»
  (см. «Веб-функции»).
- **Кэш текста.** Извлечённый текст книги сохраняется в `text_cache_dir` (по умолчанию `/var/cache/books_library`,
  на NVMe) в файле `text_cache.db` (SQLite, сжатый zlib). Ключ — путь относительно каталога книг, размер, mtime и формат;
  переименованный или перенесённый файл находится по размеру, mtime и формату, если такая запись одна, и получает новый путь.
  Шинглы не кэшируются (их хэши зависят от `PYTHONHASHSEED`). Кэш не меняет библиотеку, поэтому работает и в `dedup -n`.
  В журнал и итог попадают `text_cache_hit` и `text_cache_miss`; строка «кэш текста: попаданий N, промахов N» печатается
  в конце прогона. Предел — `text_cache_mb`; сверх него удаляются давно использованные записи. Каталог не создаётся:
  если его нет или нет прав на запись, в журнал пишется предупреждение и `dedup` работает без кэша. Очистка — удалить
  `text_cache.db*` (вместе с `-wal` и `-shm`) при неработающем `dedup`; при следующем прогоне текст извлечётся заново.

### dedup-folders

Дубли внутри каждой папки автора (папка верхнего уровня «Фамилия Имя Отчество»). Папки сравниваются независимо; папки
«_…» и «.…» пропускаются; `-p` ограничивает одной папкой автора. Папка больше `DEDUP_FOLDER_MAX` (3000 книг)
пропускается со счётчиком `folder-too-large`.

- Текст, кэш текста и извлечение — как у `dedup`. Шинглы берутся по единой выборке (хэш по модулю 4 равен 0) для всех
  книг папки, иначе длинные и короткие тексты несравнимы.
- Порядок значимости: формат (epub → fb2 → txt → pdf → djvu → прочие), затем нативный epub (раньше сконвертированного), затем кириллическое имя, затем больше слов, затем путь.
- Жадный проход: книга — дубль, если ≥ 97 % её шинглов уже есть у оставленных и похожих и в ней ≥ 200 слов; карантин
  `duplicate/`, связи переносятся на оставленную книгу. Книга с долей от 85 % до 97 % — «похожая» (если имя другое; одноимённая с ≥ 85 % — дубль, same-name): остаётся и попадает в
  группу «похожие» для решения вручную.
- Оставленный файл с транслитным именем, у которого есть дубль с кириллическим именем, переименовывается в имя дубля
  (с наибольшим числом слов). Расширение сохраняется, вместе с ним `.zip` однокнижного архива. Связи переносятся на новое имя.
- Копии одной книги в папках её соавторов (оба автора книги — папки) не дубли и в сравнение не входят: счётчик
  `coauthor-copy` в `dedup`. Внутри одной папки — дубли как обычно.
- Группы в `dup_groups`: `auto` с ключом `folder:<папка>` (оставленные и дубли); `similar` с ключом `folder:<путь похожей
  книги>` (похожая и её ближайший оставленный). Пересоздаются только `similar`-группы с ключом `folder:…`; решённые с тем
  же ключом не возвращаются; группы `dedup` и история `auto` не трогаются.
- Dry-run ничего не переносит и не пишет в базу; кэш текста можно. Итог:
  `dedup-folders: папок N, файлов N, дублей N, похожих N, без текста N, слишком больших папок N, переименовано N; кэш текста: попаданий N, промахов N`.
  После боевого запуска — `scan`, чтобы индекс увидел перенесённые и переименованные файлы.

```
python3 books_library/books_library.py dedup-folders -n    # план
python3 books_library/books_library.py dedup-folders       # боевой запуск (после -n)
```

### unpack-collections (только командная строка)

Переносит книги раздела «Сборники» (папка `_Сборники`, или подпапка через `-p`) в папки авторов верхнего уровня.
Автор — первый автор книги. Папка выбирается: точное совпадение слов имени; папка, где лежит файл, названа как автор;
единственная папка с пересечением ≥ 2 слов; иначе новая «Фамилия Имя Отчество». Книги без автора (пусто, цифры,
заглушки вроде «Неизвестный», больше 5 слов) остаются на месте. Файлы вне `books` не трогаются. Связи (отметки, полки,
сборники, дубли) переносятся `relink` пачками по 1000. Пустые папки раздела удаляются (только пустые).

```
python3 books_library/books_library.py unpack-collections -n   # план: журнал reports/unpack-collections-dry-run-*.jsonl
python3 books_library/books_library.py unpack-collections      # боевой запуск (после -n, с тем же -p)
python3 books_library/books_library.py scan                    # затем обновить каталог по новым путям
```

Журнал `reports/unpack-collections-<время>.jsonl` — строка на решение: `path` (= `from`), `from`, `to`, `author`,
`folder`, `match` (exact|parent|subset|new), `source` (meta), `status` (moved|dry|no-author|error), `error`. Откат: для каждой строки `moved` вернуть
файл из `to` в `from` (папку создать при необходимости) и затем `scan`.

### sort-underscore (только командная строка)

Программа максимум: книги из всех служебных папок `_…` каталога книг (`_Сборники`, `_documentation`, `_Журналы`,
`_разобрать`, `_Религия`, `_1tmp` и т. д.) — в папки авторов, если автор определён. Перенос тот же, что у
`unpack-collections` (`pick_folder`, соавторам — настоящие копии, `relink`, `unique_path`, пустые папки удаляются).
Источники автора по убыванию надёжности, первый сработавший:

1. `meta` — автор из книги в базе (`books.authors`), как у `unpack-collections`.
2. `folder` — папка-автор сразу над файлом внутри `_`-папки; принимается, только если такая папка автора уже есть в корне.
   Номер и соавторы в имени папки снимаются: `1. М.Уэйс и Т.Хикмен` → `Уэйс М.` (инициалы), `2) Р.Сальваторе` → `Сальваторе Р.`.
3. `filename` — `Фамилия И.О. - Название`, `Фамилия Имя - Название`, `Фамилия_-_Название`, `Фамилия.-.Название`;
   принимается, только если есть ровно одна существующая папка автора. Выпуски серии `Война Роботов 01(шагающая Смерть 1)кейт`:
   фамилия строчными после последней `)` перед расширением; принимается, только если ровно одна папка верхнего уровня с такой фамилией.
4. `text` — только txt, fb2 и epub без метаданных: первые ~2 КБ текста (epub — по главам из начала книги, пока не набрано ~2 КБ;
   если текст уже есть в кэше dedup, берётся оттуда без чтения книги), строка `Имя Фамилия. Название` или `ФАМИЛИЯ ИМЯ` строка `Имя Фамилия. Название` или `ФАМИЛИЯ ИМЯ`
   с названием на следующей строке; также строка `Имя Фамилия` или `Имя Фамилия.` отдельно в первых 5 непустых строках,
   если за ней есть ещё строка (название следующей строкой); отдельной строкой также `Имя ФАМИЛИЯ` с фамилией капсом (`Кир БУЛЫЧЕВ`),
   `Уоррен МЕРФИ, Ричард СЭПИР` (берётся первый), `М. Н. Загоскин.` и `Маринина А. Б.`; принимается, только если есть ровно одна существующая папка автора.

- Периодика (до выбора папки автора): автор из метаданных содержит слово «газета» или «журнал» (любой регистр) — книга
  идёт в `_Журналы/<издание>/<имя файла>`. Имя издания — из `books_library/periodicals.json` (автор из метаданных →
  `_Журналы/…`; журнал «Если» — `_Журналы/Если`, верхний уровень — только папки авторов); нет в таблице — по умолчанию: без слов «газета»/«журнал»/
  «оглавление» и кавычек «»", повторы слов схлопнуты. Таблица читается один раз на прогон; файла нет — только правило
  по умолчанию. Занятое имя — `conflict` в журнал, книга остаётся на месте (без `_N`). Совпадение `periodical`, счётчик `periodicals`.
- Безавторские книги из `_Сборники` и `_разобрать` (только `sort-underscore`, только эти два раздела) переносятся в
  `_1tmp/<путь внутри раздела без имени верхнего сборника>`: `_разобрать/Библиотека Мошкова/Мошков часть 4/LIB/x.txt` →
  `_1tmp/Мошков часть 4/LIB/x.txt`, `_Сборники/Сборник/a.epub` → `_1tmp/a.epub`. Папка `_1tmp` создаётся при отсутствии.
  Занятое имя — `conflict` в журнал, книга на месте (без `_N`). Совпадение `unsorted`, счётчик `to_unsorted`; связи — `relink`.
  Остальные безавторские книги остаются на месте (`no_author`).

Новые папки создаются только по источнику `meta`. Без автора книга остаётся на месте (`no_author`), кроме случая выше.
Метаданные, не похожие на имя человека (название, жанр, кракозябры: «Охота на драконов», «Японский эпос»,
«Коллективные сборники», «без автора»), новую папку не создают — книга остаётся на месте (счётчик `no_author`,
статус `no-author` в журнале).

```
python3 books_library/books_library.py sort-underscore -n --limit 2000   # пробный план: журнал reports/sort-underscore-dry-run-*.jsonl
python3 books_library/books_library.py sort-underscore                   # боевой запуск (после -n)
python3 books_library/books_library.py scan                              # затем обновить каталог по новым путям
```

`-n` печатает счётчики по разделу и источнику и по 30 примеров каждого источника. `--limit N` ограничивает число книг
(для пробного прогона). С 18.11.2026 входит в ночной таймер (шаг 5); в веб-интерфейс не входит.

Журнал `reports/sort-underscore-<время>.jsonl` — строка на решение: `path`, `from`, `to`, `author`, `folder`, `match`
(exact|parent|subset|new|initials|existing), `source` (meta|folder|filename|text), `status` (moved|dry|no-author|error),
`error`. Копия соавтору — отдельная строка `status: copy`, где `path` и `to` — путь копии. Откат: строки `moved`
возвращают файл из `to` в `path`, строки `copy` удаляют копию по `path`; затем `scan`.

### merge-authors (только командная строка)

Если в корне каталога книг есть папка «Фамилия Имя Отчество» и папка «Фамилия Имя», всё из короткой переносится в полную
(конфликт имени — уточнение в скобках, пустые папки короткой удаляются). Если полной папки нет, отчество берётся из метаданных
книг короткой папки, и папка переименовывается. Если и там отчества нет, ищутся ещё два источника, каждый только когда
предыдущий пуст: метаданные всех книг БД (`global_patronymics`, индекс строится один раз на прогон) и начало текста книг
папки из кэша текста (`text_patronymics`; текст не извлекается — промах кэша означает пропуск книги). Результат
принимается, только если третье слово — отчество (`PATRONYMIC_RE`: «Петров Иван Натали» не годится). Несколько полных
папок или несколько отчеств — ничего не меняется (журнал `ambiguous`). Инициалы («Петров И В») полным именем не считаются.
Счётчики `patronymic_db` и `patronymic_text` — сколько папок получили отчество из каждого источника.

После отчеств прогон делает два дополнительных этапа; каждый заново читает корень каталога:

- «инициалы» — папка «Фамилия И. О» или «Фамилия И» склеивается в единственную полную папку того же автора
  (`initials_folder`). При одном инициале — только если полная папка с той же фамилией одна. Неоднозначное не трогается.
- «Имя Фамилия» — папка из двух слов, где первое слово часто встречается на втором месте в именах других папок
  (порог `NAME_FIRST_MIN_GIVEN` = 10), а второе слово встречается не больше одного раза, склеивается в единственную другую
  папку того же автора (≥ 2 общих слова, ключ ⊆ или ⊇), иначе переименовывается в «Фамилия Имя». Исключения —
  `NAME_FIRST_SKIP` (настоящие «Имя Фамилия»: «Марк Аврелий», «Виктор Поль-Эмиль», «Марк Эдвина»).

Счётчики `initials`, `name_first`, `patronymic_db` и `patronymic_text` входят в итоговую строку; журнал тот же (`move`, `merge`).

```
python3 books_library/books_library.py merge-authors -n   # план: журнал reports/merge-authors-dry-run-*.jsonl
python3 books_library/books_library.py merge-authors      # боевой запуск (после -n)
python3 books_library/books_library.py scan               # затем обновить каталог по новым путям
```

Журнал `reports/merge-authors-<время>.jsonl`: строка `move` (from, to) на каждый файл, `rename`, `merge`, `ambiguous`,
`error`. Откат: `move` — файлы из `to` в `from`; `rename` — папка обратно; затем `scan`.

### misplaced (только командная строка)

Отчёт без изменений: книги в папках авторов верхнего уровня, которые лежат не в папке своего автора. Категории: `ok` —
папка подходит автору книги (общее слово или инициалы); `no-meta` — автора нет; `meta-not-author` — автор из метаданных
не похож на имя; `misplaced-existing` — книга принадлежит существующей папке автора; `misplaced-no-target` — папки
автора нет (переносить некуда). Выводятся счётчики по категориям и первые 30 примеров `misplaced-existing` (по пути).
Без `-n` пишется `reports/misplaced-<время>.json`: счётчики, сводка по папкам и все неверно лежащие строки. База открывается
только для чтения, файлы не трогаются.

```
python3 books_library/books_library.py misplaced -n   # только вывод, JSON не пишется
python3 books_library/books_library.py misplaced      # то же и JSON в reports/
```

### check-folders (только командная строка)

Отчёт без изменений: папки верхнего уровня, не начинающиеся с `_` и `.`, сверяются с форматом «Фамилия Имя Отчество» или «Фамилия Имя».
Категории проверяются по порядку: `coauthors` — разделители (`,`, ` и `, `&`, ` - `) или больше трёх слов; `not-person` — имя не
похоже на имя человека (`person_name`); `single` — одно слово; `initials` — слово из одной буквы или с точкой; иначе `ok`.
Выводятся счётчики, итог по книгам и до 20 примеров на категорию; JSON `reports/check-folders-<время>.json` содержит все папки
с числом книг. Файлы и база не трогаются, блокировка `scan` не берётся. Входит в ночной таймер перед итоговым `scan`.

```
python3 books_library/books_library.py check-folders -n   # только вывод, JSON не пишется
python3 books_library/books_library.py check-folders      # то же и JSON в reports/
```

### export-decisions и import-decisions (только командная строка)

Решения переживают удаление базы `books_library.db` (например, при восстановлении каталога Books из бэкапа).

- **Что выгружается.** `author_variants` со статусами `different` и `merged` — в `books_library/decisions/author_variants.json`:
  файл в репозитории (UTF-8, по `a`, `b`). Личное — в `decisions_dir` (по умолчанию `~/.local/share/books_library/decisions`,
  вне репозитория, проверяется при загрузке конфига): `personal.json` с отметками (`marks`), полками (`shelves` с книгами),
  правками метаданных (`meta_overrides`) и группами дублей со статусом `resolved`. Каталог — 0700, файл — 0600.
- **Ключ книги — не путь.** Ключ — первый автор (набор слов) и название, нормализованные как при дедупликации. Путь
  сохраняется в файле для справки. После переноса книги в другую папку отметка находится по ключу.
- **Записи, которым сейчас нет места в базе** (книги нет в каталоге, пара не решена в базе), при выгрузке сохраняются из
  прежнего файла. Так решение не теряется до возвращения книги.
- **Загрузка.** `scan` сам загружает решения в конце, если таблица `author_variants` пуста и есть файлы решений. Повтор не
  дублирует и не перезаписывает существующие записи. Несопоставленное пишется в журнал `reports/import-decisions-*.jsonl`
  (`action: unmatched`) и в счётчик `unmatched`. Ручной запуск — `import-decisions` (с `-n` — план).
- **Порядок.** Ночной таймер делает `export-decisions` перед итоговым `scan` (сбой не прерывает конвейер). Ручной
  экспорт — сразу после ручных правок отметок и полок.
- **Ограничение.** Пока `author_variants` в базе пуста, автозагрузка повторяется при каждом `scan`: отметка, удалённая в
  веб-интерфейсе, вернётся из личного файла. Такая база — только после восстановления; после `author-variants` загрузка
  больше не автоматическая.
- Каталог `decisions_dir` в юните: `ProtectHome=read-only`, поэтому его создают один раз вручную
  (`mkdir -m 700 -p ~/.local/share/books_library/decisions`); юнит пишет в него через `ReadWritePaths`.

```
python3 books_library/books_library.py export-decisions -n   # план, файлы не пишутся
python3 books_library/books_library.py export-decisions      # выгрузка в decisions/ и decisions_dir
python3 books_library/books_library.py import-decisions -n   # план загрузки в базу
python3 books_library/books_library.py import-decisions      # загрузка (под блокировкой scan)
```

### fix-misplaced

Переносит книги `misplaced-existing` в папку их автора. Порядок:

1. Папка целиком склеивается в существующую папку автора (`merge_folder`), только если **все** книги папки с метаданными
   голосуют за одну папку и таких книг не меньше двух. Если все книги папки имеют одного автора, а папки этого автора нет,
   папка переименовывается в имя из `pick_folder` («Фамилия Имя Отчество»), но только по правилам `rename_guard`:
   - ключ нового имени ⊇ ключ папки: переименование только дополняет имя (отчество, полное имя), существующие слова
     не меняются («Марина» → «Мария» не делается, `skip-rename-changes`); исключение — опечатка в одном слове
     (`typo_fix`): остальные слова совпадают, расстояние Левенштейна ≤ 2, и это фамилия (первое слово папки) либо
     одна лишняя/пропущенная буква («Игнан Грег» → «Иган Грег», «Кизи Кенн» → «Кизи Кен»);
   - добавленные слова — не инициалы, не короче 3 букв («Хаббард Рон» → «Хаббард Рон Л» не делается, `skip-rename-initials`);
   - имя не оканчивается частицей («де», «Де»…) и частица стоит на той же позиции, что в папке (`skip-rename-particle`);
   - общие запреты `move_guard` с префиксом `skip-rename-`.
   Счётчики `skip-rename-*` считаются по папке; при отказе книги папки идут на второй этап.
2. Остальные книги переносятся по одной: только из папки верхнего уровня (книги в подпапках — серии, тома — не трогаются),
   только с одним автором, цель должна существовать.

Запреты общие (`move_guard`), без ручных списков. Не трогаются папка и книги из неё, если в имени папки скобки
(псевдоним или настоящее имя). Не применяется перенос, если цель хуже исходной папки (меньше слов), цель — инициалы,
в цели несколько авторов, цель не похожа на имя человека, либо у папки и цели нет общего слова и различаются фамилии
(вероятно, другой человек). Опустевшие после переноса папки удаляются снизу вверх (`os.rmdir`).

Переименование строит имя по порядку слов автора из базы: для метаданных fb2 (там фамилия первая) план из `-n` нужно
проверить глазами до боевого запуска.

```
python3 books_library/books_library.py fix-misplaced -n   # план: журнал reports/fix-misplaced-dry-run-*.jsonl
python3 books_library/books_library.py fix-misplaced      # боевой запуск (после -n)
python3 books_library/books_library.py scan               # затем обновить каталог по новым путям
```

Журнал `reports/fix-misplaced-<время>.jsonl`: `move` и `rename` с полями `from`/`to` (откат — обратный перенос), `rmdir`,
`error`. Отметки и полки переносятся `relink` по ходу прогона. В JSON API — изменяющий режим: боевой запуск только с `confirm`.

### merge-folder (только командная строка)

`--from A` (можно повторять) и `--to B`: папка A переходит к B.
- **A** — папка верхнего уровня или папка внутри служебного раздела `_…` (например `_Сборники/Серия/Иван Петров`), не короче двух сегментов.
- **B** — папка автора верхнего уровня, существующая служебная папка `_…` верхнего уровня или путь внутри `_разобрать`
  (например `_разобрать/Библиотека Trauma 2.0 (69660 файлов,fb2)`); путь внутри `_разобрать` при отсутствии создаётся.
  Служебная `_…` должна уже существовать (новая не создаётся, имя проходит проверку Windows-имён); в неё всегда склейка,
  переименования нет. Пример: `merge-folder --from "Автор неизвестен" --to "_1tmp"` — файлы и подпапки переходят в `_1tmp/…`,
  папка автора исчезает; `--to "_нет"` при отсутствии `_нет` — ошибка.

Если A верхнего уровня и B нет — A переименовывается в B (при отличии только регистром — через временное имя `B.rename-tmp`),
отметки и полки переносятся по всем книгам A. Иначе (B есть, или A или B вложенные) — файлы и подпапки A переносятся в B
с теми же относительными путями (`merge_folder`), конфликт имени — уточнение в скобках (как у `name-variants`, без `_N`), пустые папки A удаляются снизу вверх.
Перед переносом пересобираются строки сборников (`rebuild_collections`), поэтому у книг остаётся запись сборника с `orig_path`
(relink переносит её на новый путь).
Проверки: путь относительный, без `..`, после разрешения ссылок внутри каталога книг (для B — внутри `_разобрать`); A и B не вложены друг в друга.
Правила `move_guard` здесь не применяются: это ручная команда, план смотрится в `-n`.

```
python3 books_library/books_library.py merge-folder --from "Иван Петров" --to "Петров Иван" -n
python3 books_library/books_library.py merge-folder --from "Иван Петров" --to "Петров Иван"
python3 books_library/books_library.py merge-folder --from "_Сборники/Серия/Иван Петров" --to "_разобрать/Серия" -n
python3 books_library/books_library.py scan
```

Журнал `reports/merge-folder-<время>.jsonl`: `rename`, `move`, `merge`, `error`, `not-book` (с `to` в карантине); откат — по `from`/`to`.

`--non-books-to-quarantine` (только с `--to` внутри `_разобрать`): книги переносятся в B как обычно, а файлы, которые не книги
(расширение не из набора scan, html/htm не считаются книгами), уходят в карантин `not-book/<путь в каталоге книг>`, а не в B.
Счётчик `quarantined_not_book`; в `-n` ничего не переносится. Пример:

```
python3 books_library/books_library.py merge-folder --from "_Сборники/Серия/Иван Петров" --to "_разобрать/Серия" --non-books-to-quarantine -n
```

### enrich-epub (только командная строка)

Правило «epub не хуже fb2»: сверяются полнота описания и структура epub с его fb2-вариантом (`book_completeness`: title, authors, series, annotation, cover, genres, lang, year, translator, publisher, isbn, toc, notes, links_ok).

- Источники fb2: строки `book_variants` с `fmt` fb2 и `keeper` = путь epub (meta JSON и колонки), и fb2 в карантине из `dup_members` (с обложкой и пересборкой).
- Есть fb2 в карантине и у epub нет оглавления, сносок или `links_ok` — пересборка из fb2 (`fb2_to_epub3`), старый epub — в карантин `replaced`.
- Иначе недостающие поля дописываются `enrich_epub_from` (непустые поля не меняются, title и авторы не трогаются); старый epub — копия в карантине `edited`.
- Без fb2 ссылки на сноски правятся точечно: `epub:type="noteref"` и класс `noteref` у ссылки, `footnote` и класс у целевого элемента; ссылка в другой файл заменяется на копию сноски в файле ссылки. Битые href не трогаются и считаются в журнале (`broken_links`).
- CSS: подсказки `-cr-hint` дописываются в первую таблицу стилей книги; без неё — атрибут `style`.

```
python3 books_library/books_library.py enrich-epub -n    # план: журнал reports/enrich-epub-dry-run-*.jsonl
python3 books_library/books_library.py enrich-epub       # боевой запуск (после -n)
```

Журнал `reports/enrich-epub-<время>.jsonl`: `enriched` (fields, note_links, broken_links), `rebuilt` (gaps, source), `skip` (reason), `failed`. Ошибка одной книги не прерывает прогон.

### strip-suffix (только командная строка)

Файлы «имя_N.ext» (N — от 1 до 99) в папках авторов переименовываются в «имя.ext», если «имя.ext» свободно и в той же папке
нет других «имя_M.ext». Иначе файл пропускается и учитывается счётчиком `skip-original-exists` или `skip-siblings`.
Режимы библиотеки уже не создают «_N» (конфликт — уточнение в скобках); этот режим и `name-variants` в ночном таймере убирают остатки. Шаг 12 ночного конвейера.
`-p DIR` — другой каталог (абсолютный или относительно каталога книг), тогда папки авторов не ограничивают поиск.
Отметки переносятся `relink`. С 18.11.2026 входит в ночной таймер (шаг 11, перед итоговым `scan`).

```
python3 books_library/books_library.py strip-suffix -n    # план: журнал reports/strip-suffix-dry-run-*.jsonl
python3 books_library/books_library.py strip-suffix       # боевой запуск (после -n)
python3 books_library/books_library.py scan
```

Журнал `reports/strip-suffix-<время>.jsonl`: `move` (from, to); откат — обратным переименованием.

### name-variants (только командная строка)

Одноимённые книги с разным текстом (переводы, редакции) остаются обе. Файл «имя_N.ext» в папке, где есть «имя.ext» или
другой «имя_M.ext» (без учёта регистра), переименовывается в «имя (уточнение).ext». Уточнение — первое, что отличает файл
от всей группы, в порядке:

1. `translator` — «пер. Фамилия»: первое значение `book_meta` (ключ `translator`, иначе `contributor`), последнее слово.
2. `lang` — `books.lang`, первые 2 буквы в нижнем регистре.
3. `source` — сборник из `book_collections` (source=`folder`, по алфавиту первый): без текста в скобках, без хвоста « - …»
   и префикса «Библиотека ».
4. `year` — `books.year`, 4 цифры и меньше 2025 (год конвертации не годится).
5. `variant` — «вариант N» (N из суффикса), если ничего из перечисленного не отличает.

Если имя занято без учёта регистра, не проходит `windows_name_error` или уже назначено в этом прогоне — берётся следующее
уточнение; не нашлось — строка `error` в журнале, файл пропускается. Без `-p` — только папки авторов верхнего уровня.
База читается одним соединением, только `SELECT`. Отметки переносятся `relink`. Ночной таймер — шаг 13, после `strip-suffix`.

```
python3 books_library/books_library.py name-variants -n   # план: журнал reports/name-variants-dry-run-*.jsonl
python3 books_library/books_library.py name-variants      # боевой запуск (после -n)
python3 books_library/books_library.py scan
```

Журнал `reports/name-variants-<время>.jsonl`: `move` (from, to, status, qualifier); откат — обратным переименованием.
Счётчики: `renamed`, `errors`, `qualifier-<вид>`.

### purge-quarantine (только командная строка, необратимо)

> **ВНИМАНИЕ: необратимо.** Удаляет содержимое папок карантина окончательно, без корзины и без отката. Запускается
> только по прямому решению пользователя. В ночной таймер не входит, в JSON API не выведен. Боевой запуск берёт общую блокировку `scan_lock` (как `scan` и остальные изменяющие режимы): если она занята, отказ с кодом `3`, ничего не удаляется и отчёт не пишется. `-n` блокировку не берёт.

`--reason R` (можно повторять) — причина из списка карантина (см. «Карантин»); иначе ошибка конфигурации. Путь
`<quarantine_dir>/R` после разрешения ссылок обязан лежать внутри карантина и не совпадать с ним; сама папка-симлинк
отвергается. Симлинки внутри не разыменовываются: удаляется сама ссылка, цель не трогается.

Порядок: инвентарь (файлы, симлинки, байты по каждой причине) → JSON-отчёт `reports/purge-quarantine-<время>.json`
со списком всех путей относительно `quarantine_dir` и размерами → удаление. Если отчёт не записался, ничего не удаляется.
Ошибки отдельных записей считаются в `errors` и пишутся в журнал, удаление продолжается. Прогресс с ETA — раз в 30 с.

**Варианты сохраняются в `book_variants` (схема v7).** Для причин `duplicate`, `replaced-calibre` и `unzipped` каждый файл до отчёта и удаления разбирается тем же разбором, что `scan` (для zip — книга внутри однокнижного архива), считается sha1 и пишется строкой `book_variants` (пачками по 200 в транзакции). `keeper` — путь книги в библиотеке, вариантом которой был файл: для `duplicate` — keeper из `dup_members`, иначе путь; для `replaced-calibre` — та же позиция; для `unzipped` — путь без `.zip`; если такой книги нет, `keeper` пуст. Ошибка разбора — строка с тем, что удалось получить, и `meta.error`. Запись вариантов не удалась — ничего не удаляется. После удаления файла проставляется `removed` (время). Карточка книги показывает варианты с её путём как keeper. Симлинки в вариантах не разбираются и не читаются. В `-n` — только число вариантов и с keeper.
`-n` только считает инвентарь и пишет счётчики: отчёт не пишется, ничего не удаляется.

```
python3 books_library/books_library.py purge-quarantine -n --reason duplicate   # счётчики, без отчёта и удаления
python3 books_library/books_library.py purge-quarantine --reason duplicate      # необратимое удаление (после -n и решения пользователя)
```

### author-variants (командная строка и ночной таймер)

Папки одного автора под разным написанием («Ivanov Ivan» и «Иванов Иван»). Кандидаты: одинаковое второе слово по первым трём
буквам и близкая фамилия после фонетической нормализации (транслит латиницы в кириллицу). Пары, различающиеся только
отчеством при равных первых двух словах, — дело `merge-authors` и сюда не попадают.

- `empty` — в одной из папок нет файлов: пустая папка (только пустые подпапки) удаляется, пара — «склеено».
- `common` — у пары есть общее название книги: склейка в папку-цель, которая выбирается так: сначала папка категории `ok`
  (`folder_category`, без инициалов — «Саймак Клиффорд», не «Д.Саймак Клиффорд»), затем больше слов (полное ФИО), затем
  больше файлов, затем по имени; тем же алгоритмом, что у `merge-authors`; конфликт имени — уточнение в скобках (без `_N`).
- `manual` — остаётся в очереди вкладки «Авторы» (`/authors?variants=1`): «Склеить в …» или «Разные авторы».
- Решённые пары (`merged`, `different`) не пересчитываются. Папка, уже ушедшая в другую пару в этом прогоне, пропускается.
- Соавторская папка («Громыко Ольга, Уланов Андрей») разбирается по своему правилу: её файлы переносятся в папку первого
  автора, каждому следующему автору кладётся настоящая копия файла (не жёсткая ссылка). Пустая соавторская папка удаляется.

Журнал `reports/author-variants-<время>.jsonl`: `move`, `rmdir`, `merge`; откат — по журналу. После прогона — `scan`.

Правило «варианты одного автора» — функция `same_person(a, b)`, обязательный фильтр перед любой склейкой (все tier, кроме соавторских папок): фамилия (первое слово) совпадает после нормализации (casefold, ё→е, латинские двойники и транслит) или отличается одной правкой при длине ≥ 5; далее слова попарно по порядку — равны, одно из них инициал, либо одна правка при длине ≥ 5 с совпадающими первыми двумя буквами; отчества (третье слово, оба полные) — только равные. Пара, не прошедшая фильтр, не склеивается и остаётся «ожидает решения» (счётчик `different` в итоге прогона). В ночном таймере — шаг 7, после `merge-authors`.

```
python3 books_library/books_library.py author-variants -n   # план
python3 books_library/books_library.py author-variants      # боевой запуск (после -n)
```

### unzip-books

Однокнижный архив `name.ext.zip` распаковывается рядом в `name.ext`. Имя книги — имя архива без
`.zip`, если его вложенное расширение совпадает с форматом записи; иначе — имя записи (только basename). Многофайловые
zip и вложенные zip не трогаются.

- Распаковка потоковая, во временный файл `.unzip-books.*.tmp` рядом с архивом. Размер сверяется с записью, CRC
  проверяет zipfile при чтении. Дата книги — дата архива. Ошибка — временный файл удаляется, архив остаётся (`failed`).
- После распаковки архив переносится в карантин `unzipped/` (не удаляется; карантин чистит пользователь). Отметки и
  полки переносятся на новый путь (relink) пачками по 1000 записей, хвост — в конце прогона.
- **Двойник**: `name.ext` уже есть с тем же размером и SHA-256 — только архив в карантин (`twin`).
- **Конфликт имени**: `name.ext` занят другим содержимым — книга сохраняется как `name_1.ext`, `name_2.ext`… (`conflict`).
- Путь внутри архива (`../…`) не выходит за папку: используется только имя файла.
- В карантин `rejected-zip/` — битый архив, который не открывается, и запись со степенью сжатия выше `ZIP_MAX_RATIO`
  (для записей больше 1 МБ; защита от zip-бомб). Потоковая распаковка предела размера не имеет: книги больше 32 МБ
  (например, pdf) распаковываются. Имя, длиннее 255 байт, недопустимое для NTFS, с `..` или разделителем пути — `rejected-name/`.
- Потоки: `unzip_workers` (по умолчанию 2 — диск HDD SMR; параллельная запись на нём медленная); `--workers N` перекрывает.
- Итог: `unzip-books: [будет ]распаковано N, двойников N, конфликтов имён N, многофайловых не тронуто N, в rejected-zip N,
  ошибок N`. После боевого запуска — `scan`: он обновит пути книг в индексе.

Порядок: `unzip-books -n` → просмотр плана → `unzip-books` → `scan`. Через API то же самое: `dry_run` и `confirm`.

## Ночная обработка

`books-library-rework.service` запускается таймером ежедневно в 04:30 (и через 10 минут после загрузки) и выполняет
конвейер по порядку:

1. `scan` — новые книги попадают в индекс; сбой этого шага прерывает конвейер.
2. `fix-encoding` — кодировка fb2 и txt.
3. `convert --only fb2` — fb2 → EPUB собственным конвертером, при сбое — через Calibre.
4. `unpack-collections` — книги из «Сборников» в папки авторов.
5. `sort-underscore` — книги из служебных папок «_» в папки авторов (автор: метаданные, папка, имя файла, текст).
6. `merge-authors` — склейка папок «Фамилия Имя» и «Фамилия Имя Отчество».
7. `author-variants` — склейка вариантов написания одного автора; только пары, которые проходят `same_person` (см. раздел режима).
8. `fix-misplaced` — книги не в папке своего автора переносятся в папку автора.
9. `dedup` — дубликаты в карантин.
10. `dedup-folders` — дубликаты внутри папок авторов.
11. `enrich-epub` — epub дополняются метаданными и структурой своих fb2 (правило «epub не хуже fb2»).
12. `strip-suffix` — «имя_N.ext» → «имя.ext», если имя свободно.
13. `name-variants` — «имя_N.ext» при одноимённом файле с другим текстом → «имя (уточнение).ext» (пер., язык, источник, год, иначе «вариант N»).
14. `windows-names` — имена, недопустимые в Windows (Syncthing), — в допустимые.
15. `check-folders` — отчёт о папках авторов, не совпадающих с форматом «Фамилия Имя [Отчество]» (`reports/check-folders-*.json`).
16. `export-decisions` — выгрузка решений (`decisions/author_variants.json` и `decisions_dir`), см. раздел режима.
17. `scan` — итоговая индексация результатов.

Шаги 2–16 — с префиксом `-`: сбой одного режима не мешает следующему и итоговому `scan`; отдельные файлы режимы и так
не останавливают. Решение пользователя от 16.11.2026: новые книги обрабатываются автоматически. Служба работает с
низким приоритетом (`Nice=10`, `IOSchedulingClass=idle`), `MemoryMax=8G`, `TimeoutStartSec=infinity`. Код возврата 2 и 3
не перезапускается.

Ручной порядок тот же: сначала `-n` каждого режима, затем боевой запуск.

Днём шаги 2–14 применяет к изменённым папкам мониторинг `serve` (см. «Регламент мониторинга»); ночной конвейер
по-прежнему проходит всю библиотеку.

## Миграции базы

Схема меняется только миграцией (`PRAGMA user_version`). Миграции применяются при `scan`, при запуске `serve`
и перед правкой метаданных; `--migrate-db` — только миграции. Текущая версия — 7:

- однокнижные zip (`mtime=-1`) перечитываются при следующем `scan`, чтобы показать их как книги;
- таблицы `dup_groups` (группа: ключ, статус `auto`/`similar`/`resolved`) и `dup_members` (участник группы: путь,
  формат, размер, слова, покрытие, роль, оставляемая книга, карантин);
- v3: таблицы `meta_overrides` (правки метаданных форматов без записи в файл, по пути книги) и `edit_log`
  (журнал правок: путь, новый путь, поля, копия прежней версии в карантине, время).
- v4: таблица `book_collections` (книга → сборник: `folder` — лежит в папке сборника, `dedup` — копия из сборника
  ушла в карантин как дубль, принадлежность перешла к оставленной книге) и VIEW `collections` (сборники со счётчиками).
  Таблица постоянная: пересборка в конце `scan` и `dedup` (не в dry-run) только дополняет её, строка «сборники: folder N,
  dedup N, без книги N». VIEW `collections` считает только книги, которые есть в каталоге.
  Фильтр по сборнику находит и книги, чья копия из сборника ушла в дубли; `relink` переносит строки при переименовании.

- v5: таблица `author_variants` (пары папок одного автора: `tier` — empty | common | manual; `status` — pending | merged |
  different; `target` — папка, в которую склеено). Решения `merged` и `different` постоянны: пересчёт их не трогает.

## Отчёты и журналы

Каталог — `books_library/reports/`.

- Порядок для Lib.rus.ec (многокнижные архивы librusec в `/mnt/copy/Books/_Сборники/Lib.rus.ec - Официальная/`): `unpack-fb2zip --multi` → `convert --only fb2` → `scan` → `dedup` → `sort-underscore` → `dedup-folders`; каждый режим сначала с `-n`.
- `unpack-fb2zip` пишет журнал `unpack-fb2zip[-dry-run]-<время>.jsonl` (архив, запись, итоговое имя или причина пропуска; actions `extracted`, `planned`, `skipped`, `failed`, `md5_mismatch`, `md5_ignored`, `replaced`).
- `<режим>[-dry-run]-<время>.jsonl` — журнал действий, пишется по ходу работы (переживает обрыв): строка на действие
  (`fixed`, `zipped`, `renamed`, `replaced`, `duplicate`, `rejected-*`, `skipped`, `failed`…) с путём, целью и причиной.
- `<режим>[-dry-run]-<время>.json` — итог по завершении: каталог, режим, статистика, путь журнала, ошибки обхода.
- Прогресс — раз в 30 с: проверено, сделано, скорость, статистика; то же попадает в журнал движка.
- Для `unpack-fb2zip` и `convert` (DOC/DOCX/RTF/ODT/MHT) отчёт — JSON `<вид>-<время>.json` перед изменением, как раньше;
  `convert --delete-source` пишет `convert-<время>.json` перед переносом исходника в карантин.
- `watch-rules-<время>.json` — сводка прохода правил мониторинга (бессрочно); файлы журналов прохода удаляются через
  90 дней, см. «Регламент мониторинга». Остальные отчёты движок не удаляет.
- Журналы движка (JSONL по схеме mytasks) — в `logs/`, см. «Журналы».

Для `dry-run` журнал и отчёт содержат тот же план, что и боевой запуск, но файлы не меняются.

## Настройки

Файл `books_library/books_library.json` создаёт мастер `check_mytasks.sh` из
`books_library.json.example` (или вручную: `cp books_library.json.example books_library.json`).
Неизвестный ключ, неверный тип или значение вне диапазона — ошибка конфигурации (код 2).
Ключи, начинающиеся с `_`, игнорируются (для комментариев).

| Ключ | По умолчанию | Значение |
|---|---|---|
| `books_dir` | `/mnt/copy/Books` | каталог книг (путь раскрывается `~`) |
| `db_path` | `books_library.db` | база SQLite; относительный путь — от каталога `books_library/`. Вынос за пределы каталога требует правки `ReadWritePaths=` в юнитах |
| `decisions_dir` | `~/.local/share/books_library/decisions` | личные решения (`personal.json`, 0600; каталог 0700): отметки, полки, правки, решённые дубли; вне репозитория, относительный путь — от `books_library/`; создаётся вручную в юните (см. «export-decisions») |
| `quarantine_dir` | `/mnt/copy/Books-removed` | карантин служебных режимов (см. «Карантин»); не может быть внутри `books_dir`; в юнитах должен быть в `ReadWritePaths` |
| `workers` | `12` | потоков служебных режимов (`fix-encoding`, `convert --only fb2`, `dedup`), от 1 до 64; ключ `--workers` перекрывает его |
| `unzip_workers` | `2` | потоков `unzip-books` (запись на HDD SMR), от 1 до 64; ключ `--workers` перекрывает его |

| `scan_workers` | `8` | потоков разбора книг при сканировании, от 1 до 64 |
| `reader_max_mb` | `64` | предел размера книги для чтения в браузере, `fix-encoding` и распаковки однокнижных zip, от 1 до 1024 МБ |
| `page_size` | `50` | книг на странице списка, от 10 до 500 |
| `convert_timeout` | `300` | тайм-аут одного запуска pandoc/LibreOffice при `convert` и ebook-convert (Calibre) при просмотре и `convert --only fb2`, с, от 10 до 3600 |
| `cache_mb` | `4096` | предел кэша просмотра `books_library/cache/` (страницы DjVu, EPUB из прочих форматов, распакованные однокнижные zip), МБ, от 100 до 1000000; сверх предела удаляются давно использованные файлы (см. «Просмотр форматов») |
| `text_cache_dir` | `/var/cache/books_library` | каталог кэша извлечённого текста для `dedup` (файл `text_cache.db`); пустая строка — кэш выключен; каталог создаёт администратор, движок его не создаёт; относительный путь — от каталога `books_library/`; в юнитах должен быть в `ReadWritePaths=` |
| `watch_interval` | `30` | опрос каталога книг веб-интерфейсом, с, от 0 до 86400; `0` — мониторинг выключен (см. «Мониторинг каталога») |
| `watch_rules_delay` | `120` | через сколько секунд без изменений мониторинг применяет правила библиотеки к изменённым папкам, от 0 до 86400; `0` — правила только ночью (см. «Регламент мониторинга») |
| `text_cache_mb` | `20000` | предел сжатых данных кэша текста, МБ, от 0 до 10000000; `0` — кэш выключен |
| `auth.user` | пусто | имя для HTTP Basic-авторизации |
| `auth.password` | пусто | пароль (лучше не хранить в файле) |
| `auth.password_env` | `BOOKS_LIBRARY_PASSWORD` | имя переменной окружения с паролем, если `auth.password` пуст |

Авторизация включается, когда задан пароль; `auth.password` без `auth.user` — ошибка конфигурации.

## Журналы

Движок пишет JSONL-журнал в `logs/books_library-<время>.jsonl` (каталог — `MYTASKS_LOG_DIR` или `logs/`
репозитория; права 600; хранятся последние `KEEP_LOGS` из `conf/log_template.conf`). Журналы служебных режимов —
в `reports/` (см. «Отчёты и журналы»). Вывод `serve` в терминале или в журнале systemd:
`journalctl --user -u books-library.service`; ночной конвейер — `journalctl --user -u books-library-rework.service`.

## Мониторинг каталога

`serve` раз в `watch_interval` секунд (по умолчанию 30) сверяет каталог книг с базой: новые, изменённые (размер,
mtime) и исчезнувшие книги. `scan` запускается заданием (видно в «Задания» на странице «Статистика»), когда
расхождение есть и не менялось с прошлого опроса: копирование закончилось, недописанные файлы не разбираются. Значит,
книга попадает в индекс через 1–2 интервала. Опрос не запускает `scan`, пока идёт другое сканирование или служебный
режим (`scan_lock`), и встаёт на паузу на время ночной переделки: `books-library-rework.service` держит
`RuntimeDirectory=books-library-rework` (`$XDG_RUNTIME_DIR/books-library-rework`), а перед первым шагом ждёт
освобождения блокировки (`flock -w 3600`), чтобы `scan` мониторинга не занял её посреди конвейера. Также пауза, если
каталог книг недоступен или базы ещё нет. Обход ~120 тыс. файлов — около секунды.

Что можно делать с папкой библиотеки руками (или через Syncthing) и что сделает `scan` — сам или по мониторингу:

| Действие | Результат |
|---|---|
| Добавить книги, папку | книги в индексе; недокопированные ждут, пока размер и mtime перестанут меняться |
| Изменить файл книги | метаданные перечитываются; отметки, полки, правки остаются (путь тот же) |
| Удалить книгу | книга уходит из индекса; отметка остаётся по пути и вернётся, если файл вернуть на то же место |
| Переименовать или перенести файл, папку | та же книга: отметки, полки, правки метаданных и сборники — на новый путь, в `edit_log` запись `{"rename": "scan"}`, счётчик `renamed`. Пара — исчезнувший и новый путь с теми же размером и mtime, иначе (копия без `-p`, неоднозначные пары) — с тем же размером и именем файла; одинаковые копии не связываются |
| Переименовать папку автора верхнего уровня | плюс решения по вариантам авторов (`author_variants`: «разные», «склеено») переходят на новое имя; условие — все книги папки ушли в одну новую папку, которой не было в базе (счётчик `renamed_folders`) |
| Переименовать и одновременно изменить файл | связать нельзя: старая книга удаляется, новая добавляется; отметки остаются на старом пути |
| Каталог или файл не читается (права, ошибка ввода-вывода) | книги в нём остаются в индексе как есть (`unreadable_kept`, событие `walk_kept`); в мониторинге — «ошибки» |
| Корень пуст (диск не смонтирован, неверный `books_dir`) | `scan` отказывается (ошибка конфигурации), индекс не чистится |
| Исчезло больше 1000 книг сразу (отвал диска, удалённая по ошибке ветка) | мониторинг встаёт на паузу и сам не чистит индекс; после проверки — «Пересканировать» |
| Каталог книг недоступен, идёт ночная переделка | пауза мониторинга до восстановления |
| Скрытые (`.имя`), служебные и HTML-каталоги | не индексируются |
| Конфликтные копии Syncthing, дубликаты | индексируются как отдельные книги; разбирает ночной `dedup` |

На странице «Статистика» — состояние (последняя проверка, ждут scan, запущено scan, ошибки, пауза, папок ждут
правил, проходов правил) и кнопка
«Остановить/Включить мониторинг»; то же — `POST /api/watch`. Кнопка действует до перезапуска `serve`; насовсем —
`watch_interval: 0` в `books_library.json`. События журнала: `watch_start`, `watch_scan`, `watch_paused`,
`watch_error`, `watch_stop`, `watch_rules`, `watch_rules_skipped`, `rules_done`, `rules_failed`, `rules_purged`.

### Регламент мониторинга

После `scan` мониторинг применяет к изменённым папкам правила библиотеки — те же шаги и в том же порядке, что ночной
конвейер (см. «Ночная обработка»), чтобы добавленное или переименованное руками приводилось к правилам сразу, а не
ночью:

1. Изменения копятся по папкам: папка автора верхнего уровня, в служебных `_…` — папка книги (вложенные поглощаются
   внешними). Удаления, книги в корне каталога и в скрытых папках правил не требуют.
2. Когда расхождений с базой нет и с последнего изменения прошло `watch_rules_delay` секунд (по умолчанию 120),
   запускается задание `watch-rules` (видно в «Задания»). Больше 50 папок сразу — массовая правка: событие
   `watch_rules_skipped`, правила применит ночной конвейер.
3. Шаги по порядку: `fix-encoding`, `convert --only fb2`, `unpack-collections` (папки внутри раздела сборников),
   `sort-underscore` (папки `_…`), `merge-authors`, `author-variants`, `fix-misplaced` (только пары и книги с
   изменёнными папками), `dedup`, `dedup-folders` (папки авторов), `enrich-epub`, `strip-suffix`, `name-variants`,
   `windows-names`. Каждый запуск — сначала `--dry-run`, затем боевой с теми же параметрами; журналы и отчёты обоих —
   в `reports/`, как у ночных шагов. Сбой запуска (`rules_failed`) не останавливает остальные, как `-` в
   rework-юните.
4. Всё, что сделал проход, — в сводке `reports/watch-rules-<время>.json` (хранится бессрочно): папки, по каждому
   запуску итоги dry-run и боевого, строки боевого журнала (`from`/`to` — для отката), ошибки. Файлы журналов прохода
   старше 90 дней удаляются (событие `rules_purged`, в сводке — `purged`); журналы больше 20 000 строк на запуск
   остаются целиком. Журналы ночного конвейера и ручных запусков не трогаются.
5. Папки авторов, куда шаги перенесли книги (`merge-authors`, `fix-misplaced` и т. п.), добавляются к следующим шагам.
6. Весь проход и итоговый `scan` — под `scan_lock`: ночной конвейер ждёт его конца, а начавшаяся ночная переделка
   прерывает проход между шагами. Изменения, сделанные самим проходом, правил повторно не вызывают.

Только ночью: `check-folders` и `export-decisions` (отчёт и выгрузка по всей библиотеке), а также всё, что изменилось
во время прохода правил, — ночной конвейер обрабатывает библиотеку целиком.

## Юниты systemd (user)

| Юнит | Что делает |
|---|---|
| `books-library.service` | постоянный `python3 -I books_library/books_library.py serve` с мониторингом каталога (`watch_interval`); перезапуск при сбое через 10 с (код 2 не перезапускается); потолок памяти 8 ГБ (`MemoryMax=8G`: Calibre, рендер DjVu и ebook-convert, 12 потоков); запись разрешена в `books_library/` (включая `reports/`), `logs/`, в каталог книг и карантин (для заданий API) |
| `books-library-rework.service` | oneshot: ночной конвейер (см. «Ночная обработка»); на время работы — `RuntimeDirectory=books-library-rework` (пауза мониторинга, см. «Мониторинг каталога»); `Nice=10`, `IOSchedulingClass=idle`, `MemoryMax=8G`; коды 2 и 3 не перезапускаются |
| `books-library-rework.timer` | ежедневно в 04:30 и через 10 мин после каждой загрузки (`OnBootSec=10min`), `Persistent=true` (пропущенный запуск — после загрузки), случайная задержка до 10 мин |

Юниты ставит и включает `check_mytasks.sh` (задания `books-library.service` и `books-library-rework.timer`).
Служебные режимы через `books-library.service` не запускаются: их вызывает ночной конвейер или запуск вручную
после `-n`, либо задания API. Песочница юнитов: `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome=read-only`,
запись в `books_library/` (включая `reports/`), `logs/`, в каталог книг (`-/mnt/copy/Books`) и карантин
(`-/mnt/copy/Books-removed`; дефис — не ошибка, если каталога нет), адресные семейства только `AF_UNIX`, `AF_INET`,
`AF_INET6`. Если `books_dir` или `quarantine_dir` в конфиге другие, поправьте пути в юнитах.

## Первый запуск

1. `python3 books_library/books_library.py scan -n` — проверить план (количество книг и ошибки обхода).
2. `python3 books_library/books_library.py scan` — создать базу и проиндексировать каталог.
3. `systemctl --user enable --now books-library.service` — запустить веб-интерфейс.
4. `systemctl --user enable --now books-library-rework.timer` — включить ночную обработку.
5. Открыть http://127.0.0.1:8090/ .

## Возможности интерфейса

- **Поиск** по названию, автору, серии, жанрам и аннотации: полнотекстовый (FTS5), регистр и `ё`/`е`
  не различаются, каждое слово запроса — префикс, слова связаны по «И». Фильтры: формат, статус чтения,
  полка, избранное, раздел, коллекция, автор, серия, жанр, язык. Сортировки: по релевантности, названию,
  автору, серии, дате добавления, году, размеру, пути (`sort=path`, порядок выпусков журналов).
- **Авторы и серии** — списки по буквам; **жанры** — по кодам fb2 с русскими названиями.
- **Разделы** (`/sections`): папки каталога с подчёркиванием в начале (`_Сборники`, `_Журналы`,
  `_Документация`, `_Разобрать`, `_Временное`, `_Религия`) и их подпапки-коллекции. Без такой папки книга
  относится к разделу «Художественная литература»; в разделах автор и название берутся из имени файла
  «Автор - Название», если в метаданных автора нет.
- **Папки** (`/browse`) — навигация по каталогу книг, только чтение; путь проверяется внутри каталога.
  Однокнижные zip показываются как книги.
- **Страница книги** — обложка, аннотация, серия, жанры, другие книги серии, скачивание файла.
- **Чтение в браузере** — fb2, fb2.zip, epub (по главам с оглавлением), txt, а также остальные форматы каталога
  (djvu постранично, mobi/azw/doc/rtf/chm и др. через EPUB, zip — содержимое архива; см. «Просмотр форматов»).
  PDF — встроенным просмотрщиком браузера. Позиция чтения запоминается.
- **Отметки** — статус (хочу / читаю / прочитано / брошено), оценка 0–5, избранное, заметки, полки.
  Отметки привязаны к относительному пути книги и переживают пересканирование; если файл удалён из
  каталога, его отметки остаются в базе.
- **Недавние** и **статистика**. Кнопка «Пересканировать» запускает `scan` в фоне.

## Веб-функции

Вкладки и формы, которые меняют базу или файлы книг. Все правки идут через те же функции, что и JSON API
(`dup_action`, `edit_book`, `rename_author`), и требуют POST с той же страницы или JSON (см. «JSON API»).

### Дубликаты

Вкладка `/dups` (статусы: `similar` — «Похожие», ждут ручного решения, по умолчанию; `auto` — «Удалены автоматически»,
дубли ушли в карантин без вопросов; `resolved` — «Решённые»; по 50 групп на странице). Группа показывает участников: оставленные книги, дубли в карантине и их ссылки.

- **Оставить все** (`keep-both`) — все файлы группы остаются, группа получает статус `resolved`.
- **Решено** (`resolve`) — только помечает группу решённой, файлы не трогает. Решённые скрыты; галочка «Решённые» рядом с заголовком показывает их вместе с текущей вкладкой (вкладки «Решённые» нет, `/dups?status=resolved` работает как раньше).
- **В карантин** (`quarantine`) — оставленная книга переносится в `duplicate/`; единственную оставленную книгу
  группы в карантин отправить нельзя.
- **Восстановить** (`restore`) — файл из карантина группы возвращается в каталог; если оставленных книг стало больше
  одной, группа снова `similar`. Если на месте уже есть файл, восстановление отменяется.

API: `GET /api/dups?status=…&page=…`; `POST /api/dups/<id>` с `{action: keep-both|resolve|quarantine|restore, path}`,
где `path` — `key_path` участника (для `resolve` не нужен).

### Карточка книги

Блок «Сведения» — все метаданные книги из `book_meta` с русскими подписями; сборники из папок — «Сборник / подраздел» (ссылка с `subsection`); сборники из метаданных (издание, издательская серия, сборник) — отдельным списком «Из метаданных» и на странице `/sections`.

### Редактирование метаданных

Страница `/edit/<id>` (ссылка «Редактировать» на странице книги и в списке «Проверки»): название, авторы (по одному
в строке), серия и номер, жанры (коды fb2 через запятую), год, язык, аннотация. Галочка «Переименовать файл по
метаданным» переименовывает файл в «Автор - Название» (символы, запрещённые в Windows, заменяются на `_`; папка —
первого автора, а для книги в разделе `_…` — прежняя).

- **epub и fb2** (в том числе внутри однокнижного zip, с тем же именем внутреннего файла) переписываются в файле.
  Новая версия проверяется (для epub — `verify_book`; для fb2 — название в файле), затем прежняя версия копируется
  в карантин `edited/<путь>` и файл заменяется атомарно. Для zip перепаковка проверяется до замены.
- **Прочие форматы** (pdf, djvu, txt, mobi и др.) не записываются: правка сохраняется в таблице `meta_overrides`
  по пути книги, и `scan` её не затирает. Итог на странице: «сохранены в каталоге».
- Каждая правка пишется в `edit_log`. При переименовании путь книги в базе меняется, отметки и полки переносятся
  (relink), правка `meta_overrides` переносится на новый путь.

API: `POST /api/books/<id>/edit` с `{title, authors[], series, series_no, genres[], year, lang, annotation, rename?}`.

### Проверка

Страница `/fix` (`GET /api/fix`, по 100 на странице, фильтр `reason=semi|garbage|title|author`) — книги с
подозрительными метаданными:

- «полу-cp866» — искажённые заглавные (`‘тейнбек` → «Стейнбек»);
- мусорные символы (mojibake), которые можно восстановить;
- пустое или числовое название;
- нет автора.

Если есть предложенная правка, кнопка применяет её через `edit_book` без переименования файла (`POST /fix/<id>`).
Предложение пересчитывается на сервере из текущих данных книги, а не берётся из формы.

### Переименование автора

Форма на странице автора (`POST /authors/rename`, поля `old`, `new`) или API `POST /api/authors/rename`
с `{old, new}`: имя автора заменяется во всех его книгах; если новое имя уже есть у других книг, это слияние.
Книги правятся через `edit_book` без переименования файлов. Больше 2000 книг у одного автора — отказ;
ошибки отдельных книг собираются в ответе, остальные книги обновляются.

## Просмотр форматов

Все форматы каталога открываются в браузере: серверные инструменты отдают страницы и текст. Файлы книг при просмотре
не меняются; временные результаты лежат в кэше `books_library/cache/`.

| Формат | Как показывается | Инструмент |
|---|---|---|
| fb2 | текст с очисткой (скрипты, стили и атрибуты удаляются), картинки только растровые | встроенный |
| epub | по главам с оглавлением | встроенный |
| txt | абзацы; UTF-8, иначе cp1251 | встроенный |
| pdf | встроенный просмотрщик браузера | — |
| djvu | постранично: PNG страницы (ширина 1400 px) и текстовый слой под ней («Текст страницы»); переход на страницу `?page=N` (с 1) | `ddjvu` (страница), `djvused` (число страниц), `djvutxt` (текст) — пакет djvulibre |
| mobi, azw, azw3, doc, docx, rtf, odt, chm | EPUB, дальше обычная читалка EPUB | `ebook-convert` (пакет calibre), результат кэшируется |
| однокнижный zip | как книга формата внутреннего файла (см. «Однокнижные zip») | встроенный |
| zip (многофайловый) | список файлов архива (первые 3000); картинки, PDF, fb2 и html (без картинок и скриптов) и текстовые файлы открываются в браузере, остальное и `&dl=1` — скачиваются | встроенный; на диск ничего не распаковывается |

**Зависимости.** `djvulibre` и `calibre` обязательны для просмотра этих форматов; `poppler` (`pdftotext`) — для `dedup`.
`check_mytasks.sh` предлагает их установку (`conf/check_mytasks.requirements`). Без них такие книги открываются с ошибкой
«Скачайте файл», остальные форматы работают.

**Кэш.** В `books_library/cache/` лежат страницы DjVu (`djvu-<ключ>-p<N>-w1400.png`), EPUB из Calibre
(`calibre-<ключ>.epub`) и распакованные однокнижные zip. Ключ — id книги, размер и mtime файла: изменился файл — новый
ключ, старый результат не используется. Предел — `cache_mb` (по умолчанию 4096 МБ); при превышении удаляются файлы,
к которым давно не обращались. Кэш — восстановимые данные: его можно удалить в любой момент (удалить содержимое каталога
`cache/`), результаты создадутся заново при следующем открытии. Каталог в `.gitignore`.

**Calibre.** Первое открытие MOBI/DOC/RTF и др. запускает `ebook-convert` во временном каталоге; у него свои
HOME и каталоги Calibre, потому что домашний каталог службы только для чтения. Проверенный EPUB попадает в кэш.
Первая конвертация занимает секунды или минуты и ограничена `convert_timeout`. Обложка таких книг в списке
показывается, только если EPUB уже в кэше (список не запускает конвертацию).

**Ограничения просмотра.** DjVu открывается постранично: поиска по всей книге нет, текст доступен только
для текущей страницы. Размер файла DjVu и форматов Calibre не ограничивается `reader_max_mb`; ограничивают
`convert_timeout` и память службы (`MemoryMax=8G`). Архивы ZIP: записи больше `reader_max_mb` не открываются.

## JSON API

Эндпоинты под `/api`, ответы — JSON. `GET /api` выдаёт список эндпоинтов (`API_HELP` в движке). API и CLI используют
одну и ту же логику: проверка параметров (`command_params`), запуск режима (`run_command`) и вывод плана. Поэтому
результат одинаков, и ошибки параметров одинаковы.

| Метод и путь | Что делает |
|---|---|
| `GET /api/books` | поиск: `q`, `author`, `series`, `genre`, `section`, `collection`, `subsection` (с `collection`), `fmt`, `lang`, `status`, `shelf`, `fav=1`, `dir`, `sort`, `page`, `per_page` (до 500). Ответ: `total`, `page`, `per_page`, `items`; у каждой книги `collections` — `section`, `collection`, `subsection`, `kind`, `source` |
| `GET /api/books/<id>` | книга с отметкой (`mark`), полками (`shelves`), сведениями (`details`: `key`, `label`, `values`) и ссылками (`links`: `page`, `file`, `read`, `raw` — для однокнижного zip) |
| `GET /api/books/<id>/file` | исходный файл книги как есть; для однокнижного zip — сам архив (распакованная книга — `/file/<id>`) |
| `POST /api/books/<id>/mark` | `{status?, rating?, favorite?, note?}` — частичное обновление отметки |
| `POST /api/books/<id>/shelves` | `{shelf_ids: [..]}` — заменить полки книги |
| `GET /api/authors`, `GET /api/series` | `q` (подстрока) или `l` (первая буква); до 1000 строк |
| `GET /api/genres`, `/api/sections`, `/api/shelves`, `/api/recent`, `/api/stats` | справочники и статистика (`watch` — состояние мониторинга) |
| `POST /api/watch` | `{action: start\|stop\|status}` — мониторинг каталога до перезапуска `serve` (см. «Мониторинг каталога») |
| `POST /api/shelves` | `{name}` — создать полку (ответ 201) |
| `POST /api/shelves/<id>/delete` | удалить полку (книги не трогаются) |
| `POST /api/jobs` | фоновое задание (ответ 202, см. ниже) |
| `GET /api/jobs`, `GET /api/jobs/<id>` | список заданий и состояние одного: `state` (queued, running, done, failed), `output` (строки плана), `result`, `error` |
| `POST /api/progress` | позиция чтения (форма `id`, `ch`, `p`) — используется читалкой |

**Задания.** `POST /api/jobs` принимает `command` (`scan`, `migrate`, `fix-encoding`, `unpack-fb2zip`, `convert`,
`dedup`, `unzip-books`), `dry_run` (по умолчанию `true`), `confirm` и параметры режима — те же, что ключи CLI, в виде
полей JSON: `path`, `only`, `max_mb`, `workers`, `to`, `overwrite`, `skip_newer`, `exclude`, `author`, `title_mode`,
`toc`, `toc_depth`, `delete_source`, `allow_no_author` (только с `only: "html"`). Неизвестные параметры — 400. Задания хранятся в памяти сервера (последние ~100)
и при перезапуске сервиса теряются; отчёты и журналы записываются в `books_library/reports/`.

**Правило dry-run → боевой запуск.** Боевой запуск режимов, меняющих файлы (`fix-encoding`, `unpack-fb2zip`, `convert`,
`dedup`, `unzip-books`, `fix-misplaced`, `merge-folder`, `strip-suffix`, `name-variants`), требует `confirm` — id **завершённого успешного** dry-run того же режима с **теми же параметрами**.
Иначе 409. `scan` и `migrate` боевые без `confirm`: меняют только базу.

**Правила запросов.** GET — без изменений. POST принимается в двух случаях: с `Content-Type: application/json`
(кросс-сайтовая страница без CORS такой запрос не отправит) или с той же страницы (`Origin`/`Referer`
совпадает с `Host`). Иначе 403. Тело — не больше 100 КБ. Basic-авторизация — та же, что у интерфейса.
Кириллица в сыром URL понимается (например, `curl` без процент-кодирования), но надёжнее кодировать
параметры (`curl -G --data-urlencode`).

Примеры (`BASE=http://127.0.0.1:8090`; при включённой авторизации добавьте `-u user:password`):

```bash
# Поиск
curl -s -G "$BASE/api/books" --data-urlencode "q=тёмный"

# Отметка: прочитано, оценка 5, избранное
curl -s -X POST "$BASE/api/books/42/mark" -H 'Content-Type: application/json' \
     -d '{"status":"done","rating":5,"favorite":true}'

# Полка и назначение книге
curl -s -X POST "$BASE/api/shelves" -H 'Content-Type: application/json' -d '{"name":"Любимые"}'
curl -s -X POST "$BASE/api/books/42/shelves" -H 'Content-Type: application/json' -d '{"shelf_ids":[3]}'

# 1. Dry-run задания (по умолчанию dry_run=true): вернёт id в поле id
curl -s -X POST "$BASE/api/jobs" -H 'Content-Type: application/json' \
     -d '{"command":"dedup","workers":4}'

# 2. Состояние и план (output) — повторять, пока state не станет done или failed
curl -s "$BASE/api/jobs/<id>"

# 3. Боевой запуск с confirm = id успешного dry-run и теми же параметрами
curl -s -X POST "$BASE/api/jobs" -H 'Content-Type: application/json' \
     -d '{"command":"dedup","dry_run":false,"confirm":"<id>","workers":4}'
```

**Безопасность API.** Через API меняются отметки, полки и запускаются служебные режимы, поэтому по умолчанию
сервер слушает только `127.0.0.1`. При доступе из сети обязательны `host` и `auth` с паролем. Защита от
CSRF — два правила выше (JSON или тот же Origin). Боевой запуск без успешного dry-run с теми же параметрами
невозможен. Юнит `books-library.service` разрешает запись в каталог книг (`-/mnt/copy/Books`), в карантин
(`-/mnt/copy/Books-removed`) и в `books_library/` (отчёты — в `books_library/reports/`), потому что боевые задания API
пишут туда; `MemoryMax` — 8 ГБ.

Чтобы запретить запись в книги через сервис (тогда боевые служебные режимы через API завершатся ошибкой, а `serve`
и dry-run работают как прежде), переопределите юнит:

```bash
systemctl --user edit books-library.service
```

В открывшемся файле (подставьте свой путь вместо `/home/esimych/esimych-docs/mytasks`):

```ini
[Service]
ReadWritePaths=
ReadWritePaths=/home/esimych/esimych-docs/mytasks/books_library /home/esimych/esimych-docs/mytasks/logs
```

Затем `systemctl --user restart books-library.service`. Пустая строка `ReadWritePaths=` сбрасывает прежний
список, следующая строка задаёт новый. Чтобы вернуть прежнее поведение, удалите override
(`systemctl --user revert books-library.service`).

## OPDS для читалок

Каталог Atom/OPDS 1.2 — `/opds`: новые поступления; `/opds?q=запрос` — поиск (шаблон `searchTerms`
объявлен в каталоге); ссылки на скачивание `/file/<id>` (для однокнижного zip — распакованная книга) и обложки `/cover/<id>`.
Адрес для читалки: `http://127.0.0.1:8090/opds`. При открытии в сеть добавляйте авторизацию: читалка передаёт её как Basic.

## Безопасность

- **Файлы книг меняют только служебные режимы** (ночной конвейер, ручной запуск после `-n` и задания API с `confirm`).
  Веб-интерфейс и `scan` файлы книг не меняют, кроме правки метаданных epub и fb2 (см. «Редактирование метаданных»;
прежняя версия — в карантине `edited/`). Удаляемое и заменяемое уходит в карантин, а не удаляется; `convert --delete-source` переносит исходник в карантин с отчётом. `unzip-books` архив не удаляет, а переносит в карантин `unzipped/`.
  Пути из запросов не принимаются: книга выбирается по `id` из базы, путь проверяется внутри `books_dir`.
- **Content-Security-Policy** для HTML-страниц: `default-src 'self'`, скрипты и картинки только со своего
  адреса, `frame-ancestors 'none'`, `form-action 'self'`, `base-uri 'none'`; `X-Content-Type-Options: nosniff`,
  `Cache-Control: no-store`.
- **Очистка содержимого книг.** При чтении в браузере из fb2/epub/txt удаляются скрипты, стили, `iframe`,
  `object` и все атрибуты, кроме картинок; картинки отдаются через сервер, только растровые типы (SVG нет).
- **Проверка Origin/Referer для POST.** Отметки, полки, сканирование и позиция чтения принимаются только с
  той же страницы (совпадение с `Host`), иначе 403. Размер тела POST — не более 100 КБ.
- **Сеть.** По умолчанию сервер слушает только `127.0.0.1`. Для доступа из сети задайте `host` и
  `auth.user` с паролем. Пароль — в переменной окружения (`auth.password_env`) или в файле с правами 600.
- **Конвертация и распаковка.** Внешние программы без оболочки, pandoc с `--sandbox`, тайм-аут, проверка
  результата, журналы и отчёты, карантин вместо удаления; zip-бомбы отсекаются пределами чтения записи.
- **Данные.** Книги и база не попадают в Git (`.gitignore` подпроекта): `books_library.json`,
  `books_library.db*`, lock-файл, `reports/`, `cache/`.

## Ограничения

- Правка метаданных pdf, djvu, txt и других форматов без записи в файл — только в базе (`meta_overrides`), см. «Редактирование метаданных». Отметки пользователя хранятся отдельно в базе.
- Просмотр mobi, azw, djvu, chm и др. в браузере — через серверные инструменты (раздел «Просмотр форматов»), без
  поиска по тексту книги. `convert` переводит DOC/DOCX/RTF/ODT и MHT/MHTML в EPUB на диске; CHM он не переводит.
- Обход каталога читает заголовки fb2 (первые 512 КБ) и содержимое zip/epub. Книги больше
  `reader_max_mb` в браузере не открываются.
- Если каталог книг временно недоступен, `scan` завершается ошибкой без изменения базы; интерфейс
  показывает уже проиндексированное.
- `dedup` видит только текст, который можно извлечь (pdf — `pdftotext`, djvu — `djvutxt`, прочее — `ebook-convert`);
  решение по группам `similar` принимается вручную во вкладке «Дубликаты» или через API.
- Тесты и статический анализ выполняются только в CI (`.github/workflows/books-library.yml`): Ruff по
  `books_library/`, проверка `books_library.json.example`, pytest `books_library/tests`.
