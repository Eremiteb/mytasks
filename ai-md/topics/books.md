# Библиотека `/mnt/copy/Books`

Общие правила — [AI.md](../AI.md), проект — [mytasks.md](../mytasks.md).

## Общие правила библиотеки

- Библиотека вне Git: книги и отчёты из `state/` в репозиторий не добавлять. Перед удалениями — локальный JSON-отчёт с путями, размерами и причинами.
- Дедупликация — только подтверждённые копии. Книга в нескольких форматах: TXT удалять только при наличии полноценного `fb2`, `epub`, `pdf` или аналога.
- В дедупликацию и граф не включать исходные `.html`/`.htm` и каталоги ресурсов `*_files`, `*.files`, `* files`.
- RTF, DOC, DOCX, CHM → EPUB. Исходник удалять только после проверки ZIP/CRC, `mimetype`, `META-INF/container.xml`, содержательных страниц и текста. Повреждённый CHM сначала проверять независимо (`ebook-convert`, chmlib, 7-Zip); физически неполный и невосстановимый удалять только с отчётом.
- `sudo` — графический askpass с явным пользователем `esimych`; пароль не запрашивать в чате и не сохранять.
- Граф — `state/books-graph/graphify-out/`. После изменения состава книг полностью пересобирать: `~/.local/share/graphify/venv/bin/python3 build_books_graph.py <каталог книг> state/books-graph/graphify-out` (из корня репозитория). Проверять итоговые счётчики, ошибки сканирования, оборванные связи и отсутствие `.part.epub`.
- Состояние на 2026-09-06 (справочно): удалены 1 113 TXT-дубликатов и 5 122 точных бинарных дубликата; 448 RTF/DOC/CHM → EPUB; `ЕСИС80.chm` восстановлен как `/mnt/copy/Books/_documentation/ЕСИС80.epub` (13 209 XHTML, ~18 млн символов); четыре обрезанных CHM удалены. Граф: 150 591 файл, 188 630 узлов, 348 796 связей, 38 сообществ, без ошибок и обрывов.
- Состояние на 2026-11-19 (справочно): в каталоге 121 451 книга; граф библиотеки — 133 949 файлов, 164 395 узлов, 302 756 связей, 61 сообщество; Мошков (html → epub) и Lib.rus.ec разобраны по авторам, остаток — в `_разобрать/<сборник>/`, не-книги — в карантине `not-book/`; удалённые из карантина варианты — в `book_variants`.

## Веб-интерфейс `books_library`

- Подпроект `books_library/`, юниты `systemd/user/books-library*`, CI `.github/workflows/books-library.yml`. Устройство, настройки, режимы — [books_library/README.md](../../books_library/README.md).
- Схема БД — только миграцией (`PRAGMA user_version`).
- Сборники: `book_collections` (схема v4): `folder` (книга в папке сборника), `dedup` (копия из сборника в карантине как дубль, принадлежность перешла к оставленной). VIEW `collections` — счётчики. Пересобирается в конце `scan` и `dedup` (не в dry-run), переносится `relink`. Таблица постоянна: пересборка только дополняет.
- Фильтр по сборнику (веб и API) ищет по `book_collections`, находит книги с дублем в карантине; на странице книги и в поиске — все её сборники.
- Просмотр всех форматов — серверные инструменты (`ddjvu`/`djvused`/`djvutxt`, `ebook-convert`). Кэш `books_library/cache/` восстановим, удалять можно; файлы книг при просмотре не меняются.
- Кэш текста `dedup` (`text_cache_dir`, по умолчанию `/var/cache/books_library/text_cache.db`) восстановим. Каталог создаёт администратор; в юнитах — `ReadWritePaths` с «-».
- Интерфейс и `scan` файлы книг только читают. Меняют их служебные режимы: `fix-encoding` (кодировка fb2 и txt), `unpack-fb2zip` (`--multi` — многокнижные zip в папки librusec, md5 из `md5_sum.txt`, `--out`, архив в карантин только с `--delete-source` после полной распаковки), `convert` (DOC/DOCX/RTF/ODT/MHT → EPUB; `--only fb2` — fb2 → EPUB собственным конвертером `fb2_to_epub3`, Calibre — запасной при провале; RTF/DOC/DOCX → EPUB делает только `convert`, исходник переносится в карантин `replaced/` только с `--delete-source` после проверки результата (не удаляется ни для одного формата); `--only html` — HTML библиотеки Мошкова → «Фамилия - Название.epub», только явно, в `all` не входит, исходник при `--delete-source` в `replaced/`; без автора в `<title>` — пропуск, а с `--allow-no-author` → «Название.epub» без автора в метаданных), `dedup`, `unzip-books`, `zip-books` (не используется). Каждый сначала запускается с `-n`.
- Удаляемое и заменяемое не удаляется, а переносится в карантин `/mnt/copy/Books-removed/<причина>/<путь в каталоге книг>` (причины — README). Исключение — `zip-books`: исходник удаляется после проверки архива.
- fb2→epub — собственный конвертер EPUB 3 (`fb2_to_epub3`) первым, Calibre — запасной при ошибке или провале проверок. Решение пользователя 18.11.2026: fb2, не сконвертированный ни одним конвертером, остаётся в библиотеке как fb2 (не в карантин); отказ — строка `rejected-convert` и `book_meta` `convert_error` = `причина|размер|mtime_ns`, повтор — только после изменения файла (счётчик `skipped-rejected`). Режим `reconvert-fb2` пересобирает старые calibre-epub собственным конвертером; старые уходят в карантин `replaced-calibre/`. Издательские данные fb2 (`publish-info`: `book-name` и серия издательства) переносятся в OPF: `book-name` — сборник `set`, серия — `books_library:publisher-series`; scan v6 видит их как сборники из метаданных, как у fb2.
- Серии (решение 19.11.2026: «записывай серии тоже»): fb2→epub переносит все `sequence` title-info (первая — как раньше, остальные — `belongs-to-collection` типа series с `group-position`). scan v6: первая серия — `books.series`, остальные — `book_meta` `series_extra` «имя #номер»; серия по папке (`N. Название` в папке `Серия (110,124)`, для книг из сборников — `orig_path`) — `series_folder`, в `books.series` только если пусто. Служебные (`SERIES_STOP`) — не серия, а `series_raw`; `scan --reparse` пересчитывает.
- Однокнижные zip прозрачны: показываются как книга внутреннего формата, путь `name.ext`; исходный zip отдаёт только `GET /api/books/<id>/file`.
- Решение 17.11.2026: книги хранятся распакованными. `unzip-books` распаковывает `name.ext.zip`: книга — рядом как `name.ext`, архив — в карантин `unzipped/`; двойник (то же содержимое) — только архив в карантин. `unzip-books` в таймере не запускается: только вручную после `-n`. `zip-books` не используется; чтение однокнижных zip в вебе остаётся.
- Правила пользователя 17.11.2026: (1) все сборники книги хранятся в БД (`book_collections`; при удалении дубля связи переносит `relink`); (2) книга лежит в папке «Фамилия Имя Отчество» (`unpack-collections`, `merge-authors`, `author-variants`); (3) дубликаты удаляются, в том числе внутри папки автора (`dedup-folders`). Копии книги соавторов — не дубли: у каждого своя настоящая копия файла (ссылки не используются), `dedup` их не трогает.
- Среди дубликатов epub нативный предпочтительнее сконвертированного из fb2 (Calibre или fb2_to_epub3) — правило пользователя 18.11.2026. Признак: Calibre (`dc:contributor opf:role="bkp"`), fb2_to_epub3 (`meta name="generator"`, у ранних выпусков — манифест `css/book.css` + `title-page`), pandoc (`unique-identifier="epub-id-1"`). Сортировка `dedup` и `dedup-folders`: формат → нативный → слова → размер.
- Программа максимум (решение пользователя 2026-11-18): все файлы из служебных папок на `_` (`_Сборники`, `_documentation`, `_Журналы`, `_разобрать`, `_Религия`, `_1tmp`), у которых определяется автор, — в именованные папки авторов «Фамилия Имя Отчество» по правилам (2)–(3); принадлежность к сборнику/разделу — в БД (`book_collections`). В `_`-папках остаётся только то, у чего автора нет (журналы, документация без автора и т. п.).
- Решение пользователя 19.11.2026: перед окончательным удалением карантина (`purge-quarantine` для `unzipped`, `duplicate`, `replaced-calibre`) сведения о каждом удаляемом варианте сохраняются в БД (`book_variants`, схема v7): разбор, sha1, keeper, дата удаления; карточка книги показывает варианты. Все варианты должны остаться в базе данных.
- Решение пользователя 2026-11-18: режимы books_library, которые ничего не удаляют окончательно (всё — в карантин `/mnt/copy/Books-removed` и журнал `reports/`), агент запускает сразу боевыми, без предварительного `-n`; ошибки по анализу результата исправляются повторным прогоном по карантину и журналу (откат). Ключ `--dry-run` в коде остаётся (правило mytasks). Окончательное удаление из карантина — по-прежнему только по прямому «удалить».
- CLI `unpack-collections` переносит книги из «Сборников» в папки авторов: сначала `-n`, журнал `reports/unpack-collections-*.jsonl` (from/to для отката), затем `scan`. В веб и API не выведен.
- CLI `merge-authors` склеивает «Фамилия Имя» с «Фамилия Имя Отчество» (отчество — из папки, метаданных книг короткой папки, а если их нет — из метаданных других книг БД или из начала текста книг папки по кэшу); неоднозначное не трогает. Затем два этапа: «инициалы» (`Фамилия И. О` → единственная полная папка автора) и «Имя Фамилия» (`Иван Петров` → `Петров Иван` или склейка в единственную полную папку). Сначала `-n`, журнал `reports/merge-authors-*.jsonl` (move/rename) для отката, затем `scan`. В веб и API не выведен.
- CLI `sort-underscore` — источники автора для книг из `_`-папок: meta, папка (с номером и соавторами: `1. М.Уэйс и Т.Хикмен`), имя файла (в т.ч. выпуски серии `…01(подзаголовок)кейт`, одна папка с фамилией), текст txt/fb2/epub (epub — по началу книги, либо кэш dedup). Только существующие папки; `-n` перед боевым запуском.
- CLI `misplaced` — только отчёт: книги в папках авторов, лежащие не в папке своего автора; счётчики категорий и 30 примеров, JSON в `reports/misplaced-*.json` (без `-n`). Ничего не меняет. В веб и API не выведен.
- CLI `fix-misplaced` — книги `misplaced-existing` в папку автора: папка целиком склеивается только при 100 % книг с метаданными, иначе книги по одной; общие запреты `move_guard` (скобки в папке, цель хуже исходной, инициалы, несколько авторов, другой человек). Переименование папки — только дополнением имени (`rename_guard`: ключ цели ⊇ ключ папки, без инициалов в добавленных словах, без частиц в конце и со сдвигом; отказы `skip-rename-*`). Сначала `-n`, журнал `reports/fix-misplaced-*.jsonl` (move/rename с from/to), затем `scan`. Изменяющий режим JSON API — только с `confirm`.
- CLI `merge-folder --from A [--from B] --to B` — ручная склейка или переименование папок. A — верхнего уровня или внутри `_…` (`_Сборники/Серия/Автор`); B — папка автора верхнего уровня или путь внутри `_разобрать` (`_разобрать/Серия`, создаётся). Переименование только для A и B верхнего уровня; иначе склейка с подпапками. `--non-books-to-quarantine` (только с `--to` внутри `_разобрать`): файлы не книг (не из набора форматов scan, html/htm тоже) уходят в карантин причины `not-book`, а не в `_разобрать`. Перед переносом пересобираются сборники (`book_collections` с `orig_path` сохраняется, relink переносит путь); отметки переносятся `relink`. Сначала `-n`, журнал `reports/merge-folder-*.jsonl`, затем `scan`. Изменяющий режим JSON API — только с `confirm`.
- CLI `strip-suffix [-p DIR]` — «имя_N.ext» → «имя.ext», если имя свободно и нет других «имя_M.ext» в папке; в папках авторов по умолчанию. Сначала `-n`, журнал `reports/strip-suffix-*.jsonl`, затем `scan`. С 18.11.2026 входит в ночной таймер (решение пользователя 18.11.2026). Изменяющий режим JSON API — только с `confirm`.
- CLI `move-books --list ФАЙЛ` — перенос отдельных книг по списку `откуда<TAB>куда` (UTF-8, пути относительно каталога книг, `#` и пустые строки пропускаются); ошибочные строки пропускаются. Куда — папка автора верхнего уровня (не короче двух сегментов) или `_Журналы/Издание/…` (не короче трёх). Связи переносятся `relink`, опустевшие папки-источники удаляются. Сначала `-n`, журнал `reports/move-books-*.jsonl` (строки `move` с from/to для отката), затем `scan`. Только CLI, не JSON API.
- CLI `purge-quarantine --reason R [--reason R2 …]` — **необратимо, только по прямому решению пользователя**: окончательное удаление папок `<quarantine_dir>/R` (R — из `QUARANTINE_REASONS`). Сначала `-n` (счётчики, без отчёта и удаления), боевой запуск пишет JSON-отчёт `reports/purge-quarantine-*.json` ДО удаления; нет отчёта — ничего не удаляется. Симлинки не разыменовываются. Варианты причин `unzipped`, `duplicate`, `replaced-calibre` записываются в `book_variants` до удаления. Не в ночном таймере, не в JSON API. Боевой запуск под `scan_lock` (занято — код 3, ничего не удаляется); `-n` без блокировки.
- Ночной таймер юнита переделки библиотеки `books-library-rework.timer`: `scan` → `fix-encoding` → `convert --only fb2` → `unpack-collections` → `sort-underscore` → `merge-authors` → `author-variants` → `fix-misplaced` → `dedup` → `dedup-folders` → `strip-suffix` → `scan` (решение пользователя 16.11.2026; `zip-books` убран 17.11.2026; решение пользователя 18.11.2026: + `sort-underscore`, `fix-misplaced`, `strip-suffix`). Заранее одобренный автозапуск, не ручной.
- Перед боевым `scan` — `python3 books_library/books_library.py scan -n`; перед любым служебным режимом — его же с `-n`. Боевой запуск вручную — только по прямому подтверждению; ночной таймер — исключение выше.
- JSON API (`/api`): боевой запуск изменяющих режимов (`fix-encoding`, `unpack-fb2zip`, `convert`, `dedup`, `dedup-folders`, `zip-books`, `unzip-books`, `author-variants`, `reconvert-fb2`, `fix-misplaced`, `merge-folder`, `strip-suffix`) — только с `confirm` = id успешного dry-run с теми же параметрами; иначе 409.
- Расширенные метаданные (схема v6: `book_meta`, подразделы и сборники из метаданных, `scan --reparse`) — спецификация [`books_library/docs/SPEC-meta-v6.md`](../../books_library/docs/SPEC-meta-v6.md); после реализации раздел переносится в README.
