Справка проекта mytasks по теме. Общие правила — [AI.md](../AI.md), правила проекта — [mytasks.md](../mytasks.md).

## `music_downloader`: конфигурация и поведение

- Обязательный непустой `download_paths` находится в корне JSON рядом с `sites` и общий для всех мостов: каждый трек сохраняется во все перечисленные каталоги. Внутрисайтовых настроек каталогов нет. Синхронно поддерживать структуру рабочего JSON, `.json.example` и README, не заменяя реальные пути и лимиты примерными.
- Скачивание — сквозной round-robin по мостам (`fill_queue`/`read_category` в `run`): по одному треку от каждого моста за круг; очередь моста пополняется его следующей категорией, только когда опустела (не заранее — ссылки категорий с метками времени протухают), и другие мосты при этом не ждут. Прежний обход «уровнями категорий» заставлял вторые категории Sefon/LMusic ждать, пока Beu FM выкачает сотни песен журнала эфира. Тест — `test_run_round_robin_refills_each_site_without_waiting_for_big_queue`.
- Метрики запуска (`report_run` в конце `run`, в `finally` — пишутся и при остановке кодом `2`): строки лога `Итог <мост>`, `Итог поиска <источник>`, `Место: <папка>` (WARNING при остатке < 50 треков), `Итог запуска` и строка `bari: …` для совместимости; те же данные — запись в таблицу `runs` БД (JSON-колонки `sites`, `sources`, `destinations`). Драйверы кладут счётчики в `track["_search_stats"]` (общий словарь запуска; `find_audio` ведёт `queries/candidates/exact/relaxed/chosen/errors/seconds`, недостающие ключи считаются нулём). Новую метрику добавлять в `site_data["stats"]`/`report_run` и тест `test_run_writes_metrics_to_log_and_runs_table`.
- Корневые `download_max_seconds` (600, общий дедлайн трека) и `download_max_mb` (100, лимит одного файла сверх остатка папки) — превышение дает ошибку одного трека, запуск продолжается. Адреса скачивания только `http`/`https`; драйверы только `.py` внутри `drivers/` после `realpath`; `.part` открывается с `O_NOFOLLOW`; имена файлов с префиксом `_` для зарезервированных имён Windows (подробности — `music_downloader/README.md`, «Безопасность»).
- TLS не ослаблять: HTTPS идёт через штатный `requests.adapters.HTTPAdapter()` (`scraper.mount("https://", HTTPAdapter())` в `run`): проверка сертификата и имени хоста, уровень OpenSSL по умолчанию. Прежний `SSLAdapter` с `DEFAULT@SECLEVEL=1` на все `https://` снят 2026-11-12: рукопожатие со всеми 25 хостами драйверов (сайты, `search_sources`, CDN `cdn1–4.sefon.pro`, `storage.xpleer.com`, `dl3s4.muzofond.fm`, `cdn5.drivemusic.me`, `ru.hitmoz.org`, `prod-1.storage.jamendo.com`, `stream.beufm.kz`) проходит на SECLEVEL=2. Не оставлять HTTPS штатному `CipherSuiteAdapter` cloudscraper: он задаёт единственную кривую `prime256v1`, и `cdn2/cdn3.sefon.pro` отвечают `SSLV3_ALERT_HANDSHAKE_FAILURE` (ночь 2026-11-12, когда адаптер был снят без замены). Если новый хост падает с `dh key too small`/`ca md too weak`, ослаблять только для него (`scraper.mount("https://<хост>/", …)`) с причиной здесь; тест — проверка `scraper.mount` в `test_run_uses_global_destinations_for_all_sites`.
- `max_size_mb` ограничивает весь каталог с подкаталогами, по умолчанию 1024 МиБ; проверка в байтах выполняется при старте и перед каждым сохранением. `save_response` проверяет каждый блок потока, в том числе без `Content-Length`, и учитывает копии в дочерних целевых каталогах. При переполнении `DownloadLimitExceeded` удаляет `.part`, завершает процесс с кодом `2`, не записывает незавершённый трек в БД и не запускает сортировщик; уже скачанное не удаляется. Контроль рассчитан на один процесс, для сторонних параллельных записей нужны квоты файловой системы. Отсутствующий, пустой или неверного типа глобальный список, отсутствующие каталоги и уже заполненные каталоги также дают код `2`.
- Дедупликация БД (`downloads`): `artist/title` — служебные нормализованные ключи, а исходные строки драйвера хранятся в `original_artist/original_title` и используются для отчётов. `normalize_db_text` = NFKC + `casefold` + только `str.isalnum()` (все разделители, пробелы и пунктуация отброшены), поэтому «Вася & Петя» == «Вася +Петя» == «ВасяПетя»; слова не удаляются — «Song (Remix)» != «Song». Ключ проверяется по ID `<site>_<track-id>` и по паре `artist/title` (уникальный индекс). Плюс дедупликация по содержимому: `save_response` возвращает `(bytes, paths, sha256_hex)`, движок сверяет хеш с колонкой `filehash`; при совпадении только что записанные копии удаляются с диска, а строка пишется с `filehash = NULL` (`INSERT OR IGNORE`) — ID не качается повторно и не нарушается частичный UNIQUE. Хеш проверяется после загрузки — экономит место, не трафик. Индексы: `UNIQUE(artist,title)` и **частичный** `UNIQUE(filehash) WHERE filehash IS NOT NULL`. При открытии БД строки перенормализуются, дубликаты `artist/title` и не-NULL `filehash` схлопываются к самой свежей. Старые исходные поля заполняются доступными до нормализации значениями `artist/title`; уже потерянные прежней версией регистр и пунктуация невосстановимы. Схема БД меняется только миграцией: версия — `PRAGMA user_version`, новая миграция — следующий номер в `DB_MIGRATIONS` (`DB_LATEST` считается по нему), DDL таблиц и индексов — в одном месте (`DB_SCHEMA`, `table_ddl`); таблицы не править `ALTER` вручную. `_rebuild_table` приводит таблицу к **текущему** `DB_SCHEMA`, поэтому изменение схемы = правка `DB_SCHEMA` + новая миграция через `_rebuild_table`, не `ALTER TABLE ADD COLUMN` (на старой базе колонку уже создаст миграция 1). `migrate_database` выполняется в начале `_create_table`, ДО перенормализации и дедупа: новая база сразу получает `DB_LATEST`; существующая — резервную копию (`conn.backup()` в `<база>.bak-v<версия>-<ГГГГММДД-ЧЧММСС>`) и миграцию в транзакции. Миграция 1 пересобирает `downloads` и `runs` в схему кода (порядок колонок, недостающие — NULL, лишние отбрасываются); индексы при пересборке воссоздаются только те, что были в старой таблице, остальные (UNIQUE на ещё не дедуплицированных данных) создаёт обычная последовательность. `music_downloader.py --migrate-db [--dry-run]` — только миграции (без перенормализации и дедупа), dry-run печатает план `[dry-run] будет: …`. Порядок в `_create_table` важен: оба индекса снимаются ДО перенормализующего `UPDATE` и дедупа и создаются заново ПОСЛЕ — при более широком ключе `UPDATE` иначе нарушит ещё живой UNIQUE. Менять `normalize_db_text` только с бэкапом рабочей `music_downloader.db` (миграция удаляет схлопнувшиеся строки). Разовый backfill `filehash` по уже лежащим на диске файлам выполнен 2026-09-06 (одноразовый скрипт удалён); при штатной работе строки с `filehash = NULL` (файл не найден) не досчитываются.
- Очистка ID3 (`clean_mp3_tags` в `save_response`, нужен `mutagen`): в тегах остаются только данные о песне. Из полей песни вырезаются ссылки (со скобками или подводкой, начинающейся с глагола «скачано с…» — одиночные «by»/«on» не трогать), строки текста песни со ссылкой удаляются (переводы строк `\r\n` сохранять, иначе очистка неидемпотентна); `TIT2`/`TPE1` целиком не удаляются; TLD `by` и прочие похожие на слова зоны не распознаются («Prod.by»), почта не ссылка; `TCOP`/`TPUB`/`TXXX` со ссылкой, URL-кадры `W***`, `TOWN`/`TRSN`/`TRSO`, TXXX `comment`/`description`/`notes` уходят в комментарий; технические кадры (`TENC`, `TSSE`, `TLEN`, `PRIV`, `GEOB`, iTunes-`COMM`, технические TXXX ffmpeg/iTunes/рипперов) удаляются, ссылки из них — в комментарий. **TXXX целиком не переносить**: в библиотеке это в основном MusicBrainz/ReplayGain/ISRC/LABEL (замер 2026-10-21, ~12 TXXX на файл). Комментарий один, оптимизирован `optimize_comment` (короткие ссылки без схемы/`www`, без повторов, без hex iTunes и повторов названия/исполнителя/альбома). Очистка на копии `.part.tags`, сбой mutagen — предупреждение и файл как есть; размер и `filehash` — от итогового файла. Уже лежащие файлы библиотеки движок не трогает. Для уже лежащих библиотек — `music_downloader/music_tags_clean.py` тем же `clean_mp3_tags`: без `--apply` dry-run на копиях, `--apply` с резервной копией исходных тегов в `state/music-tags-backup-<дата>/`, `--restore <каталог>` — откат.

### Jamendo

- Категория `/` получает из официального `tracks` API одну страницу до 200 последних треков (`releasedate_desc`), `/playlist/<ID>` использует API плейлистов. Периодические пустые ответы CDN и сбои API повторяются по `api_retry_delays_seconds` (по умолчанию `1, 3, 5` с, блок `drivers` → `music_downloader_jamendo_com`).
- Принимать только записи с `audiodownload_allowed: true` и непустым `audiodownload`; не подменять его потоковым `audio`. Ключ: сначала `JAMENDO_CLIENT_ID`, затем `client_id` записи `jamendo_com` в `sites` рабочего `music_downloader.json`; плейсхолдер `YOUR_JAMENDO_CLIENT_ID` из `.json.example` кодом не отбраковывается.
- Только песни с вокалом (`vocal_only`, по умолчанию `true`): `tracks` запрашивается с `include=musicinfo` и `vocalinstrumental=vocal`, плейлисты — с `include=musicinfo`; `musicinfo.vocalinstrumental` не `vocal` (`instrumental`/пусто) — пропуск, нет `musicinfo` — трек остаётся. Тест — `test_instrumental_tracks_skipped`. Без фильтра около 2/3 новинок Jamendo — инструментал (замер 2026-11-08).
- Ошибки API и пустые результаты логировать по-русски с `site=jamendo_com`. Проверки метаданных не должны скачивать аудио.

### Контракт драйверов, Shazam и MyChords

- Драйвер реализует `get_tracks(session, base_url, category)`. Необязательный `resolve_track(session, track)` движок вызывает только перед скачиванием нового трека, после проверки БД и общей очереди; результат — словарь `download_url/referer/src` либо `None`. При `None` или исключении трек пропускается без записи в БД, а пара «исполнитель—название» удаляется из `queued_tracks`.
- Драйверы загружаются через `spec_from_file_location`; каталог загрузчика отсутствует в `sys.path`, поэтому соседние драйверы подключать по пути, как `_load_driver` в Shazam, а не через `from drivers import`.
- Настройки драйвера (тайм-ауты, User-Agent, паузы, расписания повторов, лимиты, тайм-ауты `yt-dlp`) — словарь `SETTINGS` на уровне модуля драйвера со значениями по умолчанию; код читает их из `SETTINGS[...]` в момент вызова. Движок накладывает значения из блока `drivers.<имя файла без .py>` файла `music_downloader.json` через `apply_driver_settings` (`drivers/music_downloader_driver_settings.py`; неизвестный ключ, неверный тип и отрицательное число — warning и значение по умолчанию); источникам поиска настройки передаются в `track["_driver_settings"]` и применяются в `_load_driver` при загрузке. Новые параметры добавлять в `SETTINGS` и в блок `drivers` файла `music_downloader.json.example` (тест сверяет их); регулярки, селекторы и URL-шаблоны в `SETTINGS` не выносить.
- `shazam_com`: чарт `/ru-ru/charts/top-200/world` запрашивать с проверенными Firefox-заголовками `SETTINGS["chart_headers"]` — Chrome-профиль и `curl` без заголовков возвращали 405/204/чужую страницу. Shazam (Next.js App Router за Fastly) периодически отдаёт по адресу чарта HTTP 200 со страницей чужой песни (иной canonical, ~1.8 МБ вместо ~3.7 МБ), дефект держится до истечения TTL узла и виден не со всех маршрутов; полная HTML-страница и RSC-поток того же адреса ломаются независимо (наблюдались оба сочетания, и «оба сразу»). Поэтому `get_tracks` на каждой попытке пробует **два источника**: `parse_chart` (HTML: canonical + карточки `[data-test-id="songItem"]` с восстановлением SSR-вставок `$RS(...)`, ранги 1…200, 200 уникальных `adam_<id>`), затем при неудаче `parse_flight_chart` (RSC: заголовок `RSC: 1`, ответ `text/x-component`; те же данные регуляркой по `self.__next_f` — `"trackName"/"artistName"/…/song/<id>/`; ранг = порядок карточек, совпадает с DOM; те же ключи `adam_<id>`). Попытки — по `SETTINGS["retry_delays_seconds"]` (`15, 45, 90` с) с `Connection: close`. **Query-параметр-«антикэш» не добавлять** — отдельный ключ Fastly чаще указывает на битую копию. Легаси-JSON `cdn.shazam.com/shazam/v3/.../genre-global-chart-1` **не использовать** — он заморожен на данных начала 2024 г. `ERROR` пишется только после того, как оба источника промолчали на всех попытках, и означает временный сбой Shazam/CDN; на поломку разбора указывают `В карточке чарта…` / `Ожидался полный Top 200…` / `RSC-поток Shazam…` при живом чарте. RSC-ответ `text/x-component` приходит без charset — `requests` декодирует его как ISO-8859-1 (mojibake «Ã©», «Ð¢Ð°Ñ…», такие треки не находились в поиске), поэтому `get_tracks` ставит `response.encoding = "utf-8"`; не убирать. Аудио искать только через общий `search_sources` (точное совпадение `match_key`); превью Shazam/Apple не использовать.
- **Общие источники MP3 — один список `search_sources`** в корне `music_downloader.json` (`name`, `enabled`, `driver`, `base_url`, `search_path` с `{query}`); движок кладёт его в `track["_search_sources"]` перед `resolve_track`, без ключа — встроенный `DEFAULT_SOURCES` (Sefon → LMusic). Поиск — `drivers/music_downloader_audio_search.py` `find_audio(session, track, label, log)`: запросы `search_queries` (полный + «первый исполнитель + `clean_title`»), сначала точное совпадение `match_key` во всех источниках по порядку, затем мягкое `relaxed_match` (`fold_key` без диакритики и без учёта письменности — кириллица русская/казахская → латиница, q/k, kh/h, j/zh; без `(feat. …)` и remaster, общий исполнитель из `artist_keys`; remix/live — разные записи, не ослаблять; `(with X)` — тоже другая запись, но гость X может быть у кандидата в исполнителях или в `(feat. X)` — `_with_guests`/`_people`), проверка ссылки `stream=True`, пауза `query_pause_seconds` (по умолчанию 1 с); каждое обращение к источнику пишет в лог INFO-строку со статистикой («запросов N, кандидатов M, точных K, мягких L — итог») даже при пустой выдаче, иначе нельзя понять, какие источники реально нужны; `{query}` — параметр, `{query_path}` — сегмент пути. Драйвер источника обязан иметь `search_tracks(session, base_url, search_path)`. Источники (порядок — по качеству, не по охвату): `sefon.pro`, `lmusic_kz`, `muzofond` (404 = пусто), `drivemusic`, `hitmotop` (лучший охват среди сайтов, 128 кбит/с), последним `youtube_music` (системный `yt-dlp` + `ffmpeg`, песни `#songs` с точными `artists`/`track`, перекодирование в MP3 VBR ~190; медленный — держать последним). Beu FM — казахское радио, его треки несут `search_translit`: в запросы добавляется вариант в другой письменности (`to_cyrillic` / `to_latin`). Синонимы исполнителей — корневой `artist_aliases` (группы имён; движок кладёт в `track["_artist_aliases"]`, только мягкий проход и доп. запросы); группу добавлять только после проверки, что это тот же исполнитель (пример: Madi Syzdykov = Мәди Сыздықов = Madi Syzdyq = Madistation). Кандидат может нести `fetch()` вместо прямой ссылки: `find_audio` не проверяет его HTTP-запросом, движок вызывает `fetch()` вместо `scraper.get` (ответ с `status_code`/`headers`/`iter_content`, контекстный менеджер). `yt-dlp` и `ffmpeg` — необязательные `DEPS` в `check_mytasks.sh`. Замер 2026-10-24 на 132 ранее не найденных треках: MP3-сайтами 108 из 132 (82 %), вместе с `youtube_music`, транслитерацией/синонимами и правилом `(with X)` 130 из 132 (98 %); не найдены казахская песня Beu FM «Сара Амангелді — Көздерің сенің сондай әп-әдемі» (опубликован только оригинал Кайрата Нуртаса — другая запись), A. R. Rahman — Yakkai Thiri; «Tame Impala — Dracula (with JENNIE)» найдена после правила `(with X)` как «Tame Impala, Jennie — Dracula» (muzofond, 320 кбит/с, 3:30 — версия с JENNIE, у сольной 3:25); казахская «Madi Syzdykov — Ai Omir ai» найдена как «Madistation — аi ómir-ai» через `artist_aliases`. До YouTube Music трек доходит за 20–80 с; mp3party.net отклонён (CDN отдаёт текст `failed`). Источники не зашивать в код мостов; новый сайт = `search_tracks` + запись в конфиге и `.json.example`. Внешние сайты-кандидаты агентам без согласия пользователя не опрашивать.
- `mychords_net`: `/ru/novinki` → `li.b-listing__full__item a.b-listing__full__item__name` («Исполнитель - Название», разделитель — первый дефис/« – »/« — » в пробелах, `_ARTIST_TITLE_SEP_RE`: сайт перешёл на « – », и до 2026-11-12 такие треки сохранялись как «Unknown Artist»; ID из `/<id>-slug.html`) → страница трека `div.b-words__player[data-src]` с iframe `audio.xpleer.com/embed/` → `#file[data-mp3]` на `storage.xpleer.com` (`audio/mpeg`); без плеера или ссылки — `find_audio` по `search_sources`.

Трек берётся из `<span id="track_org">`, а так как в исходном HTML спан пуст (его наполняет `template/Player.js` из `1.txt` раз в 10 с, кириллица — числовые HTML-сущности), при пустом спане читается `1.txt`. Формат «Исполнитель - Название» (первый « - »), строка без разделителя — не трек. ID `fm_<sha256[:16]>` от нормализованной пары; аудио — `resolve_track` через общий `search_sources`, как у Shazam. Плюс готовые записи эфира (`_recorded_tracks`), а при отсутствии песни во всех `search_sources` — запись эфира через `fetch()` (`audio_search.FileResponse`).
- `beufm_recorder.py` (служба `systemd/user/beufm-recorder.service`, `enable --now`: `unit_enable_args` в `check_mytasks.sh` запускает сразу таймеры и не-oneshot службы): кольцевой буфер потока `stream.beufm.kz/beufm` (MP3 192 кбит/с, байты без перекодирования, нарезка `whole_frames` по целым кадрам — иначе ffmpeg видит битый кадр и бракует каждый дубль), опрос `1.txt` раз в 2 с. **`1.txt` переписывается раз в минуту (в :01)**: смена названия отстаёт от стыка на 0–60 с, резать по ней нельзя. Каждый выход песни — дубль с запасом 65 с до и 10 с после; по 3 дублям (`takes`) сравнение отпечатков `fpcalc` (`choose_take`: общий участок всех дублей, лучший — без ошибок `decode_errors` и с минимальной долей различий), отступы 0.3/1.5 с. Не сошлись — удалить старый дубль и ждать следующий выход; 2 дубля — только после `max_wait_days`; 1 дубль не используется. Песни из `music_downloader.db` не пишутся (`in_library` — ключи `normalize_db_text`). **Журнал эфира** `aired.jsonl` (`log_aired` при каждой новой песне, `list_aired`, `prune_aired`, идемпотентное `seed_aired_from_takes` по паре ID+время — служба пишет текущую песню в журнал раньше первого обслуживания, поэтому «заполнить, только если журнала нет» не работает): драйвер Beu FM отдаёт загрузчику все песни за `aired_lookback_days`, а не одну текущую — иначе песни, которые есть в источниках, никогда не скачивались, а рекордер копил их дубли (2026-10-27: 384 дубля, 2 ГБ, 0 готовых). `maintenance` раз в `maintenance_minutes`: заполнение журнала, `purge_in_library` (удалить дубли скачанных песен), `finalize_overdue`, `prune_aired`, `cleanup`. Записи — корневой `state/beufm_recordings` (music_downloader/state Git не игнорирует). Рекордер подключает драйвер Beu FM по пути, драйвер подключает рекордер лениво (иначе зацикливание). Лог — суточный: `DailyJSONLHandler` при смене даты переходит в файл нового дня (служба работает сутками). Тесты — `music_downloader/tests/test_beufm_recorder.py` (синтетические отпечатки, без сети), проверка без записи — `beufm_recorder.py --dry-run`, работа службы — задание `health` в `check_mytasks.sh`.

### Обёртка и тесты

- `music_downloader.sh` активирует `music_downloader/venv`, если он есть, запускает `music_downloader.py`, деактивирует venv и вызывает `split_by_dash.sh` только при коде `0`; у сортировщика отдельная настройка пути.
- Ошибки отдельных драйверов и треков логируются, но общий код может оставаться `0`; отсутствие JSON-файла сейчас также возвращает `0` без загрузки.
- Логи движка — `logs/music_downloader_engine-<timestamp>.jsonl`, отдельно от логов обёртки `logs/music_downloader-<timestamp>.jsonl`.
- `tests/test_music_downloader.py` загружает `music_downloader/music_downloader.py` напрямую через `spec_from_file_location`, чтобы Zed не принимал одноимённый каталог за namespace-пакет; перед Python-тестами установить requirements.
