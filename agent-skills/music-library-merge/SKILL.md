# Слияние папок библиотеки `/mnt/copy/Music`

Рабочий каталог проекта: `/home/esimych/esimych-docs/mytasks`. Актуальные правила — в `ai-md/AI.md`
и разделе `### split_by_dash.sh` в `README.md`; здесь только процедура и решения пользователя, чтобы
не перечитывать всё заново. Отвечать по-русски.

## Порядок работы (обязателен)

1. **Анализ только чтением**: `python3 split_by_dash_analyze_music.py [N]` (статистика и кандидаты
   по паттернам). Ничего не менять.
2. **Перед правкой кода**: `git status`. Тесты, `shellcheck` и `bash -n` **локально не запускать** —
   их выполняет CI после пуша (`ai-md/AI.md`), ошибки CI присылает пользователь. Пока идёт dry-run,
   **не править `split_by_dash.sh`**.
3. **Один паттерн за итерацию**: код + bats-тесты (в т.ч. на ложные срабатывания; скрипт обязан
   проходить `shellcheck -o all` и `-S style` — проверяет CI) → `./split_by_dash.sh -n /mnt/copy/Music`
   (**только dry-run**: это проверка поведения, она разрешена) → показать пользователю
   список слияний, отклонённые и удаляемые файлы → **ждать его «да» именно на боевой запуск**.
4. **Боевой запуск**: `./split_by_dash.sh /mnt/copy/Music` (явный каталог: `DEST_DIR` из конфига не
   применяется, нужен `--dest`). До и после посчитать файлы (`find -type f | wc -l`, не должно
   меняться без `case_dup_removed`), папки, нарушения имён Windows, регистровые коллизии, `&amp;`;
   проверить лог `logs/split_by_dash-*.jsonl` (ошибки, число `case_merged`); повторный dry-run должен
   быть пустым.
5. **Коммит и пуш — вместе, только после явного «да» именно на коммит**; CI после пуша не ждать. Ответ на другое действие («запускай»)
   коммит не разрешает. Сообщение коммита — файлом (`git commit -F`), только файлы задачи.

## Запреты

- Никогда не запускать `split_by_dash.sh` без `-n` для проверки или демонстрации на боевых данных;
  для демо — копия скрипта во временной папке без `conf/`. Эта ошибка уже приводила к необратимым
  изменениям Music.
- Не добавлять паттерн «артикль The» как кандидат слияния (пользователь запретил предлагать). Наоборот:
  ведущее `The ` из имён папок исполнителей **удаляется** (`The Rasmus` → `Rasmus`).
- Паттерны 10–11 (перенос `A feat. B` / `A & B` в папку `A`) меняют принцип раскладки — без решения
  пользователя не реализовывать. Опечатки, транслитерацию и префикс DJ/MC — только по ручному списку
  `state/split_by_dash_verdicts.tsv` (`merge`/`keep`), автоматически не объединять.
- MusicBrainz: не чаще 1 запроса в секунду, User-Agent без почты пользователя; результаты кэшируются
  в `state/`.
- Файлы без « - » в имени (старые `aerosmith-dream-on.mp3`) скрипт переименовывает по тегам ffprobe
  (`artist`/`album_artist` + `title`) в `Исполнитель - Название.ext` и раскладывает; без тега исполнителя —
  событие `skip_no_artist`, файл не трогается. В dry-run смотреть `dry_renamed_by_tag`.
  Теги сверяются со старым именем файла: совпал только title — перестановка (`tags_swapped`), ничего — `skip_tag_mismatch`, artist с « - » — `skip_artist_dash`, конфликт имён (и в папке исполнителя в `DEST_DIR`) — остаётся больший файл, при равном размере удаляется новый (`tag_dup_removed`).

## Решения пользователя по эталону (приоритет сверху вниз)

1. не КАПС целиком (`Hurts`, не `HURTS`); 2. без `_`/`+` (следов замены знаков); 3. **приоритет `&`**:
` & ` > `&` > `, ` > ` и `/` and ` > прочее (`&` всегда с пробелом с обеих сторон, кроме ведущего
`&ME`; `&amp;` → `&`); 3a. вариант **со** служебным словом (`Жігіттер тобы`, `Группа губы`) —
независимо от числа файлов; 4. **`ё` в приоритете** (`Серёга`, `Ёлка`, `Пётр Налич`); 5. **казахские
буквы в приоритете** (`Қайрат Нұртас`); 6. латинские буквы **без диакритики** (`Beyonce`, `Maneskin`,
`Kirush Rotva`); 7. больше файлов; 8. «Первая заглавная, остальные строчные»; 9. первая по кодовым
точкам. Официальное имя из MusicBrainz (`OFFICIAL_NAMES=yes`) — без `The`.

Ключ группы: нижний регистр, без слов «и»/«and»/«группа»/«тобы»/«ансамбль»/«band»/«official», без
`The` в начале, `ё`→`е`, диакритика и казахские буквы приведены к базовым, только буквы и цифры.
`й` и `и` не отождествляются. Спорные слияния (разный «мягкий» ключ) проверяются сначала по тегам
файлов (`ffprobe`), затем по MusicBrainz; не подтверждённые отклоняются.

## Имена для Windows (Syncthing)

Недопустимые символы `< > : " \ | ? *` → `_`; без конечных точек/пробелов; `CON/PRN/AUX/NUL/COM1-9/LPT1-9`
получают префикс `_`; файлы, различающиеся только регистром, — остаётся **больший по размеру**;
исключения — `conf/split_by_dash.keep.conf` (точные имена, например
`VashKevich&Olisha - Вызывай скорую.mp3`).

## Контекст

`/mnt/copy` — NTFS; NAS-копия `/mnt/store/Music` синхронизируется `sources.sh` (таймер `sources.timer`,
21:30, `rsync --delete`), при расследованиях учитывать, что она перезаписывается. Таймер
`music-downloader.timer` (21:00) запускает `music_downloader.sh`: скачивание в `_cloud` и сортировщик.
