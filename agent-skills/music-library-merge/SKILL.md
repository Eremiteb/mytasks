# Слияние папок библиотеки `/mnt/copy/Music`

Проект: `/home/esimych/esimych-docs/mytasks`. Правила — в `ai-md/mytasks.md` и разделе `### split_by_dash.sh`
в `README.md`; здесь процедура и решения пользователя. Отвечать по-русски.

## Порядок работы (обязателен)
1. **Анализ только чтением**: `python3 split_by_dash_analyze_music.py [N]` (статистика, кандидаты по паттернам). Ничего не менять.
2. **Перед правкой кода**: `git status`. Тесты, `shellcheck`, `bash -n` локально не запускать — их делает CI
   после пуша (`ai-md/mytasks.md`), состояние CI проверять самому через gh одной командой (`gh run list --limit 5`, при падении `gh run view <id> --log-failed`), не ждать и не опрашивать. Пока идёт dry-run, `split_by_dash.sh` не править.
3. **Один паттерн за итерацию**: код + bats-тесты (в т.ч. на ложные срабатывания; проходить `shellcheck -o all`
   и `-S style`) → `./split_by_dash.sh -n /mnt/copy/Music` (**только dry-run**, разрешён) → показать список
   слияний, отклонённые и удаляемые файлы → ждать «да» именно на боевой запуск.
4. **Боевой запуск**: `./split_by_dash.sh /mnt/copy/Music` (явный каталог: `DEST_DIR` из конфига не применяется,
   нужен `--dest`). До и после посчитать файлы (`find -type f | wc -l` — не меняется без `case_dup_removed`),
   папки, нарушения имён Windows, регистровые коллизии, `&amp;`; проверить лог `logs/split_by_dash-*.jsonl`
   (ошибки, число `case_merged`); повторный dry-run должен быть пустым.
5. **Коммит и пуш — вместе, только после явного «да» именно на коммит**; CI после пуша не ждать; состояние проверить самому через gh (`gh run list --limit 5`, при падении `gh run view <id> --log-failed`). Ответ на
   другое действие («запускай») коммит не разрешает. Сообщение коммита — файлом (`git commit -F`), только файлы задачи.

## Запреты
- Никогда не запускать `split_by_dash.sh` без `-n` для проверки или демо на боевых данных; для демо — копия
  скрипта во временной папке без `conf/`. Эта ошибка уже приводила к необратимым изменениям Music.
- Не предлагать артикль «The» как кандидат слияния. Наоборот: ведущее `The ` из имён папок исполнителей
  **удаляется** (`The Rasmus` → `Rasmus`).
- Паттерны 10–11 (перенос `A feat. B` / `A & B` в папку `A`) меняют принцип раскладки — без решения пользователя не реализовывать.
  Опечатки, транслитерацию и префикс DJ/MC — только по ручному списку `state/split_by_dash_verdicts.tsv`
  (`merge`/`keep`), автоматически не объединять.
- MusicBrainz: не чаще 1 запроса в секунду, User-Agent без почты пользователя; результаты кэшировать в `state/`.
- Файлы без « - » в имени (`aerosmith-dream-on.mp3`) скрипт переименовывает по тегам ffprobe (`artist`/`album_artist`
  + `title`) в `Исполнитель - Название.ext` и раскладывает; без тега исполнителя — `skip_no_artist`, файл не трогать.
  В dry-run смотреть `dry_renamed_by_tag`. Теги сверяются со старым именем: совпал только title — перестановка
  (`tags_swapped`); ничего — `skip_tag_mismatch`; artist с « - » — `skip_artist_dash`; конфликт имён (в т.ч. в папке
  исполнителя в `DEST_DIR`) — остаётся больший файл, при равном размере удаляется новый (`tag_dup_removed`).

## Решения пользователя по эталону (приоритет сверху вниз)
1. не КАПС целиком (`Hurts`, не `HURTS`); 2. без `_`/`+` (следов замены знаков);
3. **приоритет `&`**: ` & ` > `&` > `, ` > ` и `/` and ` > прочее (`&` всегда с пробелом с обеих сторон, кроме ведущего `&ME`; `&amp;` → `&`);
3a. вариант **со** служебным словом (`Жігіттер тобы`, `Группа губы`) — независимо от числа файлов;
4. **`ё` в приоритете** (`Серёга`, `Ёлка`, `Пётр Налич`); 5. **казахские буквы в приоритете** (`Қайрат Нұртас`);
6. латинские буквы **без диакритики** (`Beyonce`, `Maneskin`, `Kirush Rotva`); 7. больше файлов;
8. «Первая заглавная, остальные строчные»; 9. первая по кодовым точкам.
Официальное имя из MusicBrainz (`OFFICIAL_NAMES=yes`) — без `The`.

Ключ группы: нижний регистр; без слов «и»/«and»/«группа»/«тобы»/«ансамбль»/«band»/«official»; без `The` в начале;
`ё`→`е`; диакритика и казахские буквы — к базовым; только буквы и цифры. `й` и `и` не отождествлять.
Спорные слияния (разный «мягкий» ключ) проверять сначала по тегам (`ffprobe`), затем по MusicBrainz; не подтверждённые отклонять.

## Имена для Windows (Syncthing)
Недопустимые `< > : " \ | ? *` → `_`; без конечных точек и пробелов; `CON/PRN/AUX/NUL/COM1-9/LPT1-9` — префикс `_`;
файлы, различающиеся только регистром, — остаётся **больший по размеру**. Исключения — `conf/split_by_dash.keep.conf`
(точные имена, например `VashKevich&Olisha - Вызывай скорую.mp3`).

## Контекст
`/mnt/copy` — NTFS. NAS-копия `/mnt/store/Music` синхронизируется `sources.sh` (таймер `sources.timer`, 21:30,
`rsync --delete`) — при расследованиях учитывать перезапись. Таймер `music-downloader.timer` (21:00) запускает
`music_downloader.sh`: скачивание в `_cloud` и сортировщик.
