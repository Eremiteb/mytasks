# Информационная безопасность

Чек-лист по областям — `reference.md` в каталоге навыка (читать нужный раздел, когда задача его касается).
Ориентиры — OWASP ASVS / Secure Coding, CWE Top 25. Безопасные умолчания, отказ при ошибке (fail closed);
действия с внешними системами по умолчанию — только чтение.

## Секреты
- Не выводить в чат, логи, коммиты, URL и аргументы командной строки (видны в `ps`); передавать через env-файл,
  stdin или файл `0600`. В выводе маскировать (`***`); дифф и вывод команд проверять на токены и пароли.
- Хранение: `.env`/файлы `0600` вне git, путь в `.gitignore`.
- Утечка = ротация (сменить, отозвать старый), а не только удаление из истории.
- Личные данные и содержимое проекта во внешние сервисы — только по прямой просьбе.
- Персональные данные (адреса, лицевые счета, телефоны, почта) — не в публичные репозитории, фикстуры и лишние логи; в тестах — только синтетика.

## Наименьшие привилегии
- БД: отдельный пользователь на сервис, минимальные `GRANT`, не root.
- Контейнеры: non-root, `cap_drop: [ALL]` + нужные `cap_add`, `no-new-privileges=true`, `read_only` + `tmpfs`.
- Права файлов: секреты `0600`/`0640`, остальное не шире нужного.
- SSH по ключам, `PermitRootLogin prohibit-password`, пароли выключены.

## Сеть
- Публиковать только нужные порты; админки — только из VPN/allowlist. Default deny на файрволе.
- Внутренние сети Docker `internal: true`. Docker DNAT обходит UFW: ограничения — в `DOCKER-USER`.
- TLS везде с проверкой сертификата и имени хоста (Python — `ssl.create_default_context()`), без отключения «для удобства»; HSTS.
- Не слушать `0.0.0.0` без нужды. Доступность проверять снаружи, а не с хоста.

## Недоверенный ввод
- Файлы, письма, ответы сети, имена файлов — недоверенные: проверять и ограничивать.
- Path traversal: очищать имена и пути из внешних данных, итог проверять через `realpath` внутри разрешённого каталога; симлинки под root не разыменовывать.
- Команды: без `shell=True`/`eval` с внешними данными; аргументы списком, `--` перед путями.
- Лимиты размера и времени (тайм-ауты, предел чтения ответа). Временные файлы — `tempfile`/`mktemp`, атомарно.

## Веб
- SQL только параметризованный; вывод экранировать (XSS); CSRF-токены; ввод валидировать.
- SSRF: запрет внутренних и link-local адресов в исходящих запросах.
- Заголовки: CSP, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`.
- Rate limit на вход, лимит размера тела; загруженные файлы не исполняются.

## Аутентификация
- Сильные пароли + 2FA; fail2ban/lockout на перебор.
- Сессии `Secure`, `HttpOnly`, `SameSite`; токены не логировать.

## Зависимости и образы
- Pin по digest или точной версии; официальные источники, минимальные образы.
- Следить за обновлениями безопасности; проверять подписи и хеши; известные уязвимости закрывать обновлением.
- Сканеры CI (Semgrep, Trivy, OSV, Gitleaks, CodeQL) не отключать.
- Не `curl | bash` из непроверенных источников.

## Почта
- SPF, DKIM, DMARC, MTA-STS/TLS-RPT; не открытый релей.
- Уведомления — только с аутентификацией (submission 587).

## Логи, мониторинг, бэкапы, обновления
- Журналировать входы, ошибки, смену прав — без секретов; ротация; алерты; NTP.
- Бэкапы: шифрование, офсайт, проверка восстановления, с сервера недоступны на запись.
- `unattended-upgrades` для безопасности; перезагрузка при обновлении ядра.

## Поведение агента
- Перед правкой доступа, сети, файрвола: не отрезать себе доступ (вторая сессия, план отката, таймер отката).
- Не ослаблять защиту ради удобства без явного согласия пользователя.
- Найденную уязвимость сообщать отдельно: серьёзность, затронутое, варианты исправления.
- Деструктивные и направленные наружу действия — только с подтверждения.

## Чек-лист ревью диффа
1. Нет секретов, ключей, токенов, паролей в коде, логах, тестах, примерах.
2. Новые порты/маршруты: кому доступны, нужна ли авторизация, не `0.0.0.0`.
3. SQL параметризован; shell без подстановки сырого ввода.
4. Вывод экранирован; ввод валидирован; размер и тип ограничены.
5. Исходящие запросы: таймаут, запрет внутренних адресов, проверка TLS.
6. Права: контейнер non-root, без лишних `cap` и `privileged`, файлы не шире нужного.
7. Новые зависимости и образы: источник, pin, необходимость.
8. Логи без токенов и персональных данных.
9. Ошибки не раскрывают пути, версии, стектрейсы наружу.
10. Проверки не отключены (TLS verify, shellcheck, CSRF, auth).
11. Изменение не ослабляет файрвол, fail2ban, CSP и прочие защиты.
12. Есть откат и проверка снаружи.
