# Информационная безопасность

Подробный чек-лист по областям — `reference.md` в каталоге этого навыка
(читай нужный раздел, когда задача касается области). Ориентиры — OWASP ASVS /
Secure Coding, CWE Top 25. Безопасные значения по умолчанию и отказ при ошибке
(fail closed); действия с внешними системами по умолчанию только чтение.

## Секреты
- Никогда не выводи в чат, логи, коммиты, URL и аргументы командной строки
  (видны в `ps`); передавай через env-файл, stdin или файл `0600`.
- Хранение: `.env`/файлы `0600` вне git, путь в `.gitignore`.
- Утечка = ротация (сменить секрет, отозвать старый), а не удаление из истории.
- В выводе маскируй (`***`); проверяй дифф и вывод команд на токены и пароли.
- Личные данные и содержимое проекта во внешние сервисы не отправляй без прямой просьбы.
- Персональные данные (адреса, лицевые счета, телефоны, почта) — не в публичные
  репозитории, тестовые фикстуры и лишние логи; в тестах только синтетические данные.

## Наименьшие привилегии
- БД: отдельный пользователь на сервис, минимальные `GRANT`, не root.
- Контейнеры: non-root где возможно, `cap_drop: [ALL]` + нужные `cap_add`,
  `no-new-privileges=true`, `read_only` + `tmpfs`.
- Права файлов: секреты `0600`/`0640`, остальное не шире нужного.
- SSH по ключам, `PermitRootLogin prohibit-password`, пароли выключены.

## Сеть
- Публикуй только нужные порты; админки — только из VPN/allowlist.
- Внутренние сети Docker `internal: true`; файрвол default deny.
- Docker DNAT обходит UFW: ограничения ставь в цепочку `DOCKER-USER`.
- TLS везде с проверкой сертификата и имени хоста (в Python — явный
  `ssl.create_default_context()` для imaplib/smtplib и т. п.), без отключения
  проверки «для удобства»; HSTS; не слушай `0.0.0.0` без нужды (привязывай к адресу).
- Доступность проверяй снаружи, а не с хоста.

## Недоверенный ввод
- Файлы, письма, ответы сети, имена файлов — недоверенные: проверяй и ограничивай.
- Path traversal: имена и пути из внешних данных очищай, итоговый путь проверяй
  внутри разрешённого каталога (`realpath`), симлинки не разыменовывай под root.
- Команды: без `shell=True`/`eval` с внешними данными; аргументы списком, `--` перед путями.
- Лимиты размера и времени обработки (тайм-ауты, предел чтения ответа).
- Временные файлы — `tempfile`/`mktemp`, атомарная запись, без предсказуемых имён
  в общих каталогах.

## Веб
- Ввод валидируй; SQL только параметризованный; вывод экранируй (XSS); CSRF-токены.
- SSRF: запрещай внутренние и link-local адреса в исходящих запросах.
- Заголовки: CSP, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`.
- Rate limit на вход, лимит размера тела, загруженные файлы не исполняются.

## Аутентификация
- Сильные пароли + 2FA; fail2ban/lockout на перебор.
- Сессии `Secure`, `HttpOnly`, `SameSite`; токены не логируй.

## Зависимости и образы
- Pin по digest, официальные источники, минимальные образы.
- Следи за обновлениями безопасности; проверяй подписи и хеши; известные уязвимости
  закрывай обновлением.
- Сканеры CI (Semgrep, Trivy, OSV, Gitleaks, CodeQL) не отключай.
- Не `curl | bash` из непроверенных источников.

## Почта
- SPF, DKIM, DMARC, MTA-STS/TLS-RPT; не открытый релей.
- Уведомления — только с аутентификацией (submission 587).

## Логи, мониторинг, бэкапы, обновления
- Журналируй входы, ошибки, смену прав — без секретов; ротация; алерты; NTP.
- Бэкапы: шифрование, офсайт, проверка восстановления, с сервера недоступны на запись.
- `unattended-upgrades` для безопасности; перезагрузка при обновлении ядра.

## Поведение агента
- Перед правкой доступа, сети, файрвола: убедись, что не отрежешь себе доступ
  (держи вторую сессию, план отката, таймер отката).
- Не ослабляй защиту ради удобства без явного согласия пользователя.
- Найденную уязвимость сообщай отдельно: серьёзность, затронутое, варианты исправления.
- Деструктивные и направленные наружу действия — только с подтверждения.

## Чек-лист ревью диффа
1. Нет секретов, ключей, токенов, паролей в коде, логах, тестах, примерах.
2. Новые порты/маршруты: кому доступны, нужна ли авторизация, не слушает ли `0.0.0.0`.
3. SQL параметризован; команды shell без подстановки сырого ввода.
4. Вывод экранирован; ввод валидирован; размер и тип ограничены.
5. Исходящие запросы: таймаут, запрет внутренних адресов, проверка TLS.
6. Права: контейнер non-root, лишние `cap` и `privileged` убраны, файлы не шире нужного.
7. Новые зависимости и образы: источник, pin, необходимость.
8. Логи не содержат токенов и персональных данных.
9. Ошибки не раскрывают пути, версии, стектрейсы наружу.
10. Проверки не отключены (TLS verify, shellcheck, CSRF, auth).
11. Изменение не ослабляет файрвол, fail2ban, CSP и прочие защиты.
12. Есть откат и проверка снаружи.
