# Чек-лист ИБ по областям

Применяй раздел, когда задача его касается; не добавляй меры, которых нет в задаче.

## Секреты
- Источник: `.env`, Docker secrets, файл `0600`; не в образе, не в `ENV` Dockerfile, не в `git`.
- `.gitignore`: `.env`, `*.pem`, `*.key`, дампы. Проверка: `git ls-files | grep -Ei 'env|key|pem'`.
- Утечку ищи также в истории: `git log -p -S<фрагмент>`; найдено — ротация, потом чистка.
- Не передавай секрет в `argv` и URL (`ps`, access-логи, история shell); используй
  `--password-stdin`, `curl -K -`, `MYSQL_PWD` через файл, `.my.cnf` `0600`.
- Вывод `docker inspect`, `env`, `docker compose config` содержит секреты: фильтруй.
- Разные секреты для разных сред и сервисов; генерируй `openssl rand -base64 32`.
- Сменил секрет: обнови всех потребителей, перезапусти, проверь вход.

## Привилегии и контейнеры
- `user:` не root; `cap_drop: [ALL]`, `cap_add` только нужные; `no-new-privileges=true`.
- `read_only: true` + `tmpfs` для записываемых путей; не `privileged`, не `network_mode: host` без нужды.
- Не монтируй `/var/run/docker.sock`: это root на хосте; если нужно, через прокси с ограничением.
- Монтирования `:ro`, где запись не нужна; не монтируй `/`, `/etc`, `/root`.
- Лимиты `mem_limit`, `pids_limit`, `cpus` против исчерпания ресурсов.
- БД: `CREATE USER ... @'host'`, `GRANT` на конкретную схему и операции; без `GRANT ALL ON *.*`;
  без анонимных пользователей и `root@'%'`.
- sudo: узкие правила `NOPASSWD` на конкретные команды, не `ALL`.
- SSH: `PasswordAuthentication no`, `PermitRootLogin prohibit-password`, `AllowUsers`, смена порта не защита.

## Сеть и файрвол
- Default deny на входе; открывай точечно (`ufw allow from <vpn> to any port N`).
- Docker обходит UFW через DNAT: правило в `DOCKER-USER` (`! -i wg0 --ctorigdst <адрес> -j DROP`)
  или публикация на `127.0.0.1`/адрес VPN.
- Проверка снаружи: `nmap` с внешнего хоста, netns+veth для VPN-портов; трафик самого
  хоста идёт через `OUTPUT` и `DOCKER-USER` не проходит.
- Сети compose: `internal: true` для сервисов без выхода наружу; БД не в публичной сети.
- TLS: актуальные протоколы (1.2+), HSTS (`max-age` + `includeSubDomains`), автопродление, мониторинг срока.
- Админки (мониторинг, БД-интерфейсы, API управления): VPN или allowlist + аутентификация.
- Перед правкой UFW/маршрутов/WireGuard: сохрани правила, держи открытой вторую сессию,
  поставь отложенный откат (`at`/`systemd-run --on-active`).
- DNS: резолвер с DNSSEC/DoT где возможно; закрытые рекурсивные резолверы не открывай наружу.

## Веб-приложения
- SQL: плейсхолдеры/prepared statements; имена таблиц и столбцов — из белого списка.
- XSS: экранирование по контексту (HTML, атрибут, JS, URL); CSP без `unsafe-inline` где можно.
- CSRF: токены и `SameSite`; изменяющие запросы не по GET.
- SSRF: разрешай только http/https, резолви и проверяй IP (запрет 127/8, 10/8, 172.16/12,
  192.168/16, 169.254/16, ::1, fc00::/7), не следуй редиректам вслепую.
- Заголовки: `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `X-Frame-Options`/`frame-ancestors`,
  `Referrer-Policy`, `Permissions-Policy`; убери `Server`/`X-Powered-By` с версией.
- Загрузка файлов: проверка типа по содержимому, лимит размера, имя файла генерируй,
  каталог загрузки без исполнения (PHP `engine off`, `nginx/caddy` без handler).
- Rate limit: вход, сброс пароля, API; `client_max_body_size`/`request_body max_size`.
- Ошибки: наружу общее сообщение, подробности в лог; `display_errors=Off`, debug выключен.
- Path traversal: нормализуй путь, проверяй префикс каталога; не склеивай ввод в путь.

## Аутентификация
- Пароли: менеджер паролей, длина важнее сложности; хранение — argon2id/bcrypt, не хеш без соли.
- 2FA (TOTP/WebAuthn) для админов и внешних сервисов; коды восстановления хранить отдельно.
- Блокировка: fail2ban на ssh, почту, веб-логины; белый список своих адресов в конфиге, а не в коде.
- Сессии: `Secure; HttpOnly; SameSite=Lax|Strict`, ротация идентификатора после входа, срок жизни.
- Токены API: узкие права, срок, отзыв; не в логах и URL.
- Учётные записи по умолчанию отключи или смени пароль сразу.

## Зависимости, образы, сборка
- Образ по digest (`@sha256:`) из официального или проверенного реестра; не `latest`.
- Минимальная база (alpine/distroless/slim), многоэтапная сборка, пакеты без лишнего.
- Обновления безопасности: регулярная проверка (`apt list --upgradable`, сканер образов, `pip-audit`, `npm audit`).
- Проверка подписи/хеша скачанного: `sha256sum -c`, GPG, `cosign` где есть.
- Не `curl | bash`; скачай, проверь, потом запускай.
- Lock-файлы зафиксированы; новая зависимость — осознанное решение (ponytail: сначала stdlib).
- Патч чужого компонента — локально и с build-проверкой строк; не молча.

## Почта
- SPF (`-all` или `~all`), DKIM (ключ 2048, ротация), DMARC (`p=quarantine|reject`, `rua=`).
- MTA-STS и TLS-RPT; DANE при DNSSEC; PTR совпадает с именем хоста.
- Не открытый релей: отправка только после аутентификации; порт 25 принимает, но не релеит чужое.
- Служебные уведомления: через submission 587 с логином, иначе уйдёт в спам и без DKIM.
- Ограничения: rate limit на отправителя, размер письма, антиспам/антивирус.
- Проверка: заголовки `Authentication-Results` в доставленном письме; тест на open relay.

## Логи и мониторинг
- Журналируй: входы (успех/отказ), смену прав и конфигурации, ошибки, перезапуски.
- Не пиши в лог пароли, токены, номера карт, тело запросов с персональными данными.
- Ротация и срок хранения заданы; место на диске под контролем (алерт на заполнение).
- Алерты на аномалии: всплеск отказов входа, падение сервиса, рост ошибок 5xx, исчерпание ресурсов.
- Время синхронизировано (`timedatectl`: NTP active); без этого логи не сопоставить.
- Логи недоступны на запись обычным сервисам; для ИБ-событий — копия вне сервера.

## Бэкапы
- Шифрование на стороне источника; ключ хранится отдельно от бэкапа.
- Правило 3-2-1: три копии, два носителя, одна вне площадки.
- С сервера у бэкапа только добавление (append-only/снимки), удалить или зашифровать его нельзя.
- Регулярная проверка восстановления; фиксируй дату и результат.
- Бэкап БД согласован (дамп/снимок), не копия живых файлов.

## Обновления и хост
- `unattended-upgrades` для security-репозитория; автоперезагрузка в окно, если обновилось ядро (`/var/run/reboot-required`).
- Лишние службы и порты отключены; `ss -tulpn` сверяется с ожидаемым.
- sysctl/ядро: `rp_filter`, `accept_redirects=0`, `tcp_syncookies=1` где уместно.
- Права: `umask`, SUID-файлы под контролем, критичные файлы (`/etc/shadow`, ключи) `0600`/`0640`.
- fail2ban, auditd (по необходимости), проверка `last`/`lastb`/`journalctl -u ssh`.

## Поведение агента при изменениях
- Сначала прочитай текущее состояние (правила, конфиг, активные сессии), затем правь.
- Для доступа и сети: план отката заранее; изменение применяй так, чтобы текущая сессия не оборвалась.
- Проверь результат снаружи (другой хост, VPN-клиент), а не только `curl localhost`.
- Не ослабляй защиту ради удобства (`chmod 777`, `--privileged`, отключение TLS verify, `0.0.0.0`)
  без явного согласия; временное ослабление фиксируй и возвращай.
- Найденная уязвимость: отдельный блок отчёта — что, где, серьёзность (крит/высокая/средняя/низкая),
  как проверить, варианты исправления; не чини молча тем, что меняет поведение.
- Деструктивное (удаление данных, сброс ключей, force-push) и отправка данных наружу —
  только с подтверждения пользователя.
