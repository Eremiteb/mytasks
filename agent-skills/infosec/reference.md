# Чек-лист ИБ по областям

Применять раздел, когда задача его касается; меры, которых нет в задаче, не добавлять.

## Секреты
- Источник: `.env`, Docker secrets, файл `0600`; не в образе, не в `ENV` Dockerfile, не в `git`.
- `.gitignore`: `.env`, `*.pem`, `*.key`, дампы. Проверка: `git ls-files | grep -Ei 'env|key|pem'`.
- Утечку искать в истории: `git log -p -S<фрагмент>`; найдено — ротация, потом чистка.
- Не передавать в `argv` и URL (`ps`, access-логи, история shell): `--password-stdin`, `curl -K -`, `MYSQL_PWD` через файл, `.my.cnf` `0600`.
- Вывод `docker inspect`, `env`, `docker compose config` содержит секреты — фильтровать.
- Разные секреты для сред и сервисов; генерировать `openssl rand -base64 32`.
- После смены секрета: обновить всех потребителей, перезапустить, проверить вход.

## Привилегии и контейнеры
- `user:` не root; `cap_drop: [ALL]`, `cap_add` только нужные; `no-new-privileges=true`.
- `read_only: true` + `tmpfs` для записываемых путей; не `privileged`, не `network_mode: host` без нужды.
- Не монтировать `/var/run/docker.sock` (это root на хосте); если нужно — через прокси с ограничением.
- Монтирования `:ro`, где запись не нужна; не монтировать `/`, `/etc`, `/root`.
- Лимиты `mem_limit`, `pids_limit`, `cpus`.
- БД: `CREATE USER ... @'host'`, `GRANT` на конкретную схему и операции; без `GRANT ALL ON *.*`, анонимов и `root@'%'`.
- sudo: узкие `NOPASSWD` на конкретные команды, не `ALL`.
- SSH: `PasswordAuthentication no`, `PermitRootLogin prohibit-password`, `AllowUsers`; смена порта — не защита.

## Сеть и файрвол
- Default deny на входе; открывать точечно (`ufw allow from <vpn> to any port N`).
- Docker обходит UFW через DNAT: правило в `DOCKER-USER` (`! -i wg0 --ctorigdst <адрес> -j DROP`) или публикация на `127.0.0.1`/адрес VPN.
- Проверка снаружи: `nmap` с внешнего хоста, netns+veth для VPN-портов; трафик самого хоста идёт через `OUTPUT`, `DOCKER-USER` не проходит.
- Сети compose: `internal: true` для сервисов без выхода наружу; БД не в публичной сети.
- TLS 1.2+, HSTS (`max-age` + `includeSubDomains`), автопродление, мониторинг срока.
- Админки (мониторинг, БД-интерфейсы, API управления): VPN или allowlist + аутентификация.
- Перед правкой UFW/маршрутов/WireGuard: сохранить правила, держать вторую сессию, поставить отложенный откат (`at`/`systemd-run --on-active`).
- DNS: резолвер с DNSSEC/DoT где возможно; закрытые рекурсивные резолверы не открывать наружу.

## Веб-приложения
- SQL: плейсхолдеры/prepared statements; имена таблиц и столбцов — из белого списка.
- XSS: экранирование по контексту (HTML, атрибут, JS, URL); CSP без `unsafe-inline`, где можно.
- CSRF: токены и `SameSite`; изменяющие запросы не по GET.
- SSRF: только http/https; резолвить и проверять IP (запрет 127/8, 10/8, 172.16/12, 192.168/16, 169.254/16, ::1, fc00::/7); редиректы не выполнять вслепую.
- Заголовки: `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `X-Frame-Options`/`frame-ancestors`, `Referrer-Policy`, `Permissions-Policy`; убрать `Server`/`X-Powered-By` с версией.
- Загрузка файлов: тип по содержимому, лимит размера, имя генерировать; каталог загрузки без исполнения (PHP `engine off`, `nginx/caddy` без handler).
- Rate limit: вход, сброс пароля, API; `client_max_body_size`/`request_body max_size`.
- Ошибки: наружу общее сообщение, детали — в лог; `display_errors=Off`, debug выключен.
- Path traversal: нормализовать путь, проверять префикс каталога; ввод в путь не склеивать.

## Аутентификация
- Пароли: менеджер паролей, длина важнее сложности; хранение argon2id/bcrypt, не хеш без соли.
- 2FA (TOTP/WebAuthn) для админов и внешних сервисов; коды восстановления — отдельно.
- Блокировка: fail2ban на ssh, почту, веб-логины; белый список своих адресов — в конфиге, не в коде.
- Сессии: `Secure; HttpOnly; SameSite=Lax|Strict`, ротация id после входа, срок жизни.
- Токены API: узкие права, срок, отзыв; не в логах и URL.
- Учётки по умолчанию отключить или сменить пароль сразу.

## Зависимости, образы, сборка
- Образ по digest (`@sha256:`) из официального или проверенного реестра; не `latest`.
- Минимальная база (alpine/distroless/slim), многоэтапная сборка, без лишних пакетов.
- Регулярная проверка обновлений: `apt list --upgradable`, сканер образов, `pip-audit`, `npm audit`.
- Подпись/хеш скачанного: `sha256sum -c`, GPG, `cosign` где есть.
- Не `curl | bash`: скачать, проверить, запустить.
- Lock-файлы зафиксированы; новая зависимость — осознанно (ponytail: сначала stdlib).
- Патч чужого компонента — локально и с build-проверкой строк; не молча.

## Почта
- SPF (`-all` или `~all`), DKIM (ключ 2048, ротация), DMARC (`p=quarantine|reject`, `rua=`).
- MTA-STS и TLS-RPT; DANE при DNSSEC; PTR совпадает с именем хоста.
- Не открытый релей: отправка только после аутентификации; порт 25 принимает, но чужое не релеит.
- Служебные уведомления — через submission 587 с логином; иначе спам и без DKIM.
- Ограничения: rate limit на отправителя, размер письма, антиспам/антивирус.
- Проверка: `Authentication-Results` в доставленном письме; тест на open relay.

## Логи и мониторинг
- Журналировать: входы (успех/отказ), смену прав и конфигурации, ошибки, перезапуски.
- Не писать в лог пароли, токены, номера карт, тела запросов с персональными данными.
- Ротация и срок хранения заданы; алерт на заполнение диска.
- Алерты: всплеск отказов входа, падение сервиса, рост 5xx, исчерпание ресурсов.
- NTP активен (`timedatectl`); без него логи не сопоставить.
- Логи недоступны на запись обычным сервисам; ИБ-события — копия вне сервера.

## Бэкапы
- Шифрование на стороне источника; ключ хранить отдельно от бэкапа.
- 3-2-1: три копии, два носителя, одна вне площадки.
- С сервера только добавление (append-only/снимки): удалить или зашифровать бэкап нельзя.
- Регулярная проверка восстановления; фиксировать дату и результат.
- Бэкап БД согласован (дамп/снимок), не копия живых файлов.

## Обновления и хост
- `unattended-upgrades` для security-репозитория; автоперезагрузка в окно при обновлении ядра (`/var/run/reboot-required`).
- Лишние службы и порты отключены; `ss -tulpn` сверяется с ожидаемым.
- sysctl: `rp_filter`, `accept_redirects=0`, `tcp_syncookies=1` где уместно.
- `umask`, SUID под контролем, критичные файлы (`/etc/shadow`, ключи) `0600`/`0640`.
- fail2ban, auditd по необходимости; проверка `last`/`lastb`/`journalctl -u ssh`.

## Поведение агента при изменениях
- Сначала прочитать текущее состояние (правила, конфиг, активные сессии), потом править.
- Для доступа и сети: план отката заранее; применять так, чтобы текущая сессия не оборвалась.
- Проверять снаружи (другой хост, VPN-клиент), а не только `curl localhost`.
- Не ослаблять защиту ради удобства (`chmod 777`, `--privileged`, отключение TLS verify, `0.0.0.0`) без явного согласия; временное ослабление фиксировать и возвращать.
- Уязвимость: отдельный блок отчёта — что, где, серьёзность (крит/высокая/средняя/низкая), как проверить, варианты исправления; не чинить молча то, что меняет поведение.
- Деструктивное (удаление данных, сброс ключей, force-push) и отправка данных наружу — только с подтверждения пользователя.
