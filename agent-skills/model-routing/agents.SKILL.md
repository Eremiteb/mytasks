# Выбор модели под шаг

Цель — не тратить старшую модель на механику и не отдавать лёгкой решения, где ошибка дорога.
Отвечать по-русски. Список доступных моделей — меню `/model` агента (в Codex ещё `~/.codex/models_cache.json`);
идентификаторы не угадывать, брать из меню.

**Применять всегда, когда это возможно** (требование пользователя): шаг ниже класса текущей модели
по умолчанию отдавать подагенту на самой лёгкой модели, если агент это умеет, иначе предлагать переключение.

**Младшая модель — только самая лёгкая** (решение пользователя 13.11.2026): средние модели (Claude Sonnet,
средняя GPT) не использовать ни для подагентов, ни для сессий, ни в предложении переключения.

**Вся рутина — лёгкой модели, старшей — только анализ** (решение пользователя 13.11.2026). Старшая модель
сама делает лишь то, с чем лёгкая не справится: анализ и диагностику с неизвестной причиной, архитектурные
решения, оценку рисков ИБ, необратимые операции и проверку результата лёгкой модели. Всё остальное — правки
по понятному плану, команды, проверки, сбор данных, документация, граф, коммит — уходит лёгкой модели, даже
если самому «быстрее». **Лучше написать план для лёгкой модели, чем делать на старшей:** если шаг можно
описать, старшая модель пишет подагенту точный план (файлы, конкретные правки или команды, критерии
готовности, проверки) и затем сверяет результат (`git diff`, вывод проверок). Не уверен, что лёгкая модель
справится даже по плану, — шаг остаётся на старшей, а не уходит на среднюю.

## Классы шагов

| Класс | Модель | Примеры |
|---|---|---|
| Механика по готовому образцу | самая лёгкая (Claude Haiku, Gemini Flash-Lite/Flash, младшая GPT) | документация по готовому коду, обновление графа, `git status`/`diff`, коммит и пуш после «да», переименования, чтение и пересказ |
| Типовая разработка с тестами | **самая лёгкая** (как механика) | новая функция по образцу соседних, правка тестов, починка упавших тестов, анализ логов |
| Решения и сложная диагностика | старшая (Claude Opus, Gemini Pro, старшая GPT) | новая архитектура, расследование с неизвестной причиной, ревью спорных мест, безопасность |
| Необратимое | старшая или не делать без «да» | удаление данных, миграции БД, службы и systemd, боевые запуски, force-push |

Сомневаешься между лёгкой и старшей — бери старшую. Лёгкую модель не использовать там, где ошибка тихая
(неверная миграция, неверный фильтр удаления).

## Как переключаться
Свою сессию агент сменить не может. Поэтому:
1. Если агент умеет подагентов с выбором модели (Claude Code `Agent` с `model`) — отдать самодостаточный
   шаг подагенту с полным брифом и проверить результат (`git diff`, тесты).
2. Иначе перед серией из ≥ 3 шагов более низкого класса написать пользователю одну строку:
   «Дальше механика (документация, граф, коммит) — можно переключиться: `/model <лёгкая модель>`;
   для архитектурной части вернёмся на старшую».
   Предлагать один раз за разговор; не предлагать при остатке меньше ~3 вызовов инструментов — смена модели
   сбрасывает кэш контекста, и первый ход на новой модели читает весь контекст по полной цене.

## Лимиты и контекст
Если агент показывает остаток лимита (Codex `/status`, Gemini нижняя строка): при расходе окна ≥ 70 % не
предлагать старшую модель до сброса; при заполнении контекста ≥ 50 % сначала предложить сжатие
(`/compact` или новая сессия), потом смену модели. Называть цифры в предложении.

## Политика расходов
Подстраивайся под то, как оплачивается агент: есть показатель лимита окна — действуют пороги выше; нет —
осторожные значения по умолчанию (механика лёгкой моделью, контекст ≥ 50 % — сжатие, старшая модель только
на дорогие шаги). Цены в навык не зашиты: порядок «старшая дороже» стабилен, числа сверять с актуальными
данными провайдера. Подагентов и параллельные сессии не плодить без явной пользы. Политика не отменяет
правил безопасности: необратимое не отдаётся лёгкой модели ради экономии.

## Безопасность
- Коммит и пуш — только после «да» именно на них; трейлер `Co-Authored-By` называет модель, которая реально делает коммит.
- Боевой запуск скрипта с `--dry-run` — только после успешного dry-run и «да» пользователя.
- В отчёте сказать, что и на какой модели сделано и что проверено сразу после.

**Метка — обязательство** (урок 2026-11-11): шаг ниже текущей модели исполнять подагентом этой модели,
если агент умеет; самому — только названное исключение (< ~3 вызовов, нужен контекст диалога, те же файлы)
с причиной для пользователя. Метки плана — только `[Haiku]` (самая лёгкая) и `[Opus]` (старшая).
