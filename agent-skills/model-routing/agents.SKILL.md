# Выбор модели под шаг

Перед первым планом или делегированием взять актуальный каталог моделей платформы (`/model`, API/инструмент или локальный кэш). Идентификаторы не угадывать.

Выбрать **две старшие модели**:
- быстрая и экономичная — обычная работа: типовая разработка, документация, команды, сбор данных, граф;
- самая сильная — сложная диагностика, архитектура, ИБ, необратимые операции, проверка результата.

Младшие и средние не использовать, кроме коммита и пуша. Примеры линеек: Claude — Fable и Opus; Codex — Sol и Astra; Gemini — две актуальные старшие. Не зашитые версии: в метках, командах и отчётах — точные идентификаторы своей платформы. Названия не переносить между платформами.

Codex (исключение с приоритетом): `gpt-6-astra` — планирование, сложные решения, ИБ, необратимое, итоговая проверка; `gpt-6-sol` — рабочая старшая; `gpt-6-luna` — младшая для безопасной рутины. Старшая составляет полный конкретный план рутины и передаёт подагенту на Luna; при доступном подагенте рутину сама не делает. Sol — если шаг не подходит Luna, но не требует Astra. Без подагентов — предложить `/model gpt-6-luna` после сверки каталога.

Если доступны подагенты с выбором модели: обычные самодостаточные шаги — первой старшей, сложные — второй. Иначе один раз предложить точную `/model <id>`.

Каждый шаг плана помечать точным идентификатором выбранной модели. Метка — обязательство: шаг исполняется ею.

**Рутина — младшей модели, обязательно** (16.11.2026; приоритет над «младшие не использовать»; без «по возможности», критерий — экономия токенов): больше одного вызова, вывод больше ~30 строк, серия правок, документация, тесты, установка, наблюдение, сбор данных, коммит. Старшая делает рутину сама, только если она дешевле брифа (один вызов с коротким выводом или бриф длиннее шага), и называет исключение с причиной.

| Платформа | Рутина (младшая) | Решения, ИБ, необратимое, проверка | Делегирование |
|---|---|---|---|
| Claude Code | Haiku (`claude-haiku-*`) | Opus | Agent с `model: haiku` |
| Codex | `gpt-6-luna`; не подходит — `gpt-6-sol` | `gpt-6-astra` | подагент на Luna; без подагентов — см. выше |
| Gemini CLI | самая младшая актуальной линейки (Flash/Flash-Lite) | самая сильная линейки (Pro) | подагент с младшей; без подагентов — `/model <младшая>` один раз |

**Максимум младшей модели в любых задачах** (16.11.2026): старшая — диспетчер и ревьюер (спецификации, решения, риски, проверка diff). Весь код по спецификации, включая новые функции, режимы, веб и API, пишет младшая модель кусками по одной функции; независимые — параллельно без пересечения файлов. Старшая пишет код сама только для узких мест безопасности, если ревью младшей дважды не прошло, и называет исключение.

**Коммит и пуш** — исключение с приоритетом (2026-11-15): всегда подагент **самой младшей модели** каталога (Codex — `gpt-6-luna`; Gemini — самая младшая линейки), даже из одного вызова. Старшая даёт готовое сообщение коммита и точный список файлов, затем сверяет `git log -1` и `git status`; трейлер и метка шага называют модель, реально сделавшую коммит. Нет подагентов — коммит делает текущая модель, сообщив пользователю.

Безопасность от модели не зависит: коммит и пуш — только после разрешения; боевой запуск — после успешного dry-run и подтверждения; необратимое — только самой сильной моделью и с явным «да».
