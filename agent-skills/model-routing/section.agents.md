## Выбор модели под шаг

Применять **всегда, когда это возможно**: шаг ниже класса текущей модели по умолчанию отдавать
подагенту на самой лёгкой модели, если агент это умеет, иначе предлагать переключение. Средние модели
(Claude Sonnet, средняя GPT) не использовать — ни для подагентов, ни для сессий, ни в предложении
переключения. Вся рутина — лёгкой модели; старшей — только анализ и то, с чем лёгкая не справится
(диагностика, архитектура, ИБ, необратимое, проверка результата). Лучше написать план для лёгкой
модели и проверить её результат, чем делать шаг на старшей.
Экономить дорогие модели: при составлении плана и на границе шагов относить каждый шаг к классу —
механика (документация, граф, коммит и пуш, чтение) → самая лёгкая модель; типовая разработка с тестами
→ тоже самая лёгкая; новая архитектура, сложная диагностика и необратимые операции (удаление данных,
миграции, службы, боевые запуски) → старшая. Сомневаешься — бери старшую. Если агент не может сменить
свою модель сам, перед серией механических шагов предложить пользователю одну строку с точной командой
переключения (один раз за разговор, не при остатке меньше ~3 вызовов: смена модели сбрасывает кэш).
Подробности — навык `model-routing` (`~/.agents/skills/model-routing/SKILL.md`; для Claude Code —
`~/.claude/skills/model-routing/SKILL.md`).
Шаги плана помечать классом модели: `[Haiku]` — самая лёгкая, `[Opus]` — старшая.

**Метка — обязательство, а не формальность** (урок 2026-11-11: метки ставились, а все шаги, включая
механику, делались на старшей модели). Шаг с меткой ниже текущей модели выполняется подагентом этой
модели, если агент это умеет; сделать его самому можно только как названное исключение (шаг короче
~3 вызовов, нужен контекст диалога, правит файлы, которые сейчас правишь сам) — с причиной для
пользователя. Это постоянная просьба пользователя, она важнее умолчаний среды против подагентов.
