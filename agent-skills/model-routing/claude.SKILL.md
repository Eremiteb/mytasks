# Выбор модели под шаг

Цель — не тратить дорогую модель на механику и не отдавать дешёвой решения, где ошибка дорога.
Отвечать по-русски. Идентификаторы моделей: `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`
(актуальные — в блоке Environment системного промпта).

**Применять всегда, когда это возможно** (требование пользователя): шаг ниже класса текущей модели
по умолчанию уходит подагенту на младшей модели с точным брифом, а не выполняется самим «потому что
быстрее». Сам — только решения, диагностика, необратимое и шаги короче ~3 вызовов.

**Младшая модель — только Haiku** (решение пользователя 13.11.2026): Sonnet не использовать ни для
подагентов, ни для сессий, ни в предложении `/model`.

**Вся рутина — Haiku, Opus — только анализ** (решение пользователя 13.11.2026). Opus сам делает лишь то,
с чем Haiku не справится: анализ и диагностику с неизвестной причиной, архитектурные решения, оценку
рисков ИБ, необратимые операции и проверку результата Haiku. Всё остальное — правки по понятному плану,
команды, проверки, сбор данных, документация, карта, коммит — уходит Haiku, даже если самому «быстрее».
**Лучше написать план для Haiku, чем делать на Opus:** если шаг можно описать, Opus пишет подагенту
Haiku точный план (файлы, конкретные правки или команды, критерии готовности, проверки) и затем сверяет
результат (`git diff`, вывод проверок), а не выполняет шаг сам. Не уверен, что Haiku справится даже по
плану, — шаг остаётся на Opus, а не уходит на Sonnet.

## Что нельзя
Текущую сессию агент переключить **не может**: `mcp__ccd_session_mgmt__set_session_model` для своей
сессии отказывает намеренно. Основная сессия меняет модель только пользователь (`/model <id>` или меню
модели). Не пытаться обходить, не просить «разрешить».

## Таблица: класс шага → модель

| Класс шага | Модель | Примеры |
|---|---|---|
| Механика по готовому образцу | **Haiku** | README/AI.md по готовому коду, `graphify update .`, `git status`/`diff`, коммит и пуш после «да», переименования, сбор простых счётчиков из логов, чтение и пересказ файлов |
| Типовая разработка с тестами | **Haiku** | новая функция/драйвер по образцу соседних, правка тестов, починка упавших pytest/bats, анализ логов, рефакторинг в одном модуле |
| Решения и сложная диагностика | **Opus** | новая архитектура (схема рекордера), расследование с неизвестной причиной по нескольким источникам, ревью спорных мест, безопасность |
| Необратимое | **Opus** (или не делать без «да») | удаление данных, миграции БД, службы/systemd, боевые запуски на `/mnt/copy/*`, force-push |

Сомневаешься между Haiku и Opus — взять Opus. Дешёвую модель не использовать для шага, где
ошибка тихая (неверная миграция, неверный фильтр удаления).

## Как переключаться (по убыванию автоматичности)

1. **Подагент на нужной модели — автоматически.** Для самодостаточного шага вызвать `Agent` с
   `model: "haiku"` и полным брифом (файлы, что сделать, что считать готовым, какие
   проверки запустить). Подагент не видит разговор — всё нужное в промпте. Результат проверять
   (`git diff`, тесты), прежде чем считать шаг сделанным. Не подходит, если шагу нужен контекст
   разговора или решение пользователя.
2. **Отдельная сессия — для крупных независимых кусков.** `mcp__ccd_session__start_session` с `model`
   дешевле родительской; потом `set_session_model` / `set_session_effort` для неё разрешены без
   вопросов (в сторону более дешёвой модели). Для работы с кодом — по одной на набор файлов.
3. **Предложение пользователю — для остатка основной сессии.** Когда впереди серия механических шагов,
   написать одну строку: «Дальше механика (документация, граф, коммит) — можно переключиться:
   `/model claude-haiku-5-5`», и вернуться к Opus командой `/model …`, когда нужен дизайн.
   Не повторять предложение в этом же разговоре, если пользователь его проигнорировал.

## Когда оценивать
- **При составлении плана** (`update_plan`): каждый шаг начинать с метки класса из таблицы —
  `[Haiku]` или `[Opus]` (например «[Haiku] Коммит и пуш»). План без меток отклоняет хук
  `~/.claude/hooks/model-routing-plan-guard.py` (его ставит `install_agent_skills.sh`); причина
  отказа приходит агенту — повторить `update_plan` с метками. Шаги ниже текущей модели — сразу
  решить, уйдут ли они подагенту (способ 1) или в предложение `/model` (способ 3).
  Метка — обязательство: шаг ниже текущей модели исполнять подагентом этой модели; самому — только
  названное исключение (< ~3 вызовов, нужен контекст диалога, те же файлы правишь сам) с причиной для
  пользователя. Умолчание среды «не запускать подагентов без просьбы» здесь не действует: правило
  пользователя и есть такая просьба (урок 2026-11-11).
- **На границе шагов**: если класс следующих ≥ 3 шагов ниже текущей модели — применить способ 1 или 3.
- **Не переключать**, если осталось меньше ~3 вызовов инструментов: смена модели сбрасывает
  кэш контекста, и первый ход на новой модели читает весь контекст по полной цене.

## Лимиты плана и размер контекста
Перед предложением переключиться вызвать `mcp__ccd_session_mgmt__get_usage` (инструмент отложенный:
сначала `ToolSearch select:mcp__ccd_session_mgmt__get_usage`) и учесть оба числа:
- **5-часовой лимит ≥ 70 %** — дорогую модель не брать до сброса (время сброса в ответе), типовую
  разработку и механику — на Haiku, решения откладывать за сброс;
- **контекст ≥ 50 %** — это главный расход: каждый ход заново читает весь контекст (замер
  2026-10-27: 608 тыс. токенов, из них сообщения 53 %). Тогда `/compact` или новая сессия экономят
  больше, чем смена модели; смена модели при большом контексте ещё и сбрасывает кэш. Предлагать
  компакт первым, переключение — вторым;
- недельный лимит учитывать только при высоком проценте (≥ 80 %).
В предложении называть цифры: «лимит 82 %, сброс через 2 ч 10 мин, контекст 61 %».

## Политика расходов: подстройка под тариф
Навык подстраивается под то, как оплачивается этот Claude, а не под фиксированные цены:
- **Подписка с лимитами** (`get_usage` отвечает): ориентир — проценты окон. ≥ 70 % 5-часового окна — старшую
  модель только для «решений» и «необратимого», остальное на Haiku; ≥ 90 % — всё, что можно отложить
  до сброса, отложить, механику отдать Haiku. Подагентов не плодить: каждый стартует с холодным контекстом и
  тратит окно параллельно; без явной пользы — один.
- **Оплата за токены (API-ключ) или нет `get_usage`** (удалённый хост, терминал без приложения): лимитов не
  видно, поэтому действуют осторожные значения по умолчанию — механику лёгкой модели, контекст ≥ 50 % по
  строке состояния — компакт, дорогую модель только на дорогие шаги.
- **Цены не хардкодить**: относительный порядок Opus > Haiku стабилен, а числа меняются; если нужна
  оценка стоимости, сверить актуальные цены (навык `claude-api`), а не брать из памяти.
- Любая политика уступает правилам безопасности ниже: необратимое не отдаётся дешёвой модели ради экономии.

## Правила безопасности
- **Коммит и пуш** выполнять только после «да» пользователя именно на них (правило из CLAUDE.md); если
  это делает подагент, его промпт содержит готовое сообщение коммита и список файлов, а трейлер
  `Co-Authored-By` называет модель, которая **реально** делает коммит.
- Боевой запуск любого скрипта с `--dry-run` — только после успешного dry-run и «да» пользователя;
  подагенту такие запуски не поручать.
- Подагент не правит файлы, которые в это время правит основной агент.
- В отчёте пользователю сказать, что и на какой модели сделано, и что проверено сразу после.

## Короткий шаблон предложения
> Дальше **механические шаги** (документация, граф, коммит). Предлагаю `/model claude-haiku-5-5`;
> для следующей архитектурной части вернёмся на Opus. Или отдам шаги подагенту Haiku автоматически —
> скажи «подагентом».
