# Выбор модели под шаг

Отвечать по-русски. Модели: `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5` (актуальные — в Environment).

## Правила пользователя (обязательные)
- **Рутина — подагенту Haiku всегда** (16.11.2026; без «по возможности», критерий — экономия токенов: каждый
  вызов основной сессии перечитывает весь контекст по цене старшей модели). Рутина: больше одного вызова
  инструмента; вывод больше ~30 строк (файлы, логи, grep, diff, листинги, выборки); серия однотипных правок,
  документация, тесты, установка, наблюдение, сбор цифр; коммит и пуш — всегда.
- Opus делает рутину сам, только если она дешевле брифа (один вызов с коротким выводом или бриф длиннее шага).
  Исключение называть пользователю с причиной; нарушение — ошибка, сказать о ней.
- **Максимум Haiku** (16.11.2026, сильнее правил ниже). Opus — диспетчер и ревьюер: точные спецификации
  (файлы, сигнатуры, алгоритм, граничные случаи, критерии готовности), решения, риски, проверка diff. Весь код
  (включая новые функции, режимы, веб, API, миграции по готовой схеме) — подагенты Haiku кусками по одной
  функции/странице; независимые — параллельно без пересечения файлов. Opus пишет код сам только для узких мест
  безопасности (пути, распаковка, удаление данных), если ревью Haiku дважды не прошло, и называет это.
- **Младшая модель — только Haiku** (13.11.2026): Sonnet не использовать ни для подагентов, ни для сессий, ни в `/model`.
- **Вся рутина — Haiku, Opus — только анализ** (13.11.2026). Opus: диагностика с неизвестной причиной,
  архитектура, риски ИБ, необратимое, проверка результата Haiku. Остальное (правки по плану, команды, проверки,
  сбор данных, документация, карта, коммит) — Haiku, даже если самому быстрее.
- **План для Haiku вместо исполнения на Opus:** точный план подагенту (файлы, правки или команды, критерии
  готовности, проверки), затем сверка (`git diff`, вывод проверок). Не уверен, что Haiku справится по плану, —
  шаг остаётся на Opus, не уходит на Sonnet.

Свою сессию агент не переключает: `mcp__ccd_session_mgmt__set_session_model` отказывает намеренно. Переключает
только пользователь (`/model <id>` или меню). Не обходить, не просить «разрешить».

## Таблица: класс шага → модель

| Класс шага | Модель | Примеры |
|---|---|---|
| Механика по готовому образцу | **Haiku** | README/AI.md по готовому коду, `graphify update .`, `git status`/`diff`, коммит и пуш после «да», переименования, счётчики из логов |
| Типовая разработка с тестами | **Haiku** | функция по образцу соседних, правка тестов, починка pytest/bats, анализ логов, рефакторинг в модуле |
| Решения и сложная диагностика | **Opus** | новая архитектура (схема рекордера), расследование с неизвестной причиной, ревью спорных мест, безопасность |
| Необратимое | **Opus** (или не делать без «да») | удаление данных, миграции БД, службы/systemd, боевые запуски на `/mnt/copy/*`, force-push |

Сомневаешься — Opus. Дешёвую модель не брать для шага с тихой ошибкой (неверная миграция, неверный фильтр удаления).

## Как переключаться (по убыванию автоматичности)
1. **Подагент на нужной модели — автоматически.** `Agent` с `model: "haiku"` и полным брифом (файлы, что сделать,
   что считать готовым, проверки). Подагент не видит разговор — всё в промпте. Результат проверять (`git diff`,
   тесты) до того, как считать шаг сделанным. Не подходит, если нужен контекст разговора или решение пользователя.
2. **Отдельная сессия — для крупных независимых кусков.** `mcp__ccd_session__start_session` с `model` дешевле
   родительской; дальше `set_session_model` / `set_session_effort` в сторону дешевле — без вопросов. Для кода — по сессии на набор файлов.
3. **Предложение пользователю — для остатка сессии.** Одной строкой: «Дальше механика — можно переключиться:
   `/model claude-haiku-5-5`; для архитектуры вернёмся на Opus — `/model …`. Или отдам шаги подагенту — скажи
   «подагентом»». Не повторять, если проигнорировал.

## Когда оценивать
- **План (`update_plan`):** каждый шаг с меткой `[Haiku]` или `[Opus]` («[Haiku] Коммит и пуш»). Без меток план
  отклоняет хук `~/.claude/hooks/model-routing-plan-guard.py` (ставит `install_agent_skills.sh`); причину получит
  агент — повторить `update_plan` с метками. План из 3+ шагов, где все `[Opus]`, тоже отклоняется без причины
  «(Opus: …)» хотя бы в одном шаге: рутину пометить `[Haiku]`, «весь план на Opus» обосновать. Шаги ниже текущей
  модели сразу решить: подагенту (1) или `/model` (3).
- **Метка — обязательство:** шаг ниже текущей модели исполняет подагент этой модели; самому — только исключение
  «дешевле брифа» с причиной. Коммит и пуш под исключение не попадают. Умолчание «не запускать подагентов без
  просьбы» не действует: правило пользователя и есть такая просьба (урок 2026-11-11).
- **На границе шагов:** класс следующих ≥ 3 шагов ниже текущей модели — способ 1 или 3.
- **Не переключать**, если осталось меньше ~3 вызовов: смена модели сбрасывает кэш, первый ход читает весь контекст по полной цене.

## Лимиты и контекст
Перед предложением переключиться вызвать `mcp__ccd_session_mgmt__get_usage` (отложенный: `ToolSearch select:mcp__ccd_session_mgmt__get_usage`):
- **5-часовой лимит ≥ 70 %** — дорогую модель не брать до сброса (время в ответе); механику и разработку — Haiku, решения — за сброс;
- **контекст ≥ 50 %** — главный расход (замер 2026-10-27: 608 тыс. токенов, из них сообщения 53 %). Сначала
  `/compact` или новая сессия (экономят больше смены модели, которая сбрасывает кэш), переключение — вторым;
- недельный лимит — только при ≥ 80 %.
В предложении называть цифры: «лимит 82 %, сброс через 2 ч 10 мин, контекст 61 %».

## Политика расходов
- **Подписка** (`get_usage` отвечает): ≥ 70 % 5-часового — старшая только на «решения» и «необратимое»; ≥ 90 % —
  отложимое до сброса, механику Haiku. Подагентов не плодить: каждый стартует с холодным контекстом; без пользы — один.
- **API-ключ или нет `get_usage`** (удалённый хост, терминал без приложения): умолчания — механика Haiku, контекст ≥ 50 % по строке состояния — `/compact`, старшая только на дорогие шаги.
- **Цены не хардкодить**: порядок Opus > Haiku стабилен; для оценки стоимости сверять цены (навык `claude-api`).
- Любая политика уступает правилам безопасности ниже.

## Правила безопасности
- **Коммит и пуш** — только после «да» именно на них (CLAUDE.md) и **всегда подагентом самой младшей модели каталога**
  (сейчас Haiku; решение 2026-11-15), даже из одного вызова. Промпт — готовое сообщение коммита и точный список
  файлов; трейлер `Co-Authored-By` называет модель, **реально** делавшую коммит. Старшая сверяет `git log -1`, `git status`.
- `--dry-run` боевого запуска любого скрипта — только после успешного dry-run и «да»; подагенту не поручать.
- Подагент не правит файлы, которые в это время правит основной агент.
- В отчёте: что и на какой модели сделано, что проверено сразу после.
