# Best practices

Практика применяется, только если решает реальную проблему здесь и сейчас. Простейшее рабочее решение
важнее «правильной» архитектуры. Правила проекта (`AI.md`, `AGENTS.md`, `CLAUDE.md`) и пользователя важнее
навыка; ослабление защиты — только с явного согласия пользователя.

## Перед правкой
- Прочитать код, места вызова, конфиг, логи; не править по догадке. Искать первопричину, не заплатку на симптом.
- Бритва Оккама: если поведение уже есть (событие в логе, проверка, настройка) — использовать его, второй
  механизм не добавлять. Дифф минимально достаточный; чужой код не «улучшать» заодно.
- Перед удалением или переименованием — все ссылки (`grep -r`, граф проекта).
- Правка скрипта: проверить связанные установочные, стартовые и миграционные скрипты и обновить синхронно.

## Код
- Ошибки явные: bash — `set -euo pipefail`, проверка кодов выхода; Python — конкретные исключения, без голого
  `except: pass` и без `|| true` ради подавления. Сбой одной единицы работы (файла, письма, записи) не роняет запуск.
- Ресурсы освобождаются гарантированно: `with`/`try…finally`, `trap` в bash.
- Идемпотентность: `mkdir -p`, `IF NOT EXISTS`, проверка перед действием. Скрипт, меняющий данные, имеет `--dry-run`.
- Без хардкода путей, секретов, доменов и адресов: из env/конфига; корень проекта — по расположению файла.
- Типы: аннотации в Python, `dataclass`/типизированные объекты вместо словарей-«мешков».
- Валидация входа (аргументы CLI, конфиг) с понятными сообщениями; взаимоисключающие режимы CLI — взаимоисключающая группа.
- Таймаут на каждый сетевой вызов (`curl --max-time`, `timeout=`).
- Атомарная запись файлов: временный файл (`tempfile`/`mktemp`) в том же каталоге и `rename`; без предсказуемых имён в общих каталогах.
- Одна ответственность у функции, говорящие имена; комментарий — «почему», не «что».
- Мёртвый код, неиспользуемые опции и ветки совместимости удалять, не оставлять «на всякий случай».
- Shell: кавычки и `${VAR}`, `[[ ]]`, в каждом `case` ветка `*)`; ввод не подставлять в команды без экранирования.
  Проходит `shellcheck -o all` и `-S style` без отключений; исправлять реструктуризацией (SC2312: подстановка — в отдельную переменную).
- Тестируемость: сеть, процессы и время подменяемы; на новое поведение — тест.

## Конфигурация и инфраструктура
- Версии зафиксированы: образ по digest или точному тегу, зависимости по версии.
- Декларативно: состояние в файле, не набрано руками на сервере.
- У сервиса — healthcheck, лимиты памяти/CPU, ротация логов.
- Периодика — таймеры systemd (`.service` + `.timer`), не cron.
- Изменение применимо повторно и откатываемо; перезапуск не ломает состояние.
- Модели, библиотеки, параметры — под фактическое железо и версии машины, подтверждённые замером.

## Данные
- Перед необратимым (миграция, удаление, перезапись) — бэкап или снимок.
- Схема БД — версионной миграцией; применённые миграции не править.
- Бэкап рабочий, только если восстановление проверено.
- Боевой запуск — после успешного `--dry-run` с теми же аргументами и конфигом и подтверждения пользователя.

## Проверка
- Проверки кода (тесты, линтеры, `bash -n`, `shellcheck`, `py_compile`, `ruff`) выполняет CI репозитория;
  локально не запускать. Нужной проверки в CI нет — добавить её в workflow. «Проверено» = зелёный CI.
- Поведение на реальной системе проверять: `--dry-run`, запрос к сервису, статус контейнера, строка лога, код выхода.
- Отчёт честный: что запущено, результат (с выводом), что не проверено и почему. Упало — не «починено», пока не понятна причина.

## Изменения
- Коммит атомарный, одна тема; в сообщении — «почему».
- Документация (README, `.env.example`/шаблон конфига, `scripts/`) — в том же изменении; рабочий конфиг — без потери значений и секретов.
- Не коммитить секреты, `.env`, дампы, артефакты сборки, кэши, `graphify-out/`.

## Эксплуатация
- Наблюдаемость: метрики, логи, алерты на то, что реально ломается.
- Близость к лимиту (память, диск, PID, квота, таймаут) — сообщать сразу: лимит, значение, что теряется, варианты.
- Предупреждения не маскировать и не называть «штатными» без доказательства; чинить в корне.
- Длительные операции — с видимым прогрессом (этап, процент, скорость, остаток).

## Анти-паттерны
- Абстракция «на вырост», слой без второго потребителя, конфиг-опция без пользователя.
- Код «на всякий случай» и ветки совместимости без живого потребителя.
- Копипаста конфигов вместо общего блока (`x-` якорь в compose, include).
- Отключение проверки (`# shellcheck disable`, `--no-verify`, `|| true`) вместо исправления причины.
- Ретраи и `sleep` вместо ожидания условия (healthcheck, `until`).
- Новая зависимость ради десяти строк стандартной библиотеки; второй механизм для уже существующего.
