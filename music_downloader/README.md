# Music Downloader

Скачивание музыки с разных сайтов через мосты (драйверы) из `drivers/`. HTTP-запросы выполняются через `cloudscraper`; запуск отдельного браузера не требуется. Все мосты сохраняют треки в единый набор папок, заданный глобально.

## Структура проекта

```
music_downloader/
├── music_downloader.py          # Основной скрипт
├── music_downloader.json        # Рабочая конфигурация: общие папки и сайты
├── music_downloader.json.example # Шаблон конфигурации
├── drivers/                     # Драйверы для каждого сайта
│   ├── music_downloader_sefon_pro.py
│   ├── music_downloader_lmusic_kz.py
│   ├── music_downloader_agugai_kz.py
│   ├── music_downloader_lmu_kz.py
│   ├── music_downloader_tunes_kz.py
│   ├── music_downloader_jamendo_com.py
│   └── music_downloader_shazam.py
├── music_downloader.db          # SQLite: история загруженных треков
├── requirements.txt             # Зависимости Python
├── setup_venv.sh                # Подготовка виртуального окружения
├── tests/                       # Локальные smoke-тесты
└── venv/                        # Виртуальное окружение
```

Логи сохраняются на уровень выше, в `../logs/`. Обёртка [music_downloader.sh](../music_downloader.sh) и сортировщик [split_by_dash.sh](../split_by_dash.sh) находятся в корне проекта [mytasks](../README.md).

`music_downloader/` входит в Git-репозиторий `mytasks` как обычная папка, без отдельного `.git` и без submodule. Исходники, драйверы, тесты, этот README и `music_downloader.json.example` коммитятся вместе с основным проектом. Рабочий `music_downloader.json`, БД и её резервные копии, логи и виртуальное окружение остаются локальными согласно `.gitignore`.

## Установка и запуск

Команды ниже выполняются из каталога `music_downloader/`. Нужны Python 3 и доступ к интернету для установки зависимостей и обращения к музыкальным сайтам; в CI используется Python 3.12.

### 1. Создание виртуального окружения

```bash
python3 -m venv venv
source venv/bin/activate
```

### 2. Установка зависимостей

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

Вместо шагов 1–2 можно выполнить `bash setup_venv.sh`.

### 3. Подготовка конфигурации

Если рабочего файла ещё нет, создайте его из шаблона, не перезаписывая существующие настройки:

```bash
if [[ ! -e music_downloader.json ]]; then
    cp music_downloader.json.example music_downloader.json
fi
```

Отредактируйте глобальный `download_paths` и список `sites`. Целевые папки должны уже существовать и быть доступны пользователю для записи. Для путей на внешних дисках сначала проверьте, что диски смонтированы.

### 4. Запуск

Только скачивание, без последующей сортировки:

```bash
venv/bin/python music_downloader.py
```

Запуск через обёртку, которая активирует окружение и при коде выхода загрузчика `0` вызывает `split_by_dash.sh`:

```bash
bash ../music_downloader.sh
```

Пути сортировщика настраиваются отдельно; `download_paths` управляет только сохранением файлов загрузчиком.

## Конфигурация

Редактируйте `music_downloader.json` для добавления/изменения сайтов и папок для загрузки.

### Глобальные настройки

`download_paths` находится в корне JSON, рядом с `sites`, а не внутри каждого сайта. Каждый трек скачивается одним потоком и сохраняется **во все** перечисленные папки — это не выбор первой свободной папки.

Пример полной конфигурации с одним мостом:

```json
{
    "log_cleanup_days": 10,
    "log_max_files": 10,
    "file_permissions": {
        "enabled": true,
        "mode": "0666"
    },
    "download_paths": [
        {
            "path": "/mnt/copy/Music/_cloud/",
            "max_size_mb": 1024
        },
        {
            "path": "/var/downloads/clouddata/nextcloud/mobile-music/_cloud/",
            "max_size_mb": 1024
        }
    ],
    "sites": [
        {
            "site_name": "sefon.pro",
            "site_script": "drivers/music_downloader_sefon_pro.py",
            "base_url": "https://sefon.pro",
            "categories": ["/news/", "/news/2"]
        }
    ]
}
```

- `download_paths` — обязательный непустой список общих папок. У каждого элемента нужен `path`; рекомендуется абсолютный путь.
- `max_size_mb` — лимит общего размера папки с подкаталогами, а не квота отдельного сайта. По умолчанию 1024 МБ. Размер считается в единицах 1024 × 1024 байт.
- `file_permissions.enabled` — применять ли `chmod` после сохранения. `mode` задаётся строкой в восьмеричной записи. Значение `"0666"` разрешает чтение и запись всем пользователям; при необходимости ограничьте права. Владельцы и группы не меняются.
- `log_cleanup_days` — удалять логи движка старше указанного числа дней; по умолчанию 10.
- `log_max_files` — максимальное число оставляемых логов движка после очистки; по умолчанию 10.

**Лимиты проверяются один раз перед обращением к сайтам.** Если размер любой папки уже достиг лимита, весь запуск останавливается с кодом `2`. Во время скачивания размер повторно не проверяется: это стартовая проверка, а не жёсткая квота, и за запуск лимит может быть превышен.

В `music_downloader.json.example` приведены демонстрационные пути и лимиты 3072 МБ; замените их своими перед первым запуском.

### Настройки мостов

В элементах `sites` остаются настройки источников:

- `site_name` — название сайта
- `site_script` — путь к драйверу в папке `drivers/`
- `base_url` — базовый URL сайта
- `categories` — категории для скачивания

В шаблоне подключены шесть мостов: `sefon.pro`, `lmusic_kz`, `agugai_kz`, `lmu_kz`, `tunes_kz` и `jamendo_com`. Файл драйвера Shazam также есть в `drivers/`, но в шаблонный список `sites` он не включён. Для запуска нового моста добавьте его в `sites`; копировать настройки папок не нужно.

### Переход со старого формата

1. Выберите общий список папок и лимитов, если раньше у сайтов они различались.
2. Перенесите `download_paths` в корень JSON, на один уровень с `sites`.
3. Удалите копии `download_paths` из элементов `sites`.

Настройки папок внутри сайтов больше не используются и не переопределяют глобальные. Если глобальный список отсутствует, пуст или имеет неверный тип, загрузчик завершится с кодом `2` до обращения к сайтам.

## Порядок работы и обработка ошибок

- Категории обходятся по кругу: сначала первая категория каждого сайта, затем вторая и т. д. Из очередей скачивается по одному треку от каждого сайта.
- Отсутствующая папка или достигнутый лимит завершают запуск с кодом `2`, поэтому обёртка не запускает сортировщик. Проверка существования пути не гарантирует права записи: ошибки записи обрабатываются при сохранении трека.
- Ошибка загрузки драйвера, получения списка треков или скачивания отдельного трека логируется и не останавливает остальные источники. Поэтому код `0` не гарантирует, что каждый сайт и трек обработан успешно — проверяйте логи.
- Одинаковые `artist/title` сравниваются без различий в регистре (`casefold`), с удалением кавычек и схлопыванием пробелов. Общая очередь и SQLite предотвращают повторную загрузку одного трека с разных сайтов. При очистке старых дублей в БД сохраняется самая свежая запись.
- Файлы записываются как `.part`, проверяются по ненулевому `Content-Length`, если он есть, и затем переименовываются в `.mp3`. Переименование атомарно для каждого файла, но не для набора папок целиком. При ошибке оставшиеся `.part` удаляются.
- В `downloads` сохраняется фактически полученный размер после успешного сохранения во все папки. Удаление MP3 из папки не удаляет историю из БД и не приводит к повторному скачиванию.
- Устаревшая таблица `allsongs` удаляется при инициализации БД; используется `downloads`.
- Если `music_downloader.json` отсутствует, текущий скрипт завершается без скачивания с кодом `0`. Создайте конфигурацию до запуска обёртки.

## Логирование

Логи находятся в общей папке `../logs/`:

- `music_downloader_engine-<timestamp>.jsonl` — события Python-движка и мостов; очистка управляется `log_cleanup_days` и `log_max_files`.
- `music_downloader-<timestamp>.jsonl` — события shell-обёртки; она сохраняет последние 10 своих логов независимо от настроек движка.
- `cron_execution.log` — стандартный вывод и ошибки загрузчика и сортировщика при запуске через обёртку.

В конце работы движок записывает строку `bari: ...` с числом скачанных треков по сайтам и общим `total`.

## Проверки

Из каталога `music_downloader/`:

```bash
venv/bin/python -m pytest tests ../tests/test_music_downloader.py -q
venv/bin/ruff check .
venv/bin/python -m py_compile music_downloader.py
venv/bin/python -m json.tool music_downloader.json > /dev/null
```

`../tests/test_music_downloader.py` входит в тот же репозиторий и проверяет в том числе общие папки для нескольких мостов, остановку при неверной конфигурации, сохранение файлов и дедупликацию. Эти тесты используют временные папки и подменённые HTTP-ответы, не скачивая музыку из сети.
