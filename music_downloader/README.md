# Music Downloader

Загрузчик MP3 с подключаемыми мостами из `drivers/`. Движок использует `cloudscraper` и `mutagen` (очистка тегов ID3), ведёт историю в SQLite и сохраняет каждый новый трек во все глобально заданные каталоги. Браузер не требуется.

## Установка и запуск

Нужны Python 3 и сетевой доступ к источникам. Команды установки выполняются из `music_downloader/`:

```bash
bash setup_venv.sh
test -e music_downloader.json || cp music_downloader.json.example music_downloader.json
```

Перед первым запуском отредактируйте `music_downloader.json`: каталоги должны уже существовать, быть смонтированы и доступны на запись.

```bash
# Только загрузка
venv/bin/python music_downloader.py

# Загрузка из корня mytasks; при коде 0 затем запускается split_by_dash.sh
bash ../music_downloader.sh
```

Пути сортировщика задаются отдельно: `download_paths` относится только к загрузчику. Рабочие `music_downloader.json`, `music_downloader.db`, резервные копии БД, `venv/` и логи не входят в Git.

## Конфигурация, каталоги и лимиты

`download_paths` — обязательный непустой список в корне JSON, рядом с `sites`. Настройки каталогов внутри сайтов игнорируются. Каждый трек одним потоком копируется **во все** назначения, а не в первую свободную папку.

```json
{
  "download_paths": [
    {"path": "/mnt/copy/Music/_cloud/", "max_size_mb": 3072},
    {"path": "/var/downloads/clouddata/syncthing/Music/_cloud/", "max_size_mb": 3072}
  ],
  "sites": [
    {
      "site_name": "sefon.pro",
      "site_script": "drivers/music_downloader_sefon_pro.py",
      "base_url": "https://sefon.pro",
      "categories": ["/news/", "/news/2"]
    }
  ]
}
```

- `max_size_mb` ограничивает размер всего дерева каталога в МиБ (`1024 × 1024` байт); значение по умолчанию — `1024`.
- Размер каждого назначения проверяется при старте и заново перед каждым треком. Ограничивает загрузку папка с наименьшим доступным объёмом.
- Для вложенных назначений учитываются обе создаваемые копии. Повторяющиеся реальные пути, включая ссылки на один каталог, запрещены.
- Контроль рассчитан на один процесс. Параллельные записи других программ не блокируются; для общей строгой квоты используйте квоты файловой системы.
- `file_permissions.enabled` и восьмеричная строка `file_permissions.mode` включают `chmod` после сохранения. Владелец и группа не меняются; ошибка `chmod` только логируется.
- `log_cleanup_days` и `log_max_files` задают очистку логов движка; оба значения по умолчанию равны `10`.

## Очистка тегов ID3

Перед тем как `.part` станет готовым MP3, движок (`clean_mp3_tags` в `save_response`) оставляет в тегах только данные о песне; всё лишнее попадает в один общий комментарий (`COMM` без описания). Правила основаны на фактическом составе тегов библиотеки `/mnt/copy/Music`:

- **Поля песни** (название, исполнитель, исполнитель альбома, альбом, композитор, жанр и прочие текстовые `T***`): ссылки на сайты вырезаются вместе со скобками («Song (Sefon.Pro)» → «Song») или рекламной подводкой, начинающейся с глагола («скачано с sefon.pro», «download from x.com»; одиночные «by», «on», «с» перед ссылкой остаются: «Stand By www.site.kz» → «Stand By»), оставшиеся по краям разделители срезаются; поле, состоявшее только из ссылки, удаляется. Если после выреза ссылки осталась реклама («Musiclife.kz - Скачать музыку, mp3, песни бесплатно!»), значение целиком уходит в комментарий. Название и исполнитель (`TIT2`, `TPE1`) целиком не удаляются: снимаются только скобки со ссылкой («Евродэнс.ru (lmusic.kz)» → «Евродэнс.ru»), а значение, целиком похожее на сайт, остаётся. Ссылкой считается `http(s)://…` (в том числе испорченное `http:/…`), `ftp://…`, `www.…` и «голый» домен с известной доменной зоной (`sefon.pro`, `lmusic.kz`, `музыка.рф`); адрес почты ссылкой не считается; короткие зоны, похожие на слова (`in`, `to`, `am`, `us`, `co`, `de`, `by` — «Prod.by»), не распознаются, чтобы не резать названия.
- **Текст песни** (`USLT`): строка со ссылкой («Тексты на lyrics.ru») удаляется целиком, переводы строк остальных строк сохраняются как были. **Подпись обложки** (`APIC`) очищается от ссылки, сама обложка остаётся.
- **Copyright, издатель и пользовательские поля** (`TCOP`, `TPUB`, `TXXX`): значение без ссылки остаётся (MusicBrainz, ReplayGain, ISRC, LABEL, CATALOGNUMBER и т. п. не трогаются), значение со ссылкой — обычно реклама целиком («Данная аудиозапись скачана с сайта http://…») — уходит в комментарий.
- **URL-кадры** (`WOAF`, `WOAR`, `WPUB`, `WCOP`, `WXXX` и др.), владелец файла и радиостанция (`TOWN`, `TRSN`, `TRSO`), TXXX-комментарии (`comment`, `description`, `notes`) — в комментарий.
- **Технические кадры** удаляются, ссылки из них переносятся в комментарий: `TENC`, `TSSE`, `TLEN`, `TSIZ`, `TFLT`, `TMED`, `TDLY`, `TDTG`, `TDEN`, `TOFN`, `PRIV` (Windows Media), `GEOB` (Sound Forge), служебные `COMM` iTunes (`iTunNORM`, `iTunSMPB`…) и технические `TXXX` (`major_brand`, `minor_version`, `compatible_brands`, `LAVF…`, `ITUNNORM`, `encoder`, `encoded by`, `tagging time`, `coverart` и др. — списки `TECHNICAL_TXXX`, `TECHNICAL_TXXX_PREFIXES`).
- **Прочие кадры** (`UFID`, `MCDI`, `POPM`, `PCNT`, `RVA2`, `SYLT`, `TIPL`/`TMCL` и т. п.) не меняются.

Комментарий оптимизируется (`optimize_comment`): все прежние `COMM` и перенесённые фрагменты сливаются в одну строку через ` | `; часть со ссылкой сводится к самой ссылке в короткой форме — без схемы и `www`, хост в нижнем регистре (`https://www.Sefon.Pro/` → `sefon.pro`); одна ссылка в разных написаниях остаётся одна, голый домен не дублирует ссылку на страницу того же сайта (`sefon.pro` при `sefon.pro/mp3/1`); пустые части, hex-ряды iTunes, обрезки ссылок без точки в хосте (ID3v1 хранит 30 символов: «www.RnBXc») и повторы названия, исполнителя или альбома отбрасываются. Порядок — прежний комментарий, затем перенесённое.

Версия ID3v2 сохраняется (2.3 остаётся 2.3, остальные пишутся как 2.4), существующий ID3v1 обновляется из очищенного ID3v2. Файл без ID3 и файл, где чистить нечего, не перезаписываются; повторная очистка ничего не меняет. Очистка идёт на отдельной копии `.part.tags`: если mutagen не смог разобрать теги, в журнал пишется предупреждение и файл сохраняется как есть. Очищенный вариант раскладывается во все назначения; размер и SHA-256 в БД относятся к итоговому файлу на диске. Если после очистки файл не помещается в лимит (на практике файл только уменьшается), срабатывает обычный `DownloadLimitExceeded`. Уже лежащие в библиотеке файлы движок не трогает. Проверено 2026-10-21 на копиях 2000 случайных файлов `/mnt/copy/Music`: аудиоданные не меняются, повторная очистка ничего не меняет, ошибок разбора нет.

## Запись файлов и коды завершения

Поток пишется в `<имя>.mp3.part` одновременно во всех назначениях. Известный корректный `Content-Length` проверяется до записи и после неё; без него или при неверном заголовке лимит проверяется на каждом блоке. При ошибке оставшиеся `.part` удаляются, а строка БД не создаётся.

После полной записи каждый `.part` заменяется через `os.replace`. Замена атомарна для отдельного файла, но не является транзакцией для всего набора папок: если поздняя замена завершится ошибкой, уже переименованная копия может остаться без записи в БД. Существующие готовые MP3 и успешно загруженные ранее треки при превышении лимита не удаляются.

| Код | Значение |
|---:|---|
| `0` | Движок завершил обход. Это возможно при ошибках отдельных драйверов/треков и даже при отсутствующем `music_downloader.json`; проверяйте логи. Обёртка при `0` запускает сортировщик. |
| `2` | Нет непустого глобального списка `download_paths`, каталог отсутствует/уже заполнен либо очередной трек превысил доступный объём. Загрузка останавливается, сортировщик не запускается. |
| `1` или другой ненулевой | Необработанная ошибка конфигурации/программы либо код дочернего Python-процесса. Обёртка возвращает его без запуска сортировщика. |

Отсутствие права записи и повтор назначения обычно обнаруживаются при сохранении конкретного трека: ошибка логируется, обработка продолжается и итоговый код может быть `0`.

## Общие источники MP3 (`search_sources`)

Мосты без собственного аудио (`shazam_com`, `beufm_kz`) и `mychords_net` при отсутствии плеера ищут MP3 по паре «исполнитель — название» в **одном общем** списке `search_sources` в корне JSON. Источники опрашиваются по порядку, `"enabled": false` выключает источник без удаления записи; без ключа `search_sources` используется встроенный список Sefon → LMusic.

```json
  "search_sources": [
    {"name": "sefon.pro", "enabled": true, "driver": "drivers/music_downloader_sefon_pro.py",
     "base_url": "https://sefon.pro", "search_path": "/search/?q={query}"},
    {"name": "lmusic_kz", "enabled": true, "driver": "drivers/music_downloader_lmusic_kz.py",
     "base_url": "https://lmusic.kz", "search_path": "/search?q={query}"},
    {"name": "muzofond", "enabled": true, "driver": "drivers/music_downloader_muzofond.py",
     "base_url": "https://muzofond.fm", "search_path": "/search/{query_path}"},
    {"name": "drivemusic", "enabled": true, "driver": "drivers/music_downloader_drivemusic.py",
     "base_url": "https://drivemusic.me", "search_path": "/?do=search&subaction=search&story={query}"},
    {"name": "hitmotop", "enabled": true, "driver": "drivers/music_downloader_hitmotop.py",
     "base_url": "https://rus.hitmotop.com", "search_path": "/search?q={query}"},
    {"name": "youtube_music", "enabled": true, "driver": "drivers/music_downloader_youtube_music.py",
     "base_url": "https://music.youtube.com", "search_path": "/search?q={query}#songs"}
  ]
```

| Источник | Разбор выдачи | Замечания |
|---|---|---|
| `sefon.pro` | карточки `div.mp3`, расшифровка ссылки | обычно 320 кбит/с |
| `lmusic_kz` | `div.c-card-mp3[data-download_url]` | обычно 320 кбит/с |
| `muzofond` | `li.item` → `li.play[data-url]`, `span.artist`, `span.track` | ≈320 кбит/с; пустую выдачу отдаёт как HTTP 404 (= «не найдено») |
| `drivemusic` | `.music-popular__item` → `[data-url]`, `a.popular-play-author`, `.popular-play-composition a` | ссылка с меткой времени, берётся прямо перед скачиванием |
| `hitmotop` | `li[data-musmeta]` (JSON: artist, title, url), переадресация на зеркало `hitmoz` | лучший охват среди MP3-сайтов, но 128 кбит/с |
| `youtube_music` | системный `yt-dlp`: поиск песен `#songs`, у первых 3 результатов полные метаданные `artists`/`track` | последняя страховка для нишевых релизов; opus перекодируется `ffmpeg` в MP3 VBR ~190 кбит/с; медленно (несколько вызовов `yt-dlp` на запрос); нет `yt-dlp`/`ffmpeg` — источник пуст |

Кандидат источника может вместо прямой ссылки нести `fetch` — функцию без аргументов, возвращающую потоковый ответ (`status_code`, `headers`, `iter_content`, контекстный менеджер). Тогда `find_audio` не проверяет ссылку HTTP-запросом, а движок вызывает `fetch()` вместо `scraper.get`; лимиты каталогов, очистка тегов и `filehash` работают как обычно. Так устроен `youtube_music`: файл скачивается и перекодируется во временный каталог только для выбранного трека, каталог удаляется после сохранения.

Порядок — по качеству файла, а не по охвату. Проверено 2026-10-24 на 132 треках, не найденных прежней схемой (Shazam, Beu FM, MyChords); mp3party.net отклонён — его CDN отдаёт вместо файла текст `failed`.

`{query}` заменяется на URL-кодированную для параметра строку «Исполнитель Название» (`Кино+Цой`), `{query_path}` — на закодированный сегмент пути (`Кино%20Цой`). Драйвер источника обязан предоставить `search_tracks(session, base_url, search_path)` и вернуть кандидатов с `artist`, `title`, `download_url` (и при необходимости `referer`, `src`). Общий код — `drivers/music_downloader_audio_search.py` (`find_audio`). Каждый источник получает полный запрос и, если он отличается, запасной «первый исполнитель + название без feat». Сначала во **всех** источниках ищется точное совпадение нормализованных исполнителя и названия (регистр и пунктуация игнорируются). Только если его нет нигде, берётся мягкое совпадение `relaxed_match`: название без `(feat. …)`/`[ft. …]` и пометок ремастеринга (`(Remastered 2024)`, `- 2015 Remaster`) плюс хотя бы один общий исполнитель («JAMALA, ONUKA» ↔ «Jamala»), диакритика и письменность не учитываются (`fold_key`: «JAŸ-Z» ↔ «JAY-Z», «Мәди Сыздықов» ↔ «Madi Syzdykov», «аi ómir-ai» с кириллической «а» ↔ «Ai Omir ai»; в поиск добавляется запрос без диакритики). Строгий проход по-прежнему сравнивает `match_key` без этих поблажек.

**Казахские песни и синонимы исполнителей.** Beu FM — казахское радио: часть песен в эфире подписана латиницей («Madi Syzdykov — Ai Omir ai»), часть кириллицей («Сара Амангелді — Көздерің сенің сондай әп-әдемі»), а сайты и YouTube Music хранят их в другой письменности или под другим именем. Поэтому драйвер Beu FM ставит треку `search_translit`, и в поиск добавляется запрос в другой письменности (`to_cyrillic` «по-русски»: «Мади Сыздыков Ай Омир ай»; `to_latin`: «Sara Amangeldi Kozderin…»). Если исполнитель публикуется под другим именем или лейблом, его синонимы задаются в корне JSON списком групп `artist_aliases`:

```json
  "artist_aliases": [
    ["Madi Syzdykov", "Мәди Сыздықов", "Мади Сыздыков", "Madi Syzdyq", "Madistation"]
  ]
```

Синонимы участвуют только в мягком проходе (совпадение исполнителя) и дают по дополнительному запросу «синоним + название». Группа указывается вручную после проверки, что это один исполнитель: без неё «Madistation — аi ómir-ai» не будет принят за песню Мәди Сыздықова. Не-список или группа не из строк дают код `2`. `(with X)`, `remix`, `live`, версии и миксы по-прежнему различаются. Ссылка проверяется запросом без чтения тела, после каждого запроса пауза 1 с. Чтобы добавить сайт, напишите для него `search_tracks` в драйвере и добавьте запись в `search_sources` — код мостов менять не нужно. Не-список в `search_sources` даёт код `2`.

## Контракт мостов

Каждый элемент `sites` задаёт `site_name`, `site_script`, `base_url` и непустой `categories`. Драйвер загружается напрямую по пути через `spec_from_file_location` и обязан предоставить:

```python
def get_tracks(session, base_url, category):
    return [{"id": "...", "artist": "...", "title": "...", "download_url": "..."}]
```

`id`, `artist` и `title` нужны движку; прямой мост также возвращает `download_url`, при необходимости `referer` и `src`. Необязательный `resolve_track(session, track)` вызывается только для нового трека после проверки БД и общей очереди и возвращает `{"download_url", "referer", "src"}` либо `None`. `None` или исключение пропускает трек без записи в БД и освобождает его пару `artist/title` для последующих категорий. Соседние драйверы следует импортировать по файловому пути, как `_load_driver` в Shazam: каталог `drivers/` не добавляется в `sys.path`.

Категории обходятся уровнями: сначала первая у каждого сайта, затем вторая; внутри уровня скачивается по одному треку от каждого моста.

| Мост | Категории из `music_downloader.json.example` | Источник аудио |
|---|---|---|
| `sefon.pro` | `/news/`, `/news/2` | Расшифрованные MP3-ссылки карточек Sefon |
| `lmusic_kz` | `/top_kz/monthly`, `/sections/kazakhstan`, `/sections/foreign-music`, `/sections/rusian` | `data-download_url` карточек LMusic; `rusian` — точное написание URL сайта |
| `agugai_kz` | `/catalog/music` | Страницы `/music/...`, затем прямая MP3-ссылка |
| `lmu_kz` | `/sections/kazakhstan` | Карточки `/song/.../<id>`, загрузка `/download/<id>` |
| `tunes_kz` | `/` | Страницы `/<id>-slug.html`, кнопка загрузки или MP3-ссылка |
| `jamendo_com` | `/` | Официальный Jamendo API |
| `shazam_com` | `/ru-ru/charts/top-200/world` | Метаданные Shazam, MP3 ищется в `search_sources` |
| `mychords_net` | `/ru/novinki` | Плеер Xpleer со страницы MyChords, без плеера — `search_sources` |
| `beufm_kz` | `/` | Название эфирного трека Beu FM; MP3 ищется в `search_sources` |

### Jamendo, Shazam, MyChords и Beu FM

- **Jamendo:** `/` запрашивает одну страницу до 200 последних треков из `tracks` API с `order=releasedate_desc`. Периодические пустые ответы CDN и сетевые сбои API обрабатываются повторными попытками по `_API_RETRY_DELAYS` (`1, 3, 5` с). Принимаются только записи с `audiodownload_allowed: true` и непустым `audiodownload`; потоковое поле `audio` не используется. Нужен `client_id` сайта или `JAMENDO_CLIENT_ID` (переменная окружения имеет приоритет). `/playlist/<ID>` обрабатывается через API плейлистов с пагинацией. Ошибки API и пустые результаты явно логируются с `site=jamendo_com`.
- **Shazam:** мост принимает только мировой Top 200 и требует ровно 200 уникальных `adam_<id>`. Для запроса обязательны проверенные `CHART_HEADERS`; браузер и превью Shazam/Apple не используются. Shazam (Next.js за Fastly) периодически отдаёт по адресу чарта HTTP 200 с чужой страницей (иной canonical, ~1.8 МБ вместо ~3.7 МБ) — дефект держится на пограничном узле до истечения TTL, и HTML-страница и RSC-поток того же адреса ломаются независимо. Поэтому каждая попытка `get_tracks` сначала читает обычную страницу (`parse_chart`: canonical + карточки `data-test-id="songItem"` с восстановлением SSR-вставок `$RS(...)`, ранги `1…200`), а при неудаче — RSC-поток (`parse_flight_chart`: заголовок `RSC: 1`, ответ `text/x-component`, те же данные в `self.__next_f`; ранг = порядок карточек, совпадает с DOM). Попытки повторяются по `CHART_RETRY_DELAYS` (`15, 45, 90` с) с `Connection: close`. Query-параметр-«антикэш» не добавляется — у Fastly он чаще ведёт на битую копию. `ERROR` пишется только после того, как оба источника промолчали на всех попытках, и означает временный сбой Shazam/CDN, а не поломку разбора (на неё указывают `В карточке чарта…` / `Ожидался полный Top 200…` / `RSC-поток Shazam…` при живом чарте). RSC-поток приходит как `text/x-component` без charset, и `requests` по умолчанию декодирует его как ISO-8859-1 («NatÃ©», «Ð¢Ð°Ñ…» вместо «Naté», «Тат…»): искажённые имена не находились в источниках MP3 и попадали бы в БД, поэтому ответ Shazam всегда читается как UTF-8. Для нового трека MP3 ищется в общих `search_sources` (см. выше).
- **MyChords:** `/ru/novinki` разбирается по `li.b-listing__full__item a.b-listing__full__item__name`, ID — из `/<id>-slug.html`. Для нового трека мост проходит цепочку `div.b-words__player[data-src]` → iframe `audio.xpleer.com/embed/` → `#file[data-mp3]` на `storage.xpleer.com`. Если плеера или ссылки нет либо запрос не удался, пишется предупреждение и трек ищется в общих `search_sources` по исполнителю и названию из списка; не найден и там — `None`.

- **Beu FM:** мост берёт не каталог, а то, что играет в эфире радио сейчас (0 или 1 трек за обход). Название на странице лежит в `<span id="track_org">`, но в исходном HTML спан пуст: его раз в 10 с заполняет `template/Player.js` из файла `1.txt` (строка «Исполнитель - Название», кириллица числовыми HTML-сущностями). Поэтому `get_tracks` читает спан, а при пустом значении — тот же `1.txt`; строка без разделителя « - » (джингл, реклама, название станции) трека не даёт. Разделитель — первый « - ». ID радио нет, поэтому ключ `fm_<16 hex>` — SHA-256 нормализованной пары (регистр и пунктуация игнорируются). `resolve_track` ищет MP3 в общих `search_sources` (см. выше); нет совпадения — трек пропускается без записи в БД. Уже скачанный трек (по ID или паре `artist/title`) пропускается до поиска. `base_url` — `https://beufm.kz`: сертификат выдан только на этот хост, `https://www.beufm.kz` не проходит проверку TLS (мост сам подменяет `www`). Один обход фиксирует лишь песню, звучащую в момент запуска, поэтому для охвата эфира нужен частый запуск по расписанию.

## База данных и дедупликация

SQLite-файл `music_downloader.db` содержит таблицу `downloads`: ID вида `<site_name>_<track-id>`, нормализованные `artist/title` для дедупликации, исходные `original_artist/original_title` для отчётов, источник, имя, фактический размер, `filehash` (SHA-256 содержимого) и время. Перед постановкой в очередь проверяются и ID, и общая пара `artist/title`. В отчётах следует выводить `original_artist/original_title`, а не служебные нормализованные ключи.

Нормализация приводит строку к NFKC, применяет `casefold` и оставляет только буквы и цифры — все разделители, пробелы и пунктуация отбрасываются, поэтому «Вася & Петя», «Вася +Петя» и «ВасяПетя» дают один ключ; слова при этом не удаляются, так что «Song (Remix)» и «Song» остаются разными. При каждом открытии БД старые строки перенормализуются, дубликаты `artist/title` удаляются с сохранением самой свежей записи, дубликаты `filehash` (не NULL) — тоже, и поддерживаются уникальный индекс по `artist/title` и **частичный** уникальный индекс по `filehash` (`WHERE filehash IS NOT NULL`). Порядок в `_create_table` важен: индексы снимаются до перенормализации и дедупа и создаются заново после. Недостающие `original_artist`, `original_title` и `filehash` добавляются на месте (`ALTER TABLE`). Для старых строк исходные поля заполняются прежними значениями `artist/title`; если БД уже нормализовалась старой версией, потерянные регистр и пунктуацию автоматически восстановить нельзя. Устаревшая таблица `allsongs` удаляется. Удаление MP3 вручную не удаляет историю и не вызывает повторную загрузку.

Дедупликация по содержимому: `save_response` считает SHA-256 итогового файла (после очистки тегов, а если чистить было нечего — записанного потока). Если такой хеш уже есть в БД (тот же файл под другим именем или из другого источника), только что сохранённые копии удаляются с диска, а строка всё равно добавляется — но с `filehash = NULL`, чтобы ID больше не качался и при этом не нарушался частичный уникальный индекс. Хеш проверяется уже после загрузки, поэтому экономит место, а не трафик. Исторические строки с `filehash = NULL` (файл не найден на диске) при штатной работе не backfill-ятся; разовый backfill по существующим файлам делает `state/music_downloader_hash_cleanup.py` (`--apply`, с резервной копией БД и JSON-отчётом).

## Логи

- `../logs/music_downloader_engine-<timestamp>.jsonl` — движок и мосты; поля и имена полей берутся из `../conf/log_template.conf` либо шаблона/встроенных значений.
- `../logs/music_downloader-<timestamp>.jsonl` — shell-обёртка; она независимо оставляет 10 последних файлов.
- `../logs/cron_execution.log` — stdout/stderr движка и сортировщика при запуске обёрткой.

JSONL движка содержит время, уровень, сообщение, `service.name` и версию схемы. Итоговая запись `bari: ... total=N` показывает число успешных загрузок по мостам; отсутствие ошибок в коде завершения не заменяет проверку логов.

```bash
music_downloader/venv/bin/python -m pytest tests/test_music_downloader.py music_downloader/tests -q

music_downloader/venv/bin/ruff check music_downloader/
music_downloader/venv/bin/python -m py_compile music_downloader/music_downloader.py
music_downloader/venv/bin/python -m json.tool music_downloader/music_downloader.json.example >/dev/null
```

CI выполняет Ruff и оба набора Python-тестов на Python 3.14 при изменениях загрузчика, общих тестов или workflow.
